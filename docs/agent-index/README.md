# Agent Index — read this before you start

> Three generated indexes plus a manifest. If you are a cloud coding agent
> picking up GSE work, this directory is the map. Everything it points at is
> already in the repository.

## The one thing to know

**The research corpus is already in `main`.** 1,511 paper extractions in
`docs/research/2026-09-21/arxiv-deep/`, 147 program files in
`docs/research/2026-09-21/arxiv-program/`. They were not lost and did not need
recovering — they were unfindable, because there was no index.

If you were told the papers are missing, they are not. If you were about to
re-download or re-extract them, stop and read
[`WORKSPACE-MANIFEST.md`](WORKSPACE-MANIFEST.md).

For questions about *what the papers imply*, go to
`docs/research/2026-09-21/arxiv-program/index/` — `corpus-index.jsonl`,
`IMPROVEMENT-LEDGER.md`, `SIGNAL-GAPS.md`, `BUILD-QUEUE.md`.

## The second thing to know

**495 branches on `origin` are not in `main`. 116 of them carry ≥5 changed
files.** Work gets pushed and never merged. If you branch from `main`, you will
not see it, and the agent after you will not either.

Before you build something, check [`BRANCH-MAP.md`](BRANCH-MAP.md) for whether
it already exists on a branch. Before you report done, understand that a push
is not a merge.

## When you finish a piece of work

1. Commit to a named branch (never straight to `main`).
2. Push it.
3. **Say in your report which branch, and that it is unmerged** — so the next
   agent can find it in the map.

That third step is the whole fix. The map is regenerated by
`scripts/gen-agent-index.py`; it cannot document work that was never pushed.
