# [1851] When Do Corrective Features Help? An Agent for Corrective Feature Discovery on Black-Box Forecasters (CRAFTER) (arXiv:2608.05207)

**Citation:** Fangxin Wang, Ziyi Zhang, Diyi Zhuang, Langzhou He, Shiyu Wang, Baichuan Mo, Philip S. Yu (2026). *When Do Corrective Features Help? An Agent for Corrective Feature Discovery on Black-Box Forecasters (CRAFTER)*. arXiv:2608.05207v1. URL: https://arxiv.org/abs/2608.05207
**Ledger completed:** 2026-09-22. **Read:** full text (PDF, lines 0–3220, main body, references, all supplement appendices — Alg S1, Tables S1–S13, LLM prompts/roles, feature-source anatomy, transferability, budget sweep).
**Verdict:** ADOPT

Rationale: the frozen-backbone + source-blind gate + validation-selected corrector with a NONE floor is directly deployable onto the GSE engine as a risk-capped correction layer, and the headroom characterization tells Garrett exactly where to deploy it and where not to.

## 1. Research question
When does post-hoc corrective feature discovery help a frozen black-box forecaster — i.e., under what conditions does mining interpretable features of the model's residual (y − ŷ) and applying a lightweight corrector improve accuracy — and which feature source (enumerable compositional search vs. LLM-named semantic features) drives the gain?

## 2. Dataset / schema
Six public forecasting datasets: EPF-DE (German day-ahead electricity prices), ROSSMANN and ROHLIK (promotion-driven retail panels), BIZITOBS-L2C (hourly business operations), FAVORITA (store-sales panel), M5 (weekly competition data). All public access. Six frozen pretrained backbones (run covariate-blind so all methods correct the same residual): Timer, Chronos, Moirai, Toto, Chronos-2, Moirai-2.0. Metric: wMAPE of the horizon *total* (the deployment-consumed quantity). Public datasets may appear in the LLMs' pretraining corpora; the authors argue the leakage surface is small (the LLM emits only feature specs/code reading past history and the backbone forecast, never test-period values).

## 3. Method / model
Two heterogeneous generators mine the frozen backbone's residual: (a) a compositional Monte-Carlo tree search (4-layer conditioned UCB1 tree: family → arity → channels → operator; families pool channels so one reward updates a whole mechanism; per-arity statistics so univariate/bivariate evidence never mix; canonical order-and-rename-invariant hash dedup + rejection blacklist; decayed credit to sibling contexts; UCB1 with κ = 1.4, R = 3 rounds), and (b) an LLM proposing named combinations (LLMcombo), binary flags (LLMflag), and short executable code (LLMcode). LLM roles (Appendix H): PLANNER (fast tier, strict-JSON exploration directions), SPECIFIER + REFLECTION (reasoning tier; REFLECTION fires only when <3 candidates pass), BASE PROPOSER (invents new univariate base columns; forbidden from mixing history and forecast in one function); legacy RERANKER disabled — the merged pool is gated deterministically, not by LLM. ~12 LLM queries per 3-round run. Both generators feed one source-blind acceptance gate: a candidate survives only if its Spearman correlation with the unexplained validation residual exceeds a threshold, it is not collinear with an accepted feature, and per-family/per-round budgets hold. One CRAFTER round (Alg S1): fit corrector set on F → residual r → PLANNER directions → SPECIFIER + UCB-SAMPLE → source-blind gate → admit → refit corrector on F∪A → permutation-Δval-wMAPE prune → update UCB credits. The corrector is validation-selected from {NONE, additive GBDT, multiplicative GBDT} (histogram GB: 200 trees, depth 4, lr 0.1, min_samples_leaf 20); NONE is an asymmetric bet — a round never ships a corrector worse on validation than leaving the backbone alone. The coupled variant CRAFTER†: LLM-invented base columns join the search's channel pool in later rounds, and the search's accepted/rejected sets condition the next LLM proposal. Crucial routing choice (§5.4): covariates enter only as *corrector* features, never as backbone inputs — feeding covariates directly to a covariate-capable backbone (Moirai-2.0) can substantially degrade the raw forecast; the correction layer is stable across this choice. The same harness runs every method (identical cached residuals, same gate, same corrector set, same top-K selection, same GPT-5.2 backend) — so CRAFTER also functions as an *instrument*: any external FE system runs through the pipeline, and forecast differences are attributable to the feature source alone. Compute (Appendix D): backbones run once on A100/A40 and cache; the residual-correction loop runs on CPU; a full single-seed sweep of the 36-cell grid completes in ~30 min on warm caches — orders of magnitude cheaper than per-dataset finetuning.

## 4. Equations & assumptions
- Correction factor: multiplicative f = clip(y˜_h/ŷ_h, 0.3, 3.0), plus an additive-offset option.
- Acceptance gate: accept iff |ρ_Spearman(c, r)| > τ with τ = 0.05 global (no per-dataset tuning) AND pairwise |ρ| ≤ 0.75 with accepted features AND ≤2 features/family AND ≤10/round.
- Search reward: r_proxy = 0.4|ρ| + 0.3·I[accepted], plus realized signal from gradient-boosting importance and γ = 0.3·(round Δval-wMAPE). UCB1 with κ = 1.4, K = 4 planner directions per round.
- Vocabulary: B = 8 binary ops {add, sub, mul, div, abs_diff, min, max, safe_div}, T = 15 unary transforms, flag conditions {<,≤,>,≥,=,≠,between,in,not_in}; families: level/trend/seasonality/volatility/shift/anomaly.
- Stated assumptions: residual headroom orders the gain (weak backbones with informative covariates → large gains; saturated cells → neutral/negative); the LLM and the search compete on one validation-grounded scale (source-blindness); a feature that does not beat the residual-correlation gate never ships; the NONE floor is a validation-time safeguard, not a test guarantee.

## 5. Features / target
Target: the horizon total (wMAPE on the horizon total). Input channels: backbone forecast + exogenous covariates (per dataset). Candidate feature kinds: atomic (compositional search specs), LLMcombo (named exogenous combinations), LLMflag (binary flags), LLMcode (short executable code). ~74% of selected features are LLM-sourced; survival rates: LLMcombo 68%, LLMflag 41–44%, LLMcode 9% (code features almost always pruned); atomic 58–61%. Representative accepted features (Appendix J): renewable_penetration (renewables-forecast/load-forecast ratio, ρ=−0.81, share 81% on EPF/Moirai), baseline_mean_x_open (context-mean × Open, share 88% on ROSSMANN), event_ratio (last-value/context-mean, earthquake-shock flag on FAVORITA), min(softplus(hour), is_weekend) (ρ=−0.78, share 48% on BIZITOBS), trend_r_squared (share 55% on FAVORITA/Toto), mk_trend_tau = Kendall τ of demand vs. time (share 28% on M5).

## 6. Validation design
Rolling-origin backtest: three expanding train:val:test splits (6:1:1, 7:1:1, 8:1:1), 3 seeds, 9 runs per (dataset, backbone) cell — 36 cells total. Every feature-engineering method uses the same harness, so only the feature generator differs. RAW, COV (covariate-only corrector), and FT (head-only finetune) involve no LLM/search randomness and are single-run on the same splits. Significance: one-sided Wilcoxon signed-rank over paired cells. Cross-LLM reproduction on DeepSeek-3.4-pro with the same grid.

## 7. Numerical results / baselines
- CRAFTER and CRAFTER† beat tsfresh, CAAFE, and LLM-FE at *every* feature budget K ∈ {5, 10, 20, 50, All}; paired Wilcoxon p<0.01. At K=5 CRAFTER already exceeds the best external system's uncapped budget — the margin is feature quality, not count.
- Mean test-wMAPE lift over RAW (GPT-5.2): Timer +25.7/+25.8 (CRAFTER/CRAFTER†), Chronos +8.5/+11.4, Moirai +27.2/+26.8, Toto +14.8/+16.6, Chronos-2 +6.4/+7.4, Moirai-2 +12.5/+12.8; wins 3–6/6 datasets per backbone. Weakest backbones' error cut by up to 27%.
- Roughly *doubles* the corrector-only (COV) lift — the discovered features add real value beyond just giving the corrector the raw covariates.
- Finetuning (Tables S1–S2): head-only and full-parameter finetuning do not remove the gain — ordering CRAFTER < COV < no-correction holds on both zero-shot and finetuned branches (EPF/ROSSMANN/ROHLIK); on 6/8 full-param Moirai cells CRAFTER still helps; finetuning rarely beats correcting the frozen backbone. M5 is saturated — all gradients coincide (the headroom condition).
- Without-vs-with LLM (Table S5): atomic UCB search alone moves accuracy by ≈0 (better-or-equal on 10/30 cells, mean +0.006 wMAPE); adding the LLM is the decisive step (mean −0.037 wMAPE, better on 28/30 cells), concentrated on weak-backbone cells.
- Feature budget (Table S11): K = 20 is the practical operating point (K = 20/50/all nearly identical); win rate over RAW is 80% across every K — the budget never changes *which* cells win, only the margin; on raw-weak cells mean lift reaches −0.131 at K=20 vs +0.008 on raw-strong cells (budget amplifies an existing gap).
- Main grid (Table S12): CRAFTER beats every non-finetuned baseline in most of the 36 cells and also beats FT in many EPF/ROSSMANN cells (marked ∗); saturated M5/FAVORITA rows show no gain.
- Backend robustness (Table S13, DeepSeek-3.4-pro): same qualitative pattern (e.g., Moirai +27.9%), but median per-cell seed std is 0.49 (CRAFTER) vs 0.01–0.08 for TSFresh/CAAFE/LLM-FE — CRAFTER's LLM sampling is the noisiest; largest stds sit on EPF and BIZITOBS; split variance (≈3.2) dominates seed variance (0.49), so temporal drift is the bigger deployment risk than seed noise.
- Transferability (Tables S9–S10): features transferred from an earlier split match the target's own features at the median (relative +0.2%, 17/30 within ±5%); median +0.0% vs the covariate-only corrector, 12/30 beat it; 7/30 catastrophic transfers (worse than self by >15%) concentrate on single-series EPF with Moirai — volatile, shift-sensitive corner; multivariate BIZITOBS transfers at median +0.0%. Low feature-name overlap across splits = equivalent-feature redundancy, not nontransferability.

## 9. Leakage & limitations
- Headroom rule: in saturated cells (M5 rows; BIZITOBS under Chronos/Moirai-2.0) no feature source yields a reliable improvement — every column collapses onto RAW. The paper reports these cells honestly alongside the wins.
- A low-headroom cell can still regress out-of-sample under rolling-origin shift even when validation favored correction (BIZITOBS/Chronos noted). The NONE floor is a validation-time safeguard, not a test guarantee.
- Public datasets may appear in the LLMs' pretraining corpora; the authors argue the leakage surface is small.
- Feature budget is an amplifier, not a switch: larger K widens the margin where headroom exists but cannot manufacture structure where the residual is already near noise — it mostly adds variance and selection risk in saturated cells.
- LLM sampling noise: median per-cell seed std 0.49 for CRAFTER vs 0.01–0.08 for TSFresh/CAAFE/LLM-FE; volatile cells (EPF) vary across backends — the deployment rule is backend-invariant, not the feature sets.
- LLMcode features are almost always pruned (9% survival) — LLM free-form code is not the value; named combos and flags are.
- Catastrophic transfer exists: 7/30 cells where transferred features are >15% worse than the target's own, concentrated on single-series EPF with Moirai.

## 10. GSE overlap
GSE's engine is a frozen backbone in exactly this paper's sense: retraining/re-architecting it is expensive, but its residual has structure — primetime effects, weather, divisional familiarity, rest differentials, QB changes, coaching regimes. CRAFTER gives a principled, cheap way to fix blind spots without touching the model. The deployment rule is the valuable part: measure residual headroom first; deploy corrective discovery where residuals are structured (props markets, totals — GSE's growth lanes), and do not force correction in saturated cells (mature spread markets where the engine already fits). The NONE-floor corrector is a risk posture GSE should adopt wholesale: a correction layer that can only ship when it beats "do nothing" on validation is an asymmetric bet, matching Garrett's floor-check discipline. The covariate-routing finding is directly actionable: route new signals (injuries, weather, market data) to a residual corrector first, not into the engine's inputs, where they can degrade the raw forecast. This is a new capability (residual-mined correction layer with headroom-based deployment), not a duplicate of existing GSE work.

## 11. GSE implementation spec
Sports bridge: NFL engine residual mining — freeze the GSE pick engine; compute residuals on historical picks (actual minus predicted margin/total); run the two-generator loop where the LLM proposes named sports mechanisms the schema lacks (e.g., `short_rest_divisional = 1[rest_days ≤ 4 ∧ divisional_game]`, `backup_qb_spread_shock`, `wind_chill_kicking`) and the compositional search enumerates rolling/interaction specs over existing channels. The gate admits only features that explain validation-window residual, and the corrector (additive/multiplicative GBDT over accepted features, or NONE) adjusts each pick. Event-spike analogs of the paper's promotions/rare-events: playoff games, weather outliers, mid-season QB changes — exactly where a frozen engine's residual concentrates.

Concrete build plan:
1. Residual store: for every historical engine pick, record (game_id, engine forecast, actual outcome, residual, all covariate channels available at kickoff).
2. Generator A (compositional): typed grammar over existing channels — transforms (rolling means/stds, z-scores, lags, safe_div, log, softplus) × operators (+, −, ×, ÷, min, max), MCTS/UCB1 with reward = Spearman ρ vs. unexplained validation residual + realized validation wMAPE gain (κ=1.4, per the paper).
3. Generator B (LLM): roles (Planner → Specifier → Base Proposer → Reflection); propose named combos, binary flags, short pandas code; hard rule: code may only read pre-kickoff history and the engine forecast — AST-scan for negative shifts before execution (~12 LLM queries per 3-round run in the paper).
4. Gate: accept iff Spearman ρ(candidate, unexplained validation residual) > τ (τ=0.05 start) AND max |corr| with accepted set < 0.75 AND ≤2/family, ≤10/round. Source-blind: LLM and search candidates scored identically.
5. Corrector: fit {NONE, additive GBDT, multiplicative GBDT} on accepted features; ship the best validation wMAPE; R=3 rounds of diagnose → re-mine.
6. Feature memory: persist accepted features; warm-start the next window's corrector and re-validate (the paper's §5.5 transfer result justifies amortizing the search — but replay on EPF-like volatile regimes requires fresh validation).

## 12. Reproducible test
Task: correct the GSE engine's historical NFL spread/total residuals, 2019–2023 train, 2024 validation, 2025 test, rolling-origin with three expanding splits. Baselines: RAW engine, covariate-only GBDT corrector (COV analog), and one external FE system (tsfresh bank) run through the identical gate/corrector harness. Metric: wMAPE-style calibration/log-loss on the horizon (game) total; one-sided Wilcoxon over per-game paired cells.

## 13. Acceptance / rejection gate
ADOPT if: ≥0.003 held-out NFL log-loss improvement on 2025 games versus both the RAW engine and the covariate-only corrector, with the NONE floor holding (no shipped corrector worse than "do nothing" on validation), no post-kickoff leakage in any accepted feature (AST-verified), and ≥60% of accepted features human-auditable with a named sports mechanism. REJECT (do not deploy) if any of: leakage scan fails, no gate improvement vs. both baselines, review auditability <60%, or all target markets show the saturated-cell pattern (correction collapses onto RAW).

## 14. Improvement experiment
The paper's headroom characterization is descriptive — it never uses headroom to *gate the spend*. Run a headroom-gated deployment experiment: first fit only the cheap covariate-only GBDT corrector (COV) on each market's residuals and measure its validation lift as a headroom proxy; then run the full LLM+search loop only on markets whose COV lift exceeds a threshold (say 2% wMAPE), and ship NONE everywhere else. Compare (a) total LLM/API spend, (b) retained aggregate lift, and (c) the false-deployment rate (corrections shipped that regress out-of-sample) against the paper's always-run-the-loop protocol. Rationale: the paper shows the LLM is the expensive differentiator (≈74% of selected features, ~12 queries/run) while budget amplifies rather than creates gains — so a cheap headroom pre-test could keep most of the lift at a fraction of the cost, and it directly tests whether the headroom rule generalizes from their six datasets to GSE's markets.
