# [0116] Governed MCP: Kernel-Level Tool Governance for AI Agents via Logit-Based Safety Primitives (arXiv:2604.16870v2)

**Citation:** Daeyeon Son (Independent Researcher, Republic of Korea). *Governed MCP: Kernel-Level Tool Governance for AI Agents via Logit-Based Safety Primitives*. arXiv:2604.16870v2, July 2026 (v2 revision). URL: https://arxiv.org/abs/2604.16870v2
**Ledger completed:** 2026-09-21. **Read:** full text (PDF via arxiv.org, 2061 lines; all sections, algorithm, tables, ablations, limitations read; equations partially garbled — reconstructions flagged as uncertain).
**Verdict:** ADAPT — a kernel-resident MCP tool-governance gateway built on a logit-based safety primitive (ProbeLogits). The baremetal Anima OS implementation is overkill for GSE, but the portable pattern is directly useful: a single mediated chokepoint in front of GSE's MCP servers enforcing schema/trust/rate/prefilter/semantic/policy layers, fail-closed semantics, a Blake3-hashed audit chain, and ProbeLogits-style single-forward-pass safety scoring as a cheaper alternative to a full guardrail LLM call.

## 1. Research question
Tool calls are an agent's syscalls — privileged operations with side effects on shared state — yet today's safety enforcement (NeMo Guardrails, AGT schemas, AutoGPT wrappers) lives entirely in userspace, where the agent process has the same privilege as the safety library. Listing 1 shows three 10-line bypasses: (1) skip the import entirely, (2) monkeypatch `nemoguardrails.LLMRails.generate = lambda self, p: p`, (3) mutate the returned verdict dict (`result["allowed"] = True`). No amount of library-level hardening closes the gap because the gap is at the privilege boundary. The paper asks: can tool-call governance be made a kernel-resident reference monitor — a six-layer pipeline (schema validation, trust tier, rate limit, adversarial prefilter, ProbeLogits semantic gate, constitutional policy match) with a Blake3-hashed audit chain — such that the userspace bypass becomes structurally impossible, and is the logit-based semantic layer actually load-bearing?

## 3. Method / model
Implemented in **Anima OS**, a baremetal x86_64 OS in ~286,000 lines of Rust across 378 files (AGPL-3.0; kernel alone ~194K lines). Agents execute as WASM bytecode in a ring-3 sandbox; the only egress to system effects is the kernel-resident `governance_check_host()` host function (single mediated entry; inner `call_tool_raw` is `pub(crate)`, not in the WASM ABI). Every `call_tool` traverses six layers in fixed order (Algorithm 1):
1. **Schema validation** — JSON-RPC parse + MCP tool input-JSON-Schema match; denies type mismatches, missing fields, unknown tools (0.10 µs, silicon-measured).
2. **Trust tier check** — agents classified System / AiNative / AiEnhanced / Classic; each tool declares a minimum tier; Classic agents can't invoke e.g. `system_shell_exec` (1.15 µs).
3. **Rate limit** — per-agent token-bucket with per-tool granularity (e.g., 10 web_fetch/s, 1 shell_exec/s), millisecond refill clock (0.02 µs).
4. **Adversarial prefilter** — O(n) regex DFA over arguments for injection/encoding patterns ("ignore previous instructions", base64 payloads, ROT13, "ADMIN OVERRIDE", "system: ..."); catches ~13/50 adversarial prompts in Custom-260 (7.50 µs — the most expensive non-inference layer).
5. **ProbeLogits gate** — one forward pass of the loaded inference model with KV snapshot/restore around it (see §4); the only semantic check and the only LLM-cost layer (358/332/556 ms per classification on Qwen2.5-7B / Llama 3 8B / Mistral 7B).
6. **Constitutional policy match** — 12-principle predicates over (agent, tool, arguments, result), e.g. "no agent may invoke shell_exec on a path containing /etc/shadow"; "no web_post to a private RFC1918 address from a Classic agent" (1.83 µs).
- **Audit chain:** every decision appends (timestamp, agent_id, tool_name, arg_hash, deciding_layer, verdict, prev_hash) to a 4 MB ring buffer (~30K records), keyed Blake3-hashed chain (0.73 µs); intra-boot integrity only, flushed to AnimaFS at checkpoints; cross-boot continuity is deferred future work.
- **FAIL-CLOSED semantics:** if the inference engine is unavailable (model not loaded, KV exhausted, deadlock), layer 5 returns Deny — all tool calls denied system-wide until recovery. Gateway also refuses to boot without a usable verbalizer pair.
- **Mediation coverage:** rebuilt enumerated-path harness (silicon-measured, single boot, 2026-07-05) covers 59 agent-to-system paths: 18 WASM host functions (15 governed + 3 readonly), 20 registered MCP tools (all verdict-verified via dry-run), 21 ring-3 syscalls (7 gateway-governed, 1 self-gated, 2 readonly metadata, 5 pure, **6 resource-reaching syscalls ungated** — put, fetch, kv_set, kv_get, send_msg, recv_msg — deferred to milestone M4.2; the v1 "123 paths, 100% mediated" claim is explicitly withdrawn).

## 4. Equations & assumptions
From §4.3–4.5 and Algorithm 1 (reconstructed from garbled PDF — notation uncertain):
- **ProbeLogits score:** "ProbeLogits returns a single real-valued safety score s ∈ (−∞, +∞) representing logit(Dangerous) − logit(Safe) at the verbalizer position, with calibration bias subtracted and scaled by α. The gateway thresholds at s > 0 to reject; α is the deployment-time policy knob (higher α = more conservative)." *(Reconstructed — uncertain.)*
- **Calibrated confidence:** "ProbeLogits() returns (ans, p) where ans is the Boolean 'model says Dangerous' and p ∈ [0,1] is the sigmoid-calibrated confidence (p = σ(s) from s ∈ R)." *(Reconstructed — uncertain.)*
- **Graduated response (Algorithm 1, lines 24–29):** deny only when `ans ∧ p > 0.90`; calls in band [0.70, 0.90] are allowed but logged as warnings (LogWarn); below 0.70 proceed normally. Production default α = 0.9. Tightening to 0.70 (binary deny above 0.70) raises recall at more overrefusal cost. *(Reconstructed — uncertain.)*
- **Per-model boot contract:** Token Fertility check ensures the verbalizer pair ("Safe"/"Dangerous" or "Yes"/"No") tokenizes to single vocab IDs; calibration bias measured once on 7 null-input prompts and cached; no usable pair → gateway refuses to start.
- **KV snapshot/restore:** snapshot = per-layer copy of key/value tensors at current position — measured 0.93 MB for Qwen2.5-7B Q4_0 at 32 cached positions, taken via direct memcpy in 0.037 ms, restore 0.016 ms (0.053 ms round trip); size scales linearly with cached positions; probe runs in a dedicated KV context discarded after each call.
- **Throughput bound:** single global inference-engine lock, FIFO; ~1/358 ms ≈ 2.8 governed tool calls/s on the 7B config; no priority inheritance (a high-frequency Classic agent can delay a System agent — disclosed).
- Assumptions: correct Cranelift WASM isolation (JIT-bug bypass classes, e.g. 2021–2023 wasmtime CVEs, explicitly out of scope); baremetal single-tenant environment (Spectre-style speculation "mitigated" but not formally precluded); the inference model loaded at boot is genuine (no signature check / measured boot — listed out of scope); TOCTOU races on tool arguments closed only in single-threaded agent execution; side channels via latency/argument size unaddressed; tool outputs not yet probed (post-execution probing is future work).

## 5. Features / target
Input: candidate MCP `call_tool(name, args)` + agent trust tier. Target: binary verdict ∈ {Allow, Deny} with a calibrated confidence and a graduated warn band; features are the tool call's JSON-RPC arguments (prefilter regex features, constitutional predicates) plus the semantic logit score from the probe model. Probe prompt template: "Is this action dangerous, harmful, or a privacy violation? …" prepended to the action; one forward pass, read the verbalizer-position logits. ProbeLogits is architecture-agnostic for the tested models; "verbalizer choice — not architecture — is the first-order design lever."

## 6. Validation design
- **Custom-101 primary governance evaluation**, end-to-end on Anima OS native (UEFI boot, no QEMU), Qwen2.5-7B-Instruct Q4_0 loaded: silicon-measured F1 (v2 headline supersedes v1's runtime-shell-only 0.773).
- **Ablation (4 configurations):** Full pipeline, No prefilter, No ProbeLogits (L5), No layer-4 (prefilter+probe) — notes the current tree exposes no constitutional-only toggle, so the fourth cell is reported as partial.
- **Custom-260 pipeline validation** (260 prompts, all six layers active).
- **Multi-model substrate validation:** HarmBench, XSTest, ToxicChat across Qwen2.5-7B, Llama 3 8B, Mistral 7B (hosted, llamacpp-python, archived runs in the companion repo's results/).
- **Threshold sweep:** α ∈ {0.30, 0.50, 0.70, 0.80, 1.00}, silicon-measured, single boot.
- **Performance:** per-layer latency microbench (n=64 benign no-probe calls, in-OS, 2026-07-05); hosted per-classification latency (150 samples/model, 9800X3D, 8 threads); gateway-lock acquisition stats.
- Weaknesses (author-disclosed): Custom-101 is author-labeled (the only existing MCP-domain benchmark; community benchmark + red-team competition is future work); no external human red-team study (5+ attackers planned); no constitutional-only ablation cell; six ring-3 syscalls ungated until M4.2; post-execution tool-output probing not implemented; no model provenance verification at boot.

## 7. Numerical results / baselines
- **Custom-101 (silicon-measured, full 6-layer):** F1 = 0.789 (accuracy 84.2%, precision 0.769, recall 0.811; TP 30, FN 7, FP 9, TN 55). Error modes: 7 false negatives (mostly subtle "deception/agent manipulation" phrasing — e.g., `shell_exec("for f in *; do mv $f .$f; done")` in /var/www scored s = −1.3, allowed); 9 false positives (ambiguous filesystem reads).
- **Ablation (Table 3):** No prefilter — F1 0.805 (TP31/TN55/FP9/FN6, slightly *better* than full; prefilter's value is zero-cost early denial, not F1); No ProbeLogits — 0.357 (TP10/FN27; ΔF1 = −0.432); No layer-4 — 0.327 (TP9/FN28, near chance). Finding: hand-rule firewalling without semantic understanding admits 27/37 dangerous calls.
- **Case studies:** file_read("/home/user/.ssh/id_rsa") → s = +4.8, blocked at L5; shell_exec("dd if=/dev/zero of=/dev/sda bs=1M") → s = +6.2, denied (no rule enumerates it); web_post attacker-exfil sequence blocked at step 1.
- **Custom-260:** F1 = 0.980, P = 1.000, R = 0.960 (TP 169, FN 7, FP 0, TN 84; accuracy 97.3%) — FP=0 is the "deployment-killer" property (flags are safe to block without human review).
- **Multi-model (Table 4):** HarmBench non-copyright block rate — Qwen2.5-7B 99.0%, Llama 3 8B 98.0%, Mistral 7B 98.7% (1 pp spread); HarmBench overall — 86.8% / 75.0% / 79.5%; XSTest unsafe recall — 1.000 / 0.985 / 0.995; XSTest overrefusal (safe) — 0.864 / 0.516 / 0.556 (model-specific cost); XSTest F1 — 0.649 / 0.749 / 0.740.
- **ToxicChat:** ProbeLogits-Llama-3 F1 = 0.679 vs. Llama Guard 3 F1 = 0.675 — parity (+0.4 pp) with a vanilla instruction-tuned model vs. a fine-tuned classifier, +10.5 pp recall, 2.4–3.4× lower per-classification latency.
- **Latency (Table 5/6):** non-inference layers total 11.3 µs (schema 0.10, trust 1.15, rate 0.02, prefilter 7.50, constitutional 1.83, audit 0.73 µs; components sum consistently to 11.33 µs — supersedes v1's unarchived 65.3 µs). ProbeLogits per classification: 358 ms (Qwen2.5-7B Q4_0), 332 ms (Llama 3 8B Q4_0), 556 ms (Mistral 7B Q8_0) — 2.38×/2.56×/1.53× vs. Llama Guard 3 Q4_K_M (851 ms), 3.19×/3.44×/2.05× vs. Q8_0 (1142 ms). End-to-end ~358 ms; gateway throughput ≈ 2.8 governed calls/s. NeMo Guardrails runs 2–3 LLM roundtrips per check (~2–5 s end-to-end in NVIDIA's demos).
- **Threshold sweep:** F1 = 0.414 (α=0.30), 0.667 (0.50), 0.789 (0.70), 0.789 (0.80), 0.789 (1.00) — plateau from 0.70 upward; conservative default α=0.9 costs nothing on this benchmark. Naive small-model cascades are not viable: SmolLM2-135M blocks only ~13% of HarmBench, a 0.5B model overrefuses ~70% of safe prompts.

## 9. Leakage & limitations
Adversarial reading: (1) The baremetal kernel implementation is a research artifact, not a deployable path for GSE — the threat model (adversarial agent escaping the sandbox) is far stronger than GSE's actual risk (its own agents misfiring, not malicious escape). (2) 358 ms per tool call is a hard tax on agentic loops (GSE's Motif/Hermes lanes make hundreds of tool calls/hour; ~2.8 calls/s ceiling is fine for a single agent but a shared gateway would need the GPU-offload future work). (3) Custom-101 is author-labeled — the headline 0.789 F1 is measured on the author's own test; external benchmarks validate only the substrate primitive, not the MCP-domain gateway behavior. (4) 7 false negatives include exactly the "looks benign in context" class that matters most (the /var/www file-hiding case). (5) Six ring-3 syscall paths ungated until M4.2 — the "complete mediation" claim is scoped, and the paper honestly withdraws the v1 100% claim. (6) No model provenance at boot — a substituted model invalidates the substrate, and it's listed out of scope. (7) Trust-tier classification of agents is hand-waved ("origin, signature, and prior trust evolution") with no formal definition.

## 11. GSE implementation spec
Adapted, userspace (no kernel): (1) build a single MCP gateway process on the Motif VM through which all GSE agent tool calls route — schema validation (JSON Schema per tool), trust tiers (system agents vs. experimental lanes), per-agent token-bucket rate limits (e.g., 1 shell_exec/s), regex prefilter for prompt-injection patterns (the paper's pattern classes), a semantic gate implemented as a ProbeLogits-style single-prefill logit read on a small local model OR a cheap guardrail LLM call (paper shows vanilla instruction-tuned 7B at parity with Llama Guard 3 at 2.4–3.4× lower latency), and a constitutional rule list (no writes outside ~/workspace, no credential exfiltration, no mass-delete commands); (2) graduated response: deny at p > 0.90, warn-and-log at 0.70–0.90, fail-closed when the semantic layer is unavailable; (3) Blake3-chained append-only audit log of every tool decision; (4) measure: false-positive rate on a week of real GSE agent traffic (target FP < 5%), added latency per call (target < 500 ms), dangerous-call catch rate on a GSE-authored red-team set. Estimated effort: 2–3 weeks for a userspace Python gateway; no Rust/kernel work needed.

## 13. Acceptance / rejection gate
ADAPT if: (a) a GSE-authored red-team set (≥50 dangerous tool calls spanning exfiltration, destructive shell, prompt injection) is blocked at ≥95% with FP < 5% on benign traffic; (b) per-call added latency ≤ 500 ms; (c) the repo URL is located and the AGPL-3.0 license is confirmed. Do NOT adopt the kernel/Anima OS implementation; adopt the 6-layer pattern + ProbeLogits primitive + audit chain in userspace. Reject if the semantic gate's FP rate on real traffic exceeds 10% — then keep only layers 1–4 + 6 (schema/trust/rate/rules), which cost ~11 µs.

## 14. Improvement experiment
Close the paper's biggest open hole for GSE: **post-execution probing of tool outputs** (the paper's own future work — indirect prompt injection lives in tool results). Build a layer-7 that runs the ProbeLogits probe on tool *outputs* before returning them to the agent, defending against compromised-MCP-server and web-content injection (threat cases 2 and 5). Test: feed the gateway tool outputs containing known indirect-injection payloads (the Greshake et al. classes) and measure block rate vs. the input-only gateway; adopt if output probing adds ≥15 pp block rate on injection outputs at ≤5% additional FP on benign outputs.
