# [2173] ERBench: A Benchmark and Testsuite for Equation Discovery Algorithms (arXiv:2606.09276)

**Citation:** Paul Kahlmeyer, Henrik Voigt, Michael Habeck, Joachim Giesen (2026). *ERBench: A Benchmark and Testsuite for Equation Discovery Algorithms*. arXiv:2606.09276. URL: https://arxiv.org/abs/2606.09276
**Ledger completed:** 2026-09-22. **Read:** full text (ar5iv HTML).
**Verdict:** ADAPT — the first benchmark that measures what GSE actually needs from equation discovery: *recovery* of ground-truth formulas (not in-domain fit), with 10,000 public formulas, a secret 1,000-formula competition set, and diagnostics across complexity/noise/sample-size/domain axes. GSE should adopt it as the regression test for every SR pipeline change.

## 1. Research question
In-domain predictive accuracy is a misleading proxy for scientific discovery — a polynomial can fit Newton's cooling curve perfectly yet predict below room temperature out-of-domain (Figure 1). Existing SR benchmarks (SRBench, Feynman sets) use few public formulas that leak into LLM pre-training and don't stress robustness. Can we build a common-task framework where the criterion is *symbolic recovery* of known laws, with public dev data, a secret eval set, and diagnostics that pinpoint exactly where an algorithm breaks?

## 2. Dataset / schema
**Public dev set: 10,000 formulas** (Table 2): Feynman (130), Strogatz (14), OEIS integer sequences (3,757), Eponymous/Wikipedia formulas (211, domains LLM-extracted and human-checked), PHYBench (90), SynEq synthetic DAG-sampled (5,303), SciPy densities (33), Livermore (175), Nguyen (12), Keijzer (15), Korns (15), Koza (2), Pagie (1), Vladislavleva (8), SRDS (234). **Secret eval set: 1,000 formulas** generated by a withheld parameterized process, served via competition website (https://equation-discovery.ti2.fmi.uni-jena.de/) with a triple-permutation protocol (problem order, sample order, variable order), single-use request IDs, aggregated-only scores. Sampling: diverse distribution (Kamienny et al.); domains per-formula with validity guards. Public data: https://huggingface.co/datasets/EquationDiscovery/Equation_Recovery_Benchmark.

## 3. Method / model
Not an SR method — an evaluation framework. **Metrics:** (1) Symbolic Recovery Rate — sympy-verified equivalence up to scale/shift (f−f̂=c₀ or f/f̂=c₁, Eq. 2), tiered simplification; (2) Jaccard Index over unique subexpression sets, JI = |S_true ∩ S_pred|/|S_true ∪ S_pred| (Eq. 3) — partial credit for correct substructures; (3) normalized Tree Edit Distance, TED = dist/(|T_true|+|T_pred|) via Zhang–Shasha (Eq. 4). Numeric-equivalence check (1,000 points in [−100,100]^d) used as the fast upper bound — found identical to symbolic in practice. **Diagnostics:** recovery vs operator count, sampling distribution, noise level, sample size. Taxonomy of 5 SR paradigms (conventional/sparse, enumeration, sampling-based, pre-trained, hybrid) with design principles (▶) derived per paradigm.

## 4. Equations & assumptions
- Recovery: f̂ ≡ f iff sympy proves f(x)−f̂(x)=c₀ or f(x)/f̂(x)=c₁ (Eq. 2).
- JI(T_true,T_pred) = |S(T_true)∩S(T_pred)|/|S(T_true)∪S(T_pred)| (Eq. 3).
- TED(T_true,T_pred) = dist(T_true,T_pred)/(|T_true|+|T_pred|) (Eq. 4).
- Assumptions: recovery of known laws predicts discovery of unknown ones (Popperian rationale); sympy timeouts = failures (strict lower bound); secret set stays secret (anti-contamination).

## 5. Features / target
10k/1k formulas spanning engineering, biology, chemistry, math, physics + synthetic; algebraic and transcendental forms; robustness axes: dimensionality, complexity (operator count), sample size, sampling domain, noise, distribution.

## 6. Validation design
6 algorithms × secret 1,000-formula set, default hyperparameters, 5 runs: PySR, DSR, E2E, Operon, gplearn, linear-regression baseline. Metrics: Recovery, JI, TED (+holdout accuracy secondary). Diagnostic deep-dive on PySR (Feynman subset): complexity/noise/sample-size/distribution sweeps.

## 7. Numerical results / baselines
- **PySR is the only method with non-trivial recovery: 0.29 ± 0.04** (Table 3). DSR, E2E, Operon: 0.00. gplearn: 0.05 ± 0.01. Linear: 0.00.
- **JI:** PySR 0.49 ± 0.02; DSR 0.28; linear baseline 0.25 — complex methods barely beat linear on parsimony-adjusted partial credit (bloated wrong trees penalized). **TED:** PySR 13.4, linear 14.6, gplearn 45.2.
- **Diagnostics (Figure 6):** PySR near-perfect recovery at 1–3 operators → near-zero beyond 13 operators; uniform sampling ≈ +10% over diverse distribution; noise steadily degrades; more samples steadily help. Conclusion: *problem complexity, not data scarcity, is the principal bottleneck.*
- Paradigm findings: pre-trained transformers (E2E) collapse outside pre-training domains (Figure 4); enumeration hits exponential walls; sampling-based methods are domain-sensitive (Figure 3).

## 8. Code / data availability
Public dev set + eval code + baseline wrappers: HuggingFace (EquationDiscovery/Equation_Recovery_Benchmark). Competition: equation-discovery.ti2.fmi.uni-jena.de. All open.

## 9. Leakage & limitations
Adversarial notes: (a) Secret-set integrity depends on the website staying uncompromised and request IDs single-use — a social/operational guarantee, not a technical one. (b) Recovery-of-known-laws ⇒ discovery-of-unknown-laws is a philosophical leap, honestly flagged by the authors; real discovery has no ground truth. (c) sympy-based recovery is a strict lower bound (false negatives on unsimplifiable-but-correct forms). (d) Default-hyperparameter evaluation may understate tuned methods. (e) No finance/economics/sports-domain formulas — the "diversity" claim has gaps the authors admit. (f) For GSE: sports equations live in the messy high-dimensional regime the benchmark's own impact statement warns about — clean-law recovery may overstate readiness for noisy NFL data.

## 10. GSE overlap
GSE currently evaluates every discovered equation by validation fit (Brier/MAE) — exactly the "curve-fitting, not equation discovery" failure mode this paper diagnoses (its DSR-vs-linear JI result is the cautionary tale: good fit, zero discovery). GSE has no recovery benchmark, no complexity sweep, no noise sweep, and no secret held-out eval for its SR pipeline. Every ledger in 2166–2172 proposes changing the discovery machinery; without a benchmark, GSE cannot tell whether any change actually improves *discovery* as opposed to *fitting*.

## 11. GSE implementation spec
1. Pull the ERBench public dev set; sample 200 formulas stratified by operator count (1–15) and domain.
2. Run GSE's current PySR pipeline (default config + GSE's sports config) on all 200; score Symbolic Recovery Rate, JI, TED.
3. Run the diagnostic sweeps (Figure 6 protocol): recovery vs complexity, vs noise (0–5%), vs sample size, vs sampling domain — this maps GSE's pipeline failure boundary.
4. Re-run after each pipeline change (ledgers 2166–2172 upgrades): the benchmark becomes the mandatory regression test — no SR config ships to the engine without beating the previous Recovery/JI on the 200-formula panel.
5. Longer term: contribute a sports-domain formula set (Elo/Glicko update rules, Pythagorean expectation, logistic win-prob forms) to ERBench — fills their admitted domain gap and gives GSE a home-field benchmark.
Effort: ~1 week for steps 1–3 (data + wrappers are public). No new data cost.

## 12. Reproducible test
200-formula panel, GSE PySR sports config vs default PySR vs PySR+MDL (ledger 2166) vs PySR+LLM-judge (ledger 2168). Metrics: Recovery rate, JI, TED per config; diagnostic curves per Figure 6. The test is comparative — it ranks GSE's candidate pipelines on discovery ability, not fit.

## 13. Acceptance / rejection gate
**ADAPT if:** GSE's current sports-config PySR scores Recovery < 0.40 on the 200-formula panel (confirming the pipeline is a curve-fitter, not a discoverer — the paper's core warning applies to GSE) AND the diagnostic sweeps identify at least one concrete failure axis (e.g. collapse beyond 8 operators, or noise sensitivity) that a ledger 2166–2172 upgrade is designed to fix. **REJECT if:** current config already recovers ≥ 0.60 (GSE's pipeline is already a strong discoverer — benchmark adds process, not insight) or the panel results don't discriminate between configs (all within noise — benchmark lacks resolution for GSE's operating regime). Gate pre-registered.

## 14. Improvement experiment
Beyond the paper: **sports-grounded recovery tasks**. The paper's formulas are all natural-science; GSE should build the missing domain slice — a "SportsEq" dev set of ~100 formulas with known ground truth from sports analytics: Elo updates, Glicko-2, TrueSkill, Pythagorean win expectation (various exponents), logistic regression win-prob forms, Kelly fractions, overround-implied probabilities, Dixon-Coles corrections. Run the full ERBench metric trio + diagnostic sweeps on SportsEq for each candidate pipeline. If a pipeline tops the physics panel but fails SportsEq (or vice versa), GSE learns that discovery ability is domain-sensitive — a finding the paper's framework enables but its dataset cannot produce — and tunes the pipeline on the domain that actually matters.
