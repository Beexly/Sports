# [0373] ST-VLM: Kinematic Instruction Tuning for Spatio-Temporal Reasoning in Vision-Language Models (arXiv:2503.19355v2)

**Citation:** Dohwan Ko, Sihyeon Kim, Yumin Suh, Vijay Kumar B.G, Minseo Yoon, Manmohan Chandraker, Hyunwoo J. Kim (2025). *ST-VLM: Kinematic Instruction Tuning for Spatio-Temporal Reasoning in Vision-Language Models*. arXiv:2503.19355v2. URL: https://arxiv.org/abs/2503.19355
**Ledger completed:** 2026-09-21. **Read:** full text (PDF text extract, 1987 lines).
**Verdict:** ADAPT — the kinematics instruction-tuning recipe (distance/speed/direction QA pairs over trajectories) is directly portable to an NGS-derived text QA dataset for GSE's analyst copilots; the VLM itself is not the play.

## 1. Research question
Vision-language models fail at kinematic reasoning from video (e.g., GPT-4V cannot estimate a basketball player's traveled distance). Can a VLM be taught spatio-temporal reasoning — traveled distance, traveling speed, movement direction, direction timestamps, and multi-object comparisons — by instruction-tuning on kinematic QA pairs grounded in real-world-scale 3D trajectories, including pseudo-labels generated by 4D reconstruction for videos without 3D annotations?

## 2. Dataset / schema
- **STKit (116K QA pairs, 21K videos):** labeled portion — NuScenes (13K QA, 4K videos, LiDAR), Argoverse2 (8K QA, 0.6K videos, LiDAR), Ego-Exo4D sports (6K QA, 0.8K videos, VIO/SLAM from AR devices, treated as ground truth); pseudo-labeled portion (89K QA, 15.5K videos) — BDD100K (86K QA), LLaVA-Video (2K), MultiSports (1K) via the MonST3R 4D-reconstruction + Metric3Dv2 rescaling + Grounded-SAM2 pipeline.
- **STKit-Bench (1,400 QA pairs):** 200 QA per task × 7 tasks; composition 74.8% NuPlan (unseen LiDAR dataset), 12.5% NuScenes, 5.6% Argoverse2, 7.1% Ego-Exo4D; labels balanced per task (Fig. 5).
- Trajectories sampled at 0.5-s intervals over 40-frame videos (up to 20 s). Training blend: STKit 117K + 100K LLaVA-Video-178K + 20K OpenSpatialDataset.
- Project page: https://ikodoh.github.io/ST-VLM (stated in abstract; code link not confirmed in text).

## 3. Method / model
- **QA construction:** for object i, 3D center P_t^(i) per timestamp; traveled distance = Σ_{t=s}^{e−1} ‖P_{t+1}^(i) − P_t^(i)‖_2; speed = distance/(e−s); movement direction = arccos of cosine similarity between segment vectors and initial direction P_{s+1}^(i) − P_s^(i), discretized to clock-face directions (12 o'clock = initial heading). Seven tasks: single-object (traveled distance, traveling speed, movement direction, direction timestamp) + multi-object comparisons (distance, speed, direction). Movement direction excluded for sports domain due to complex 3D trajectories. Template-based QA with visual bounding-box prompts.
- **Pseudo-labeling pipeline (unlabeled video):** geometric branch — MonST3R 4D reconstruction (depth + intrinsics/extrinsics in dynamic scenes), rescaled to real-world metric via Metric3Dv2 (fixes MonST3R's scale ambiguity); semantic branch — Grounded-SAM2 bounding boxes/masks/trajectories for moving classes (vehicles, humans), confidence/size filtered; masks lifted to 3D, trajectories = barycenter tracking; filtering/smoothing criteria calibrated against ground-truth trajectories in labeled datasets. ~400 s/video on A6000.
- **Model:** fine-tune LLaVA-OneVision 7B on the blend, 1 epoch, batch 128, cosine LR 1e−5, 3 days on 8×A6000. Blending with LLaVA-Video-178K avoids task overfitting (fine-tuning on STKit alone degraded generic benchmarks).

## 4. Equations & assumptions
- Traveled distance: Σ_{t=s}^{e−1} ‖P_{t+1}^(i) − P_t^(i)‖_2.
- Direction: θ_t = arccos(((P_{t+1}^(i) − P_t^(i)) · (P_{s+1}^(i) − P_s^(i))) / (‖P_{t+1}^(i) − P_t^(i)‖ ‖P_{s+1}^(i) − P_s^(i)‖)). (Eq. 1)
- Metrics: distance/speed correct if ŷ ∈ [0.75y, 1.25y], MAE = |y − ŷ|; direction correct if exact clock match, MAE = min(|y−ŷ|, 12−|y−ŷ|); direction timestamp correct if IoU(y, ŷ) ≥ 0.5.
- Stated assumptions: VIO/SLAM trajectories from Ego-Exo4D treated as ground truth; MonST3R+Metric3Dv2 reconstruction is metrically accurate after rescaling; smoothing/filtering thresholds transfer from labeled to unlabeled domains; GPT-4 extraction of numeric predictions from free-text responses is reliable.

## 5. Features / target
Input: video frames + bounding-box visual prompts + template question. Targets: 7 kinematic QA types (distance in meters, speed, clock-face direction, direction-change timestamp, pairwise comparisons). Horizon: up to 20 s clips.

## 6. Validation design
STKit-Bench (label-balanced, 200 QA/task) vs GPT-4V, GPT-4o, 6 open-source 7–8B video VLMs, 2 driving-specific models; robustness checks: GPT-4V with 0/1/3-shot + geometric context (camera extrinsics, depth maps); paraphrased-question benchmark (Table 5); ablation of labeled vs pseudo-labeled data (Table 6); generalization to ActivityNet/TVQA+ and five comprehensive video benchmarks (Table 7); emerging multi-step reasoning qualitative tests (Fig. 7).

## 7. Numerical results / baselines
- STKit-Bench average accuracy (Table 3): ST-VLM-7B **59.8%** vs LLaVA-OneVision-7B 27.4% (+32.4 pp), GPT-4V 28.5%, GPT-4o 26.8%, ELM 27.6%, Dolphins 17.4%, Qwen2.5-VL 22.5%, InternVL2.5 26.0%, InternVideo2.5 15.6%, VideoChat-Flash 22.7%, LLaVA-Video 24.9%, VideoLLaMA3 19.5%. Abstract claims "+31.3% over GPT-4V" (59.8 vs 28.5).
- Per-task (Acc / MAE): traveled distance 49.5% / 25.1 m (vs GPT-4V 4.5% / 33.1 m); speed 42.0% / 11.6 km/h; direction 32.0% / 1.7 clocks; direction timestamp 69.0% / 0.61 IoU; comparisons 75.5% / 76.5% / 74.0%.
- Table 4: GPT-4V with 3-shot reaches 32.8% avg (still −27 pp vs ST-VLM); adding geometric context (extrinsics+depth) *degrades* GPT-4V (31.0%).
- Table 5 (paraphrased questions): ST-VLM 58.2% avg vs GPT-4o 27.0%, GPT-4V 27.3%, LLaVA-OneVision 27.1% — not template overfitting.
- Table 6 (data ablation): no tuning 27.9% → labeled data only 51.1% → +pseudo-labels 59.8% (pseudo-labels add +8.7 pp — the paper's evidence the MonST3R pipeline is worth it).
- Table 7: ST-VLM avg 65.6 vs LLaVA-OneVision 62.9 on general video benchmarks (+2.7 pp); beats 32B LLaVA-N-Video (65.1) on average.
- §6.2 generalization (read from full text): PerceptionTest +7.4% over baseline (physical-property comprehension); ActivityNet temporal grounding R@0.3 +17.0% mIoU/R@0.3 gains; Charades-STA improved mIoU/R@0.3; DramaQA region-aware spatial VideoQA +4.6% accuracy; TVQA+ improved on both spatial and temporal grounding.
- §6.3 emerging multi-step reasoning (qualitative, Fig. 7): airplane-speed question answered 36.58× slower than a normal plane (vs LLaVA-OneVision's 10×); faster-player identification by jersey + speed estimation — correct where baseline fails. Combines kinematic estimates with LLM knowledge/arithmetic without explicit training.
- My read: the per-task absolute numbers (32–49% on single-object tasks) show the capability is real but still crude — comparisons (74–76%) are easy, precise distance/direction estimation is not.

## 9. Leakage & limitations
- STKit-Bench is generated by the same trajectory machinery as the training data (NuPlan is held out as a dataset but not as a pipeline) — train/bench pipeline overlap inflates the headline 59.8%.
- GPT-4 used to extract numeric answers from free-text responses — extraction errors become model errors for baselines.
- Movement direction excluded for sports (complex trajectories) — the one task family most relevant to NFL (player direction changes) is the one they dodge.
- Ego-Exo4D sports videos are egocentric AR footage, not broadcast — no broadcast-sports evaluation.
- 400 s/video pseudo-labeling cost on A6000 makes scaling expensive; the 89K pseudo-labels required ~170 GPU-days.
- Absolute errors remain large (MAE 25.1 m distance, 11.6 km/h speed) — fine for "which player is faster" but not for measurement-grade analytics.
- External validity to NFL: the QA format transfers (distance/speed/direction questions over trajectories), but NGS tracking already gives exact answers deterministically — a VLM guessing them from pixels is strictly worse than computing them from tracking data.

## 10. GSE overlap
Extension, not duplicate. GSE has no VLM lane and no instruction-tuning work. The overlap is conceptual: GSE's NGS taxonomy (2026-09-21, 27 families) *is* the kinematic ground truth (top speed, distance traveled, acceleration) that this paper tries to make VLMs estimate from pixels. The portable idea: turn GSE's existing nflverse/NGS tables into a kinematic QA instruction dataset (e.g., "How far did Player X travel on this play? What was his top speed? Which defender closed faster?") to fine-tune an analyst copilot — the text-QA analog of STKit, with exact ground truth for free. Relevant docs: NGS metric glossary (Beexly/Sports commits f6b67f2, 6c89cba), `2026-09-18-ml-research-brief.md` (multimodal fusion / frontier-model techniques areas — results pending, so no conflict).

## 11. GSE implementation spec
Skip the VLM. Build **GSE-KinQA**: (1) from nflverse 2020–2025 + NGS-style tracking (or gse-lab tables), generate template QA pairs for every play: traveled distance (sum of frame displacements), max speed, direction-change count, pairwise comparisons (which receiver reached higher top speed), direction-at-snap questions; (2) format as instruction-tuning JSONL (~100–200K pairs, deterministic ground truth — zero labeling cost); (3) fine-tune a small open LLM (Llama 3.1 8B, already in TASK-012's stack) on it for 1–3 epochs; (4) use as the knowledge-grounded analyst assistant for the GSE content desk ("how fast was Worthy's top speed on that TD" answered from data, not vibes). Effort: 1–2 weeks for the QA generator; fine-tune cost modest. This directly inverts the paper: instead of teaching a VLM to *guess* kinematics from pixels, teach an LLM to *answer* kinematics questions from GSE's exact data.

## 12. Reproducible test
Generate 5,000 KinQA pairs from the 2024 season (held-out from training), ask the fine-tuned model distance/speed/comparison questions in paraphrased form (per the paper's Table 5 robustness protocol), extract numeric answers with the same ±25% accuracy rule the paper uses. Baseline: the base Llama 3.1 8B without KinQA tuning (expect ~25–30% per the paper's base-model levels).

## 13. Acceptance / rejection gate
ADOPT the KinQA-tuned assistant for GSE content work only if it reaches ≥55% accuracy on the 5,000-pair held-out set with paraphrased questions (matching the paper's 58.2% paraphrased level) AND ≥95% on comparison questions; otherwise REJECT — a hallucinating kinematics assistant is worse than none.

## 14. Improvement experiment
The paper's pseudo-labeling exists because driving/sports videos lack 3D labels; GSE has the opposite luxury — exact tracking labels. Exploit it: train the model on *multi-step* kinematic reasoning chains (paper's Fig. 7 direction) that the paper only shows qualitatively, e.g., "Given Player X's route distance and top speed, and the defender's closing speed, was the separation at catch point above the league-average NGS separation for this route type?" — with each reasoning step grounded in a computed quantity. Test whether chain-supervised training beats answer-only training on a held-out multi-step set; the paper hypothesizes emergence but never measures it.
