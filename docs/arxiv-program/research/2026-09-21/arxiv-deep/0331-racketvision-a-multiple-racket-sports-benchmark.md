# [0331] RacketVision: A Multiple Racket Sports Benchmark for Unified Ball and Racket Analysis (arXiv:2511.17045v3)

**Citation:** Linfeng Dong, Yuchen Yang, Hao Wu, Wei Wang, Yuenan Hou, Zhihang Zhong, and Xiao Sun (2026). *RacketVision: A Multiple Racket Sports Benchmark for Unified Ball and Racket Analysis*. arXiv:2511.17045v3. URL: https://arxiv.org/abs/2511.17045v3
**Ledger completed:** 2026-09-21. **Read:** full text (PDF text extract, 564 lines + references).
**Verdict:** REJECT — table tennis/tennis/badminton benchmark with no GSE product lane and no NFL data transfer; the only portable lesson (cross-attention > naive concat for event-conditioned fusion) is a general method note, not an adoption.

## 1. Research question
Can a single unified benchmark spanning three racket sports (table tennis, tennis, badminton) advance computer vision for sports analytics across three interconnected tasks — fine-grained ball tracking, articulated racket pose estimation, and predictive ball trajectory forecasting — and, critically, does multi-sport training help, and can racket pose information improve trajectory prediction under the right multi-modal fusion architecture?

## 2. Dataset / schema
- **RacketVision** (new dataset): **1,672 video clips, 435,179 frames, 12,755 seconds** from 942 top-level professional game broadcasts on YouTube. Per sport: table tennis 50 games / 780 clips / 170,027 frames / 3,878 s / 19,495 ball annotations / 6,648 racket annotations; tennis 431 / 431 / 150,399 / 4,285 / 21,544 / 7,395; badminton 461 / 461 / 114,753 / 4,592 / 23,003 / 10,578. Totals: 64,042 ball + 24,621 racket annotations, 1080p.
- Clips are 5–10 s segments with the ball actively in play; sparse annotation (20% of frames per clip sampled): ball = position point + visibility flag; racket = bounding box + 5 keypoints (top, bottom, handle, left, right). A per-clip median frame is provided as a background reference. Annotations at pixel level.
- Trajectory-prediction training data is generated by the pipeline itself: trained ball tracker + racket pose estimator run on full clips to produce dense per-frame "soft labels," segmented into history/future segments.

## 3. Method / model
Three tasks, all benchmarked with established baselines (no novel model proposed — the dataset and the fusion findings are the contribution):
1. **Ball tracking**: single-frame and multi-frame (5 preceding frames) settings; baselines RTMDet, YOLO11, WASB (background modeling), TrackNetV3 (heatmap-based), in single-sport (SS) and multi-sport (MS) training.
2. **Racket pose estimation**: top-down baseline, RTMDet detector + RTMPose keypoint model, SS and MS settings.
3. **Ball trajectory prediction**: backbones LSTM (2-layer) and Transformer (4-layer encoder-only); three input/fusion settings — Ball-Only (unimodal baseline), Concat Fusion (ball + 5-keypoint racket pose embeddings concatenated along feature dim), Cross-Attention Fusion (ball trajectory sequence as Query; racket pose sequence as Key/Value). Short setting: N=20 history, M=5 future; long setting: N=80 history, M=20 future.

## 4. Equations & assumptions
No equations stated. Task definitions only: ball tracking predicts `(xt, yt) ∈ R²` and visibility `vt ∈ {0,1}`; pose estimation predicts bbox `(xmin, ymin, xmax, ymax) ∈ R⁴` and 5 keypoints `{(xi, yi)}⁵_{i=1} ∈ R¹⁰`; trajectory prediction maps history `RN×2` (ball-only) or `RN×(2+10)` (ball+racket) to future `RM×2`. Metrics named but not formalized: Precision, Recall, MDE, mAP@50, PCK@0.2, MPJPE, mOKS, NME, ADE, FDE.

## 5. Features / target
- Ball tracking: input RGB frame(s) (+ optional median background frame); target = ball pixel coordinates + visibility flag.
- Racket pose: input single RGB frame; target = racket bbox + 5 keypoints (top, bottom, handle, left, right).
- Trajectory prediction: input = history of ball positions (N=20 or 80) optionally plus 5-keypoint racket pose history; target = ball positions over next M=5 or 20 frames. Metrics in pixels at 1920×1080.

## 6. Validation design
Fixed train/test splits per sport (exact split sizes not stated in the extracted text). Baselines compared across model × (single vs. multi-sport) × (background modeling on/off) × (frame count) for tracking; model × (single vs. multi-sport) for pose; backbone × fusion for trajectory. No time-ordered or cross-broadcast validation described; no confidence intervals; soft-label pipeline means the trajectory task's training inputs are model predictions, not ground truth.

## 7. Numerical results / baselines
Ball tracking (Table 3; best MS-TrackNetV3 with background modeling, 4 frames): table tennis Prec 0.924 / Rec 0.762 / MDE 3.41 px / mAP 71.1; tennis Prec 0.945 / Rec 0.880 / MDE 1.96 / mAP 81.9; badminton Prec 0.915 / Rec 0.865 / MDE 1.54 / mAP 83.1. Multi-sport gains: mAP +19.2% tennis (81.9 vs 68.7 single-sport), +14.6% badminton (83.1 vs 72.5); single-sport retains slight edge in tennis precision (0.962 vs 0.945) and MDE (1.66 vs 1.96). Background modeling cuts MDE 54.0% (table tennis), 61.4% (tennis), 54.8% (badminton) for TrackNetV3 single-frame. Multi-frame (#F=4) improves recall/mAP but slightly worsens MDE vs single-frame in tennis (1.96 vs 1.70).
Racket pose (Table 4, RTMPose): multi-sport PCK@0.2 — table tennis 81.8 (vs 75.6 SS, +6.17%), tennis 89.6 (vs 83.7, +5.97%... text states improvements of 6.17%, 6.36%, 5.97% for table tennis, badminton, tennis; tennis reaches 89.69% in text), badminton 88.5 with best MPJPE 5.00 px and mOKS 0.668. Per-keypoint PCK (Table 5): top/bottom/handle ≥92.6–99.7%; side keypoints (left/right) 64.8–80.1% (occlusion by grip, motion blur).
Trajectory prediction (Table 6): **naive concat fusion consistently underperforms the ball-only baseline** across both backbones and all sports. Cross-Attention LSTM is best overall. Long-horizon (pixels, ADE/FDE): tennis ball-only 62.5/108.7 → concat 76.8/125.0 → cross-attn **55.5/94.7**; table tennis ball-only 113.9/184.3 → concat 139.9/198.9 → cross-attn **101.3/161.3**; badminton ball-only 118.7/194.7 → concat 134.5/203.3 → cross-attn **114.6/187.6**. Short badminton: ball-only ADE 37.5 → cross-attn 37.0 (small gain — many samples are mid-flight with no racket interaction, where the model correctly learns to ignore the modality). Cross-attention excels at hit/turning-point frames (qualitative Figure 6).

## 9. Leakage & limitations
- **Soft-label training loop**: the trajectory predictor is trained on dense predictions from the paper's own tracker/pose estimator, not human labels — systematic perception errors propagate into the "ground truth" of the prediction task, and the reported gains are partly measured on that loop's own outputs.
- **Sparse (20%) human annotation** with no reported inter-annotator agreement; YouTube broadcast footage with compression artifacts and camera cuts.
- **No transfer evidence**: all results in-domain on the three racket sports; pixel-space metrics (not metric-space) limit comparability.
- **Event sparsity caveat** (authors' own): most trajectory samples contain no racket interaction, so the headline fusion gains are concentrated at rare hit frames; average ADE/FDE improvements are modest.
- **External validity to NFL**: zero — no football data, no shared sensor modality path, no product lane (Garrett's scope is NFL/NCAA; tennis/badminton/table tennis have no revenue or content lane).

## 11. GSE implementation spec
No implementation — REJECT. Nothing in the dataset or the three task pipelines is adopted. The one method note worth filing (not building): if GSE ever fuses an event-conditioned auxiliary modality into a trajectory or pass model (e.g., defender pose at the catch point into a separation model), use cross-attention-style selective fusion rather than feature concatenation — the paper's consistent concat-degradation result is the evidence. That is a 2-sentence design note, not a project.

## 12. Reproducible test
Not applicable — REJECT. No GSE dataset or baseline exists for racket-sport ball tracking, and creating one serves no GSE lane.

## 13. Acceptance / rejection gate
**Rejected.** The acceptance criterion would have been: a transferable artifact (dataset, model, or method) that improves an existing GSE tracking/ngs lane on NFL data within a bounded test. RacketVision offers none: the dataset is racket-sport broadcast video (no NFL applicability), the baselines are standard (RTMDet/YOLO11/TrackNetV3/RTMPose), and the single novel finding (fusion architecture matters) is a design heuristic already consistent with standard practice. Gate outcome: file the fusion heuristic in the NGS-replacement notes, adopt nothing.

## 14. Improvement experiment
If the fusion insight were ever tested in GSE's world: take the NGS-replacement route-prediction stack and condition a receiver-trajectory forecaster on defender-pose "event frames" (press contact, break point) using the paper's Query=trajectory / Key-Value=pose cross-attention pattern, vs. a concat-fusion baseline and a trajectory-only baseline, evaluated on separation-at-target metrics from NFL tracking data. The hypothesis, imported from this paper, is that concat fusion will degrade vs. the unimodal baseline while cross-attention improves at event frames — a cheap experiment that would validate or kill the transferred lesson on football data.
