# [1846] Large Language Models for Automated Data Science: Introducing CAAFE for Context-Aware Automated Feature Engineering (arXiv:2305.03403)

**Citation:** Noah Hollmann, Samuel Müller, Frank Hutter (2023). *Large Language Models for Automated Data Science: Introducing CAAFE for Context-Aware Automated Feature Engineering*. arXiv:2305.03403v5. University of Freiburg / Prior Labs. NeurIPS 2023. URL: https://arxiv.org/abs/2305.03403
**Ledger completed:** 2026-09-22. **Read:** full text (arXiv PDF, v5, lines 0–1800, all 6 main sections, Tables 1–6, Figures 1–20, Appendices B–G incl. broader-impact/bias analysis, full prompt, semantic-blinding ablation, per-dataset results, compute appendix, dataset collection details — verified complete 2026-09-22).
**Verdict:** ADAPT

Rationale: GSE's LLM-assisted analysts already propose features by hand; CAAFE gives the exact protocol to automate that (context prompt → code-generating LLM → validation-gated keep/reject) with per-feature natural-language usefulness explanations. Adopt as the semantic layer *over* the OneBM relational engine (1845), not as a replacement for numeric search.

## 1. Research question
Can LLMs inject domain knowledge into AutoML feature engineering? Traditional AutoML (model selection/training/scoring ≈ 23% of a data scientist's time) leaves data engineering and domain-knowledge integration to humans. CAAFE (Context-Aware Automated Feature Engineering) uses an LLM as a code generator: given a dataset description + feature names/dtypes/missingness/10 sample rows, it iteratively proposes pandas code that adds semantically meaningful features, executes it, and keeps the feature only if cross-validated performance improves. Bridges LLM semantic knowledge and classical ML robustness via code as the interface. Also directly benchmarked against the lane's anchor methods (DFS = 1845's predecessor, AutoFeat = 1844).

## 2. Dataset / schema
14 tabular classification datasets, ≤ 2,000 samples each (feature engineering matters most at small N): 10 OpenML (airlines, balance-scale [R], breast-w, cmc, credit-g, diabetes, eucalyptus, jungle-chess, pc1, tic-tac-toe [R]; [R] = reduced training size because TabPFN hit AUC 1.0 by default) + 4 post-Sept-2021 Kaggle datasets web-crawlers likely missed (health-insurance, pharyngitis, kidney-stone, spaceship-titanic). Dataset descriptions web-crawled text associated with the public datasets. 50/50 train/test splits, 5 repetitions with different seeds (Bouthillier et al. 2021 variance control). Time: datasets span decades; paper 2023.

## 3. Method / model
**Loop (Fig. 1):** input (D_train, D_valid, dataset description) → construct prompt → LLM generates pandas code block adding exactly one useful column (plus optional drops of redundant columns) → execute on current frames → fit classifier on D'_train, evaluate on D'_valid (10 random validation splits; keep iff mean(Δaccuracy, ΔROC AUC) > 0) → repeat 10 iterations.
**Prompt (Fig. 5, Appendix D):** (A) user dataset description with context, (B) feature names (semantic anchors), (C) dtypes, (D) missing-value %, (E) 10 sample rows; code-format template requiring "# Feature name", "# Usefulness:" (why this adds real-world knowledge for predicting the target), "# Input samples:" (3 values of used columns); Chain-of-Thought instructions (Wei et al. 2023); one worked example. Evaluation metric in prompt: accuracy on a holdout.
**Execution safety:** parse syntax, whitelist allowed pandas operations (imports and arbitrary calls excluded); error feedback loop — execution errors are fed back into the next iteration's prompt, and CAAFE recovered from all errors (52 faulty features / 7.4% over 14 datasets × 5 splits × 10 iterations).
**LLMs:** GPT-4 and GPT-3.5 (Sept 2021 knowledge cutoff). Evaluation classifier for keep/reject: TabPFN (Hollmann et al. 2022); final eval also on logistic regression, random forest, ASKL2.0, AutoGluon.
**Comparison protocol:** DFS ("add_numeric", "multiply_numeric" primitives), AutoFeat (1 step), FETCH — each alone and CAAFE-first-then-classical.

## 4. Equations & assumptions
No equations stated (systems/methods paper). Named statistics: mean ROC AUC / accuracy over 5 seeded 50/50 splits; mean(ΔACC, ΔROC AUC) > 0 as keep criterion. Assumptions (stated): descriptive feature names carry usable semantics (numbered-feature datasets excluded); web-crawled dataset descriptions are adequate context (authors note user-supplied descriptions would be better); the LLM's Sept 2021 cutoff risks benchmark memorization — mitigated by the 4 post-cutoff Kaggle datasets; the keep criterion is *not* a statistical test (authors flag this as a limitation); semantics-blind generation is the proper ablation of their core claim.

## 5. Features / target
Inputs: raw tabular features with descriptive names. Generated features (Table 3 examples): combinations (fever∧rhinorrhea from symptom co-occurrence knowledge), ordinal binning (Age → AgeGroup Child/Teen/YoungAdult/Adult/Senior on Spaceship Titanic), string parsing (Cabin "F/356/S" → Deck + CabinSide), physics knowledge (balance-scale: left_weight×left_distance = left_moment; right_moment; moment_difference — then *dropping* the four raw columns), missing-aware string extraction with error recovery (Health Insurance Age_difference with fillna(0)). Targets: 14 binary/multi-class labels (ROC AUC OVO), one per dataset. No time horizon (static tabular).

## 6. Validation design
5 seeded 50/50 train/test splits per dataset; same splits for all methods; 10 random validation splits per keep/reject decision (mean ΔACC/ΔROC AUC > 0). LLM-memorization control: post-Sept-2021 Kaggle datasets "improved by CAAFE in all cases" per authors. Semantic-blinding ablation (Appendix E.1): hide feature names + dataset description → GPT-4 CAAFE drops from mean AUROC 0.822 to 0.800. No significance tests.
Appendix F (compute): average CAAFE run = 4:43 min per dataset (GPT-4, 10 iterations; code generation dominates); GPT-3.5 cuts time to ~1/4 and cost to ~1/10. Eval hardware: one RTX 2080 Ti + 8× Xeon Gold 6242 @ 2.80GHz. Appendix G.1 (dataset curation): OpenML sets restricted to those with descriptive feature names; datasets with >20 features dropped (GPT-4 8192-token prompt limit); sets perfectly solvable by TabPFN alone subsampled to 10–20% (balancescale 20%, breastw/tictactoe 10%); focus on ≤2000 samples since FE matters most on small data; 4 Kaggle sets released after the LLM knowledge cutoff; rows with missing values dropped. Appendix E.2 (Table 5 per-dataset ROC AUC OVO): biggest GPT-4 gains on tictactoe (0.6989→0.9536) and jungle_chess (0.9334→0.9453); GPT-4+AutoFeat and GPT-4+DFS combos best on several sets (e.g. jungle_chess 0.9535, spaceshiptitanic 0.853). Appendix E.3: all generated prompts and code published in the repo data/generated_code folder.

## 7. Numerical results / baselines
- TabPFN mean ROC AUC across 14 datasets (Table 2): No FE 0.798 → CAAFE(GPT-3.5) 0.806 → **CAAFE(GPT-4) 0.822**; mean rank 13.9 → 12.9 → **9.78**. Improvement on 11/14 datasets.
- Scale of the gain: the +0.024 jump is 71% of the improvement from switching logistic regression (0.749) to random forest (0.783).
- Baselines (TabPFN column, mean AUC): DFS 0.791, AutoFeat 0.796, FETCH 0.796, OpenFE 0.798 — all below CAAFE(GPT-4) 0.822; classical AutoFE does *not* further improve TabPFN after CAAFE (but does help weaker classifiers: LR 0.769→ higher, RF 0.803).
- GPT-3.5 vs GPT-4: 3.5 improves only 6/14 datasets — model quality is load-bearing.
- Tic-tac-toe worked example: ROC AUC 0.888 → 0.987 → 1.000 in two iterations.
- Cost: 4 min 43 s per dataset; 90% of time in LLM code generation; 7.4% faulty-code rate, all recovered via error feedback. (Appendix F cost/time tradeoff plots paged; exact dollar figures not extracted.)

## 9. Leakage & limitations
Adversarial read: (a) The LLM proposes features from *names* — a feature named e.g. "spread_close" can leak through semantic guesswork (LLM knows what predicts covers and will happily build post-outcome proxies); CAAFE has no cutoff/timestamp discipline — the exact weakness OneBM (1845) solves. (b) The keep criterion is mean(ΔACC, ΔROC AUC) > 0 over 10 validation splits with *no statistical test* (authors' own admission) — with 10 iterations and noisy validation on small N, selection bias is real. (c) Validation and test share the same 50/50 split discipline, but feature *selection* used the validation side repeatedly — mild overfit to validation baked in. (d) Web-crawled dataset descriptions = memorization risk handled only partially by 4 post-cutoff datasets. (e) GPT-3.5's 6/14 shows the method is hostage to frontier-model quality (2023-era pricing; 4:43/dataset × 14 is trivial, but NFL-scale tables with hundreds of features risk the "very large prompts" limitation the authors flag). (f) Bias: the doctor/nurse fake-dataset demo (Appendix B.2) shows GPT-4 inventing gendered features with a straight face — for GSE the analog is the LLM "knowing" market narratives (e.g. "cold-weather QB") and proposing story-driven features that are noise. (g) Whitelist security is admittedly partial (infinite loops/list comprehensions not excluded).

## 11. GSE implementation spec
Build "GSE-CAAFE" as the semantic layer atop the OneBM relational engine (1845): (1) Context document: curated schema description of every nflverse/odds table (column names, dtypes, semantics, *cutoff semantics* — explicitly stating "no column may use post-kickoff information", correcting CAAFE's missing leakage discipline with OneBM's rule). (2) Candidate generation: LLM proposes ≤ 20 features/week as pandas code against the relational tables, each with a Usefulness comment; proposals restricted to pre-kickoff columns by an allowlist filter (not the paper's permissive prompt). (3) Execution: sandboxed run (whitelist + row-count cap), keep iff validation (2023 season) log-loss improves with DeLong-style paired test p < 0.05 (correcting the paper's no-significance-test weakness) AND the leakage audit (kickoff-cutoff replay) passes. (4) Human-in-the-loop: analysts review each kept feature's Usefulness comment in a weekly queue; veto = drop. Effort: ~3–4 days (prompt + harness + audit plumbing).

## 12. Reproducible test
Dataset: nflverse 2020–2024 + odds snapshots; kickoff cutoffs enforced. Protocol: 10 CAAFE iterations per week for 8 weeks on 2020–2022 train / 2023 validation; kept features frozen; evaluate LightGBM baseline vs baseline + CAAFE features on held-out 2024 (log-loss). Controls: (a) semantic-blinding ablation — same loop with column names hashed (paper's 0.822→0.800 drop is the reference: if blinding doesn't hurt, the LLM added nothing semantic and the run is noise); (b) proposal-source audit — each kept feature tagged LLM-proposed vs analyst-proposed to measure the marginal value of the machine.

## 13. Acceptance / rejection gate
ADAPT the layer iff (a) 2024 held-out log-loss improves ≥ 0.003, AND (b) semantic-blinding ablation shows ≥ 0.002 of that gain is attributable to semantics (LLM > hashed-name run — else it's just random search), AND (c) zero leakage-audit failures across all kept features. REJECT if any kept feature fails cutoff replay, if the blinding ablation matches the semantic run, or if > 30% of proposals are faulty code (harness too brittle). Budget cap: ≤ $50/month LLM spend or the layer is re-scoped.

## 14. Improvement experiment
Beyond the paper: close CAAFE's two admitted weaknesses simultaneously. (1) Replace the keep criterion with a sequential test: keep iff validation gain survives a paired permutation test with Holm correction across the 10 iterations (controls the paper's selection bias). (2) Inject OneBM-style (1845) cutoff metadata into the prompt as hard constraints with a *pre-execution* static check: parse the generated AST and reject any column reference not in the pre-kickoff allowlist before running (cheaper and safer than the paper's execute-then-evaluate). Hypothesis: the same 11/14-style hit rate with half the wasted iterations and a leakage-proof guarantee the paper lacks. Second experiment: feed the LLM the *drift-quarantine list* from ledger 1845 as negative context ("these features' distributions shifted in 2020/2024 — do not build on them without a regime interaction") — tests whether semantic context can fix the regime-break problem numeric search can't see.
