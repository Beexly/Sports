## 1. Research question
Is explicit temporal coupling (deformation fields, canonical templates, spacetime factorizations) actually necessary for dynamic-scene novel view synthesis under synchronized multi-view capture, or does geometry alone suffice? The paper argues that in a synchronized, calibrated multi-view setting typical of sports (fixed, temporally synchronized cameras), the scene at each time step is already strongly geometrically constrained (multiview rigidity in projective geometry), so a warm-start 3D Gaussian Splatting pipeline — initialize frame t from the converged Gaussians of frame t−1, optimize per frame with a fixed Gaussian budget and no densification — achieves efficient, memory-predictable retrospective NVS without temporal deformation constraints. Complementing the method, it introduces a Blender-based standardized dynamic multi-view dataset framework that generates parameterized synchronized camera rigs and training-ready exports in consistent formats, eliminating the coordinate-convention fragmentation that plagues dynamic NVS benchmarking.

## 2. Dataset / schema
All synthetic, generated with the paper's Blender 4.0 API (consistent with the setup of [57], TACV):
- **D-WS (Dancing-Walking-Standing):** three dynamic subjects (dancing, walking, standing); 65 time instances × 100 calibrated camera viewpoints. Per time step: 95 train / 1 validation / 4 test views (cameras 0, 30, 60, 90 as test). 6,175 train / 65 val / 260 test images total.
- **S-PK (Soccer Penalty Kick):** two subjects simulating a penalty kick; 109 time instances × 60 views; 55 train / 1 val / 4 test per frame (cameras 21, 37, 40, 56 test). 5,995 / 109 / 436 images.
- **S-MP (Soccer Multiplayer):** three subjects, coordinated soccer actions; 83 time instances × 60 views; 55/1/4 split (cameras 21, 37, 40, 56 test). 4,565 / 83 / 332 images.
- **Weather soccer fields:** Cloudy / Snow / Sunny SoccerField; 120 time instances × 60 views; 58 train / 2 test per step; 6,960 train / 240 test images at 1920×1080. Reconstructed with an A/B static-dynamic decomposition (see §3).
- Splits are deterministically assigned by camera name/suffix, invariant over time when the same camera set is reused. Access: generated by the paper's released Blender API ("Code, API, and Datasets can be accessed from their respective links" — links stated in paper but URLs not recoverable from PDF extraction; see §8).

## 3. Method / model
**(i) Time-indexed fixed-size 3D Gaussian representation.** Scene at time t = set of K anisotropic 3D Gaussians G_t = {g_{t,k}}; each parameterized by mean μ_{t,k} ∈ R³, covariance Σ_{t,k} ∈ R^{3×3} = R(q_{t,k}) diag(s_{t,k}²) R(q_{t,k})ᵀ (unit quaternion q, per-axis scales s), opacity α_{t,k} ∈ (0,1), and view-dependent color via spherical-harmonics coefficients b_{t,k}. Full event stored as A = {G_1,…,G_T} for random-access retrospective rendering. Densification DISABLED: ‖G_t‖ = K for all t → predictable memory, archive size, rendering throughput.
**(ii) Differentiable rasterization:** standard 3DGS — transform to camera coords μ̃ = R_i μ + t_i; project u = Π(K_i μ̃); 2D covariance Σ_2D = J R_i Σ R_iᵀ Jᵀ (J = projection Jacobian); kernel G(p) = exp(−½(p−u)ᵀ Σ_2D^{−1} (p−u)); per-pixel alpha α(p) = α·G(p); depth-sort and front-to-back composite Î(p) = Σ_k c_k α_k(p) Π_{j<k}(1−α_j(p)); color c = Σ_m b_m Y_m(d) (SH basis, normalized view direction d).
**(iii) Per-time-step optimization, no temporal deformation.** Objective per frame: L_t(Θ_t) = Σ_i L_img(Θ_t; I_t^{(i)}) + λ_reg R(Θ_t), with L_img = robust photometric loss (ℓ1/Charbonnier, optionally SSIM) and lightweight regularizer R(Θ_t) = Σ_k (‖s_{t,k}‖² + α_{t,k}² + ‖b_{t,k}‖²) plus clamping of s to a valid interval. "We do not introduce any explicit temporal deformation model or canonical-time constraint into Eq. (15)."
**(iv) Warm-chain training across time.** SfM-derived point cloud only at start time t₀ (P_{t0} = {p_k ∈ R³}_{k=1}^K; init μ←p_k, s←s₀, q←q₀, α←α₀; appearance via median color aggregation into SH DC term, higher orders zero). Forward warm chain: Θ_t^{(0)} ← Θ*_{t−1} for t = t₀+1…T (or backward Θ_t^{(0)} ← Θ*_{t+1}); fixed iteration budget per frame; archive Θ*_t. Warm start is initialization ONLY — no temporal constraint. Algorithm 1 pseudocode in paper.
**(v) Blender dataset API:** parameterized rig synthesis (hemisphere, full sphere, ellipse, stadium layout: ring + tiled cameras + optional goal-line viewpoints); OpenCV/COLMAP world-to-camera convention via explicit axis conversion; top-left image origin; export compatibility with Instant-NGP, NeRF Synthetic, TACV, COLMAP poses; three depth/point-cloud modes (COLMAP+surface, COLMAP+depth, depth-only). For the weather datasets, an A/B static-dynamic decomposition: static stadium A reconstructed once, dynamic players B per frame via residual masks (RGB differencing vs. A-only rendering + thresholding + morphological refinement, multi-view voting to retain consistently supported Gaussians, optional AABB boundary smoothing), merged at render time.

## 5. Features / target
Input features: calibrated synchronized multi-view RGB images {I_t^{(i)}} + camera parameters {π_i} + SfM point cloud at t₀. Target: photometric reconstruction — novel-view images Î*_t rendered from arbitrary query viewpoint π* at query time t, evaluated by PSNR and LPIPS against held-out test cameras. No classification/regression target; the "model" is the per-frame Gaussian parameter set Θ_t = {μ, Σ, α, b}. No learned priors beyond SH color basis; no neural network training (direct parameter optimization via differentiable rasterization).

## 6. Validation design
- Controlled benchmark: same dataset construction, camera setup, and deterministic camera-name train/val/test splits across all methods (the paper's core reproducibility contribution); split fixed across all time steps.
- Baselines compared (Table 1): dynamic NeRF methods — D-NeRF, T-4D (Tensor4D), HexPlane (HP), K-Planes (KP), StreamRF (S-RF), TACV; dynamic 3DGS — D-3DGS (Dynamic 3D Gaussians), 4DGS, ST-GS (spacetime Gaussian). All initialized with the same 100,000 points at the first time step (benchmark suite) / ground-truth point cloud from the Blender exporter (evaluation protocol); 8,000 iterations per frame for the benchmark methods vs. 8k for TA-3DGS.
- Metrics: PSNR ↑, LPIPS ↓ on test views; memory footprint; total train time; iterations.
- Ablations (§5.2): S1 (Warm+Densify) vs. S2 (Warm+NoDensify, the proposed) vs. S3 (GT point-cloud re-init every frame — impractical reference) on the Snow SoccerField; quality-vs-capacity analysis over 5 and 15 frames.
- No statistical significance testing reported; no cross-validation (fixed camera splits); synthetic-only evaluation — no real-world capture validation. Splits are by camera (viewpoint), not by time — train/val/test cameras fixed across all T (temporal generalization is the method's claim but is not tested with held-out times; every time step is optimized, so there is no temporal test set).

## 9. Leakage & limitations
Adversarial reading: (1) **Synthetic-only** — all four datasets are Blender renders; no real stadium capture, no calibration noise, no rolling shutter, no crowd/occlusion dynamics of real sports. (2) The central claim (no temporal coupling needed) holds only under the paper's own strong capture assumptions — calibrated, synchronized, static rigs; real sports broadcasts use moving/zooming cameras, explicitly excluded ("not directly addressed"). (3) Calibration errors accumulate over time via the warm chain (paper's own §5.3: "small errors in intrinsics, extrinsics, rolling-shutter effects, or subframe asynchronization … can lead to accumulation of error over time due to warm-chain setting"). (4) No temporal test set — every time step is optimized, so "retrospective NVS" is evaluated only on held-out viewpoints, never held-out times; temporal generalization is assumed, not measured. (5) Fixed Gaussian budget is a double-edged sword: S2's quality trails the densifying variant (Table 4) and cannot recover geometry missing from a bad t₀ init (reflections, textureless surfaces, limited baseline). (6) Compute: A40 50GB / H100-class hardware, hours of training per sequence — far beyond GSE's lab budget for a content toy. (7) No statistical testing; baselines run at the authors' chosen iteration budgets (8k/frame for all, but convergence behavior across methods isn't equalized). (8) For GSE specifically: even if the method worked, its output is AI-synthesized video — the standing GSE video rule (2026-09-15 HARD, plus 2026-09-10 memory entries) forbids AI-generated video as a substitute for real footage in the content operation; the only compliant use (telestrated analysis overlays) doesn't need NVS. (9) Data-access block: GSE has no source of calibrated synchronized multi-view NFL footage; NFL broadcast feeds are single-camera, moving/zooming, uncalibrated.
