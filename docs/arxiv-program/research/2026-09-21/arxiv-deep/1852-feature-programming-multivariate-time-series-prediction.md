# [1852] Feature Programming for Multivariate Time Series Prediction (arXiv:2306.06252)

**Citation:** Alex Reneau, Jerry Yao-Chieh Hu, Chenwei Xu, Weijian Li, Ammar Gilani, Han Liu (2023). *Feature Programming for Multivariate Time Series Prediction*. arXiv:2306.06252v1. URL: https://arxiv.org/abs/2306.06252
**Ledger completed:** 2026-09-22. **Read:** full text (PDF, lines 0–2947, main body, references, all appendices — A related works, B theory background, C proofs, D experimental details, E additional experiments).
**Verdict:** ADAPT

Rationale: the operator hierarchy and customization template are a principled, hyperparameter-free rolling-feature schema worth porting to GSE's sports panels, but the paper's missing pruning stage and weak 80/20 evaluation hygiene require adaptation before production use.

## 1. Research question
Can a physics-motivated, programmable framework — modeling a multivariate time series as increments governed by "spin-gas" Glauber dynamics and letting the model's derivative structure dictate the feature operators — systematically generate time-series features that improve forecasting across models, without search, LLMs, or training in the loop?

## 2. Dataset / schema
Four supervised regression sets, all 80/20 train/test: Synthetic (derived from Taxi, replacing basic features with a zero/first/second-order mix), Taxi (NYC TLC trip records, 1000 locations, 30-min intervals, forecast next 30-min), Electricity (UCI load diagrams, 370 customers, hourly, forecast next hour), Traffic (UCI PEM-SF occupancy, 440 Bay Area highways, hourly, forecast next hour). Noisiness via Temporal SNR: Synthetic 1.60, Taxi 1.27, Electricity 2.98, Traffic 1.32 — Taxi is the noisiest and shows the largest gains. Downstream models: MLP, CNN, LSTM (main text); XGBoost, LightGBM, Transformer, TFT, TCN, N-BEATS (appendix, via DART). All datasets public.

## 3. Method / model
Three operators extracted from the theory: Difference[series1, series2] (first smooth, then subtract; the order-raising building block), Window[series, lookback] (max/min/mean over a fixed lookback, multiple resolutions), Shift[series, Δτ] (arbitrary time displacement). Feature template: three lists (0th/1st/2nd order), each = raw basic features ∪ discretionary handcrafted features; the template is the user-bias injection point. Operation module: pre-programmed operator combinations + a computation flow — solid arrows = within-order generation; dashed arrows = order-to-order upgrade flow (difference of 0th→1st, difference of 1st→2nd); Window and Shift create summary features *without* changing order. Between orders, the extended features of order k−1 feed the template of order k. Generation is deterministic and hyperparameter-free: the program (template + module) fully determines the extended feature set; no search, no LLM, no training in the loop. Default program (D.1): K = 45 extended features per dataset; basic format (N,1,T), extended (N,K,T); 0th order = smoothing windows lookback [7,25]; 1st/2nd order = window/difference/shift lookback [7,25]. Theorem 5.1 is presented as the first theoretically grounded automated feature generation method for time series.

## 4. Equations & assumptions
- Fine-grained model: X_{t+Δt} = X_t + c·Σ σ_{t+lδt} — each increment is a Markovian "coin toss" under spin-gas Glauber dynamics (3.2) with effective local field Γ_{i,t} = Σ_j J_{ij}(t)σ_{j,t} + h_i(t) + g_i(p, a), where the gas-like term g injects momentum p and acceleration a. Coarse-grained back to continuous time via a path-integral/coarse-graining construction.
- Theorem 5.1 + Corollaries 5.1/5.2: the spin-gas Glauber dynamics (3.2) uniquely determines the joint distribution factoring over the temporal graph Gt,t+δt (cliques ≤ k) iff the node-conditionals are a univariate exponential family with tensor-factorized canonical parameters (sufficient conditions: node-conditionals in a univariate exponential family; joint factors over G with cliques ≤ k; cf. Yang et al. 2015). Proof in 3 steps: (1) node-conditional (5.7) is a univariate exponential family with sufficient statistics φe(σi,t+δt) = σi,t+δt and canonical Θ = ln(1/2)·Γi,t; (2) with gas-like interaction g in form (5.8), the canonical parameters take the tensor-factorized form (B.4); (3) Hammersley-Clifford + Yang et al. lemmas give the unique joint. Extended sufficient statistics: φe(X) = (σi,t, δσi,t/δt, δδσi,t/δtδt) — a (3N+N)-dimensional vector.
- Practical guidance from the theory: the ground-truth process is uniquely representable by derivative-extended sufficient statistics, motivating the {position, momentum, acceleration} order-by-order feature discipline.

## 5. Features / target
Input: basic (raw) features per dataset, plus discretionary handcrafted features injectable at each order via the template. Target: one-step-ahead value (main text); multi-horizon (predict 1/2/3/5/10/20 future values from length-20 sequences, Appendix E.1). Extended features: K=45 per dataset in format (N,K,T). Customization case studies (Appendix E.2) show three handcrafted features perfectly resembled (R² = Pearson = 1 vs. reference): Momentum MoM[t,Δτ] (shift + difference + ratio[a,b]); Bias (difference vs. SMA + ratio); Absolute Energy (square + windowed sum). The authors stress exact resemblance is not generally achievable in practice — it requires prior knowledge — but the programming interface is general: any representable feature can be programmed.

## 6. Validation design
80/20 in-sample/out-of-sample split, 10 repeats per dataset/model; metrics: out-of-sample R² and Pearson correlation (one-step-ahead). Multi-horizon experiments in Appendix E.1 with lookback T=20, 5 runs, DART default model configs. Hyperparameter search (D.2): random search, 100 iterations (lr {1e-2..1e-5}, batch {64..feature dim}, hidden {64..2048}, early stopping). Architectures (D.3): MLP 3 layers/512/ReLU; CNN 1 FC-512 + 2 conv layers kernel 3; LSTM 2 hidden layers/512; Adam lr=1e-5, betas (0.9,0.999). Hardware: RTX 2080 Ti + Xeon Silver 4214. Splits are random 80/20, not walk-forward — noted as a hygiene weakness in section 9.

## 7. Numerical results / baselines
- One-step-ahead, basic vs. basic+extended (Table 1): consistent wins everywhere except electricity-LSTM. R² improvements range 1.3–5.85% depending on dataset/model. Hardest dataset (taxi): +4.3/5.9/3.4% R² for MLP/CNN/LSTM; +2.3/3.4/3.0% Pearson correlation.
- Multi-horizon (Table 5, predict 20 from length-20): +88+% R² and +27+% Pearson correlation on average across all models — the paper's headline result, showing the features matter most when the raw sequence is uninformative.
- E.1 additional models (Table 4, T=20, 5 runs): R² Synthetic/Taxi — XGBoost 99.12→99.34 / 77.34→78.15; LightGBM 98.92→99.34 / 77.05→81.01; Transformer 96.46→96.86 / 72.64→73.70; TCN 98.87→99.37 / 75.36→77.70; TFT 96.21→97.60 / 54.58→61.31 (+12.3% rel — weakest base model gains most); N-BEATS 99.26→99.41 / 76.82→79.94. Key claim: simple models (e.g. Transformer) on extended features ≈ SOTA models (TCN, TFT, N-BEATS) on raw features.
- E.1 multi-horizon (Table 5, synthetic, horizons 1/2/3/5/10/20): 20-step R² — Transformer 54.46→73.33; TFT 35.35→64.91; TCN 17.18*→52.50* (19-step; DART requires output < input); N-BEATS 57.06→74.65. Gains widen with horizon.
- Compute (Table 2): generation time negligible vs. downstream training — Taxi 24.34 s vs. 5,461.75 s (MLP); Electricity 82.71 s vs. 16,833.59 s; Traffic 218.23 s vs. 23,883.94 s.

## 8. Code / data availability
Public GitHub repository linked from the paper. Datasets public (UCI Electricity Load Diagrams, UCI PEM-SF Traffic, NYC TLC trip records; synthetic derived from Taxi).

## 9. Leakage & limitations
- Explicitly stated: the flexibility comes with the tradeoff of *no feature selection or pruning mechanism* beyond user-specific programs — generation can produce large redundant feature sets; the authors plan to integrate selection in future work.
- Evaluation hygiene is weaker than the other wave-5a papers: an 80/20 random train/test split rather than walk-forward validation, on time-series data. GSE must re-validate any adopted variant under walk-forward splits.
- The physics derivation (sections 3, 5) is heavy relative to the practical contribution; the operators themselves (difference/window/shift) are standard time-series primitives, and the paper's real contribution is the order-by-order programming discipline plus the customization interface.
- Multi-horizon headline numbers (88% R²) reflect a task where basic features are nearly uninformative, inflating the relative gain; the one-step-ahead gains (1.3–5.85%) are the honest scale.

## 10. GSE overlap
The 0th/1st/2nd-order hierarchy (position/momentum/acceleration) is a natural schema for sports time series: raw game stats → form/momentum differentials → acceleration of form (e.g., offensive rating, its 4-week change, the change-of-change). GSE can encode this as a standing feature program rather than reinventing rolling features per model. The customization template is the practical hook: inject GSE's handcrafted sports features (rest differentials, market-implied ratings, weather interactions) as discretionary features at each order, and let the module systematically extend them — human domain knowledge composed with automated generation, exactly the CAAFE/ELATE "context + automation" theme of this wave, minus the LLM cost. Deterministic and hyperparameter-free means it slots into a production pipeline with zero inference-time cost and full reproducibility — a complement to the LLM-based papers, not a competitor. This is a new capability (standing programmable rolling-feature schema), not a duplicate of existing GSE work.

## 11. GSE implementation spec
Sports bridge: NFL team panel — 0th-order = weekly box-score and market features (points, yards, spread, total); 1st-order = Difference features (4-week momentum of offensive efficiency, spread-vs-closing-line drift); 2nd-order = acceleration (is the momentum itself accelerating — e.g., a team whose defensive decline is worsening). Window operators at 3/4/8-week lookbacks; Shift for bye-week and rest-differential lags. Discretionary injection: weather, injury-report counts, travel distance as handcrafted 0th-order features. The multi-horizon result maps to predicting a team's next-N-games trajectory (e.g., season win total) from the first N games — the paper's 88% R² setting is the analog.

Concrete build plan:
1. Implement the three operators as pure pandas functions: `difference(s1, s2, smooth_w)` (rolling-mean smooth then subtract), `window(s, lookback, stat)` (mean/min/max/std over lookback, multiple resolutions), `shift(s, Δτ)`.
2. Feature template as YAML/JSON: three order lists, each = raw columns + discretionary handcrafted sports features; store the program under version control for reproducibility.
3. Operation module: apply within-order operator combos, then the order-upgrade rule (difference of 0th→1st, difference of 1st→2nd), then window/shift summaries at each order.
4. Pair with a pruning stage the paper lacks: |corr|>0.9 dedup + TreeSHAP-interventional recursive pruning (borrowed from ELATE/CRAFTER) before model training.
5. Wrap generation in the no-leakage contract: all operators causal (past rows only), verified by AST scan; run under walk-forward splits, not 80/20.

## 12. Reproducible test
Task: one-step-ahead NFL game prediction (spread cover / total points) on walk-forward season splits (train 2019–2023, validate 2024, test 2025). Baselines: XGBoost on basic features; treatment: XGBoost on basic + feature-program extended features (0th/1st/2nd order) with the pruning stage. Report out-of-sample R² and Pearson correlation deltas, plus generation-time vs. training-time cost, mirroring the paper's Table 1/Table 2.

## 13. Acceptance / rejection gate
ADAPT if: ≥0.003 held-out NFL log-loss improvement on 2025 games versus the basic-features baseline, with all operators provably causal (AST-verified past-only), feature generation time <5% of downstream training time, and the pruning stage removing ≥50% of generated features without hurting validation performance. REJECT (do not port) if any of: no gate improvement under walk-forward splits, leakage scan fails, or the pruned extended set performs no better than hand-built rolling features of the same width.

## 14. Improvement experiment
The paper never ablates the order hierarchy itself — the physics discipline may add nothing beyond the operators. Run a controlled ablation on GSE's NFL panel: (A) the full feature program with the order-upgrade rule (difference 0th→1st→2nd); (B) the same operators applied flat (all window/shift/difference combos on raw features only, no order structure), matched for total feature count after identical pruning. Compare walk-forward XGBoost R²/log-loss. If A ≈ B, the practical takeaway is the operator bank, not the physics — and the cheaper flat variant should ship. If A wins, the {position, momentum, acceleration} discipline is validated as a reusable schema. Either outcome is actionable, and the paper's own future-work note (integrate feature selection) is served by the shared pruning stage.
