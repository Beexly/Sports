## 1. Research question
Multi-modal (LiDAR+camera) motion capture suffers two problems: (1) cross-sensor alignment depends on explicit calibration, which propagates errors under changing viewpoints and forces fixed, highly-overlapped layouts; (2) methods degrade under severe noise or partial sensor failures. Sen-Cap asks: (a) can hybrid motion capture achieve robust multi-modal alignment under arbitrary sensor deployments (calibration-free)? (b) how to make precise global human translation predictions in noisy, cluttered environments? It introduces a Unified Across-Sensor Motion Estimator (UAME) reconstructing local pose/shape in a human-centric space without inter-sensor calibration, and a Noise-Resistant Trajectory Tracker (NTT) with iterative refinement for global trajectories.

## 2. Dataset / schema
Evaluation on Human-M3 (large-scale multi-person, multi-view LiDAR+camera, outdoor) and FreeMotion (multi-sensor) under training-view (T) and novel-view (N) protocols; cross-domain on LiDARHuman26M (outdoor noisy) and RELI11D (fast motion), trained only on AMASS + FreeMotion. Inputs: sequential point clouds x_pc^{L_i} ∈ ℝ^{256×3} (FPS-sampled per LiDAR), normalized 2D keypoints x_2d^{C_j} ∈ ℝ^{17×2} (bbox-normalized per camera); outputs full SMPL parameters: shape β ∈ ℝ^{10}, pose θ ∈ ℝ^{23×3}, global orientation τ ∈ ℝ³, global translation Γ ∈ ℝ³ (6890-vertex mesh, 24 joints). Metrics: J/V Err (PS/PST) in mm, Ang Err (degrees), Accel Err (m/s²), SUCD (mm). Noise study: synthetic ShapeNet clutter injected at 3 levels (L1 low, L2 0.1–0.5 m objects, L3 0.5–1 m objects) via raycasting from LiDAR viewpoint.

## 3. Method / model
(1) UAME Stage 1 — Human-Centric Space Alignment: per-LiDAR GRU predicts rotation vector τ_i mapping its 3D joint features (PointNet encoder) to a human-centric coordinate system H via x_{3d}^{H_i} = R(τ̂_i)^{-1} x_{3d}^{L_i} (Eq. 1); alignment loss ℒ_align (Eq. 2) over 6D rotation, LiDAR-space and human-centric features; 2D keypoints encoded into the same space via 2D encoder. (2) UAME Stage 2 — Adaptive Sensor Fusion: GRUs extract F_3d, F_2d; bottleneck attention F_fusion = CrossAttn(Q=F_token, K=F_m, V=F_m) (Eq. 3, F_m = Concat(F_3d, F_2d)) — learnable fusion token forces all modalities through a shared bottleneck, re-weighting by reliability; GRU decodes SMPL β̂, θ̂ (Eq. 4) with ℒ_pose (Eq. 5). Sensor Dropout: randomly mask feature tokens from both modalities during training (simulates partial→full sensor failure). (3) NTT: iterative refinement — ΔΓ̂^n = E_O(x_pc^{n-1}, x_{3d}^L), x_pc^n = x_pc^{n-1} + ΔΓ̂^n (Eq. 6); Γ̂ = x̄_pc + Σ_n ΔΓ̂^n; loss ℒ_tr = ‖Γ̂−Γ‖² + λ(1/N)Σℒ_dtr(ΔΓ̂^n) (Eq. 7) with per-step magnitude penalty δ (Eq. 8). Fixes the centroid-drift failure: prior methods normalize the point cloud to its centroid, which noise shifts far from the pelvis, forcing the network to predict large offsets. (4) Cross-sensor human matching: optimization-based per-frame matching (from FreeCap) + matching memory bank for real-time inference.

## 4. Equations & assumptions
Eq. 1: x_{3d}^{H_i} = R(τ̂_i)^{-1} x_{3d}^{L_i}. Eq. 2: ℒ_align = (1/N_L) Σ_i (‖τ_i^{6d}−τ̂_i^{6d}‖² + ‖x_{3d}^{L_i}−x̂_{3d}^{L_i}‖² + ‖x_{3d}^{H_i}−x̂_{3d}^{H_i}‖²). Eq. 3: F_fusion = CrossAttn(Q=F_token, K=F_m, V=F_m), F_m = Concat(F_3d, F_2d). Eq. 4: β̂, θ̂ = GRU(F_fusion). Eq. 5: ℒ_pose = α‖β−β̂‖² + ‖θ−θ̂‖². Eq. 6: ΔΓ̂^n = E_O(x_pc^{n-1}, x_{3d}^L); x_pc^n = x_pc^{n-1} + ΔΓ̂^n. Eq. 7: ℒ_tr = ‖Γ̂−Γ‖² + λ(1/N)Σℒ_dtr(ΔΓ̂^n). Eq. 8: ℒ_dtr = 0 if ‖ΔΓ̂^n‖ ≤ δ else |‖ΔΓ̂^n‖−δ|. Assumptions: human kinematics are sensor-invariant (alignment anchor); calibration-free = unknown arbitrary rigid transforms between sensors; noise shifts point-cloud centroids away from pelvis; sensor failures are simulable by token masking; novel-view evaluation = altered camera extrinsics.

## 14. Improvement experiment
Go beyond the paper by replacing SMPL body-shape regression with *sport-specific kinematic priors*: the paper regresses generic SMPL parameters, but for football the interesting quantities are joint velocities/accelerations at contact (tackle biomechanics, route-running explosiveness). A follow-on would supervise the bottleneck representation directly on kinematic-chain metrics (cf. paper 5's SAIL subskills: kinematic chain, pelvis/thigh pausing) rather than mesh vertices — turning a graphics pipeline into a sports-science measurement tool, which is the only form of this work that could ever feed GSE analytics.
