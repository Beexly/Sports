## 1. Research question
Cast feature engineering as *program search*: an LLM proposes feature-transformation programs, data-driven validation feedback scores them, and an evolutionary (island-model) memory of high-scoring programs guides iterative refinement — fixing the two weaknesses of existing LLM feature engineering (CAAFE = direct prompting with validation-score-only selection; FeatLLM/OCTree = single-candidate refinement with no population memory). Table 1's four-way comparison (domain knowledge / data-driven feedback / complex features / multi-feature refinement): AutoFeat ✗✗✓✗, OpenFE ✗✗✓✗, FeatLLM ✓✗✗✗, CAAFE ✓✓✗✗, OCTree ✓✓✗✗, **LLM-FE ✓✓✓✓**.

## 2. Dataset / schema
37 datasets total: 19 classification + 10 regression with descriptive feature names (OpenML, UCI, Kaggle; sizes 315–581k rows, 4–279 features) + 8 large-scale high-dimensional classification datasets; plus 5 post-Sept-2021 classification datasets (Hollmann et al. 2024; Bordt et al. 2024 "Elephants never forget" memorization-detection sets) used for the memorization control. 80/20 train/test splits, 5 seeded repetitions (Hollmann et al. 2024 protocol). Time: 2024–2026 era paper.

## 3. Method / model
**Formulation (§3.1):** bilevel objective — max_T E(f*(T(X_val)), Y_val) subject to f* ∈ argmin_f L_f(f(T(X_tr)), Y_tr), with programs T ∼ π_θ(p) sampled from the LLM conditioned on prompt p. Approximated by evolutionary search (Algorithm 1).
**Prompt (§3.2.1, Fig. 9):** role+instruction (explicitly: "use domain knowledge", "generate complex features" — countering the LLM simplicity bias; each feature needs a one-sentence docstring + justification), task description, feature names + descriptions, serialized data samples ("If c_1 is x_i …, then Result is y_i"), the evaluation function itself in the prompt, one initial in-context demonstration (modify_features_v0), and a function-to-complete stub.
**Sampling (§3.2.2):** b = 3 programs per iteration, temperature 0.8; each program executed before evaluation (error-prone discarded); max execution-time threshold (timeout = discard).
**Evaluation (§3.3):** train tabular predictor f* on transformed training set, score on transformed validation set (accuracy / error metrics); score = fitness.
**Experience management (§3.4):** FunSearch-style island model (m = 3 islands, each evolving separately from a copy of the initial example); programs clustered within an island by program signature (identical validation scores); cluster sampling by Boltzmann probability P_i = exp(s_i/τ_c)/Σ_j exp(s_j/τ_c), τ_c controlling exploration–exploitation; top-k sampled programs become the next prompt's in-context examples (implicit mutation/crossover via prompt conditioning — no explicit operators). Global budget: 20 LLM samples per experiment (fairness vs all LLM baselines).
**Backbones:** GPT-3.5-Turbo and Llama-3.1-8B-Instruct. Predictors: XGBoost (default), MLP, TabPFN.

## 4. Equations & assumptions
Equations: (1) max_T E(f*(T(X_val)), Y_val); (2) f* ∈ argmin L_f; (3) sample serialization Serialize(x_i, y_i, C) = "If c_1 is x_{i,1}, …, then Result is y_i"; Boltzmann cluster sampling P_i = exp(s_i/τ_c)/Σ exp(s_j/τ_c); Algorithm 1 (evolutionary loop with UpdatePrompt/UpdateBuffer). Named statistics: Wilcoxon signed-rank tests (Appendix D), 5-seed mean ± std. Assumptions (stated): descriptive feature names exist (excluded numeric-ID datasets); serialized examples fit the prompt; 20-sample budget equalizes LLM baselines; memorization risk handled via post-cutoff datasets; fitness = validation score is a faithful proxy for test.

## 5. Features / target
Inputs: raw tabular features with names/descriptions. Generated: whole *programs* that add multiple features at once (multi-feature refinement — unique in Table 1). Discovered operators skew toward sophisticated transforms under evolution (groupby-then-mean/min/max, residual, sigmoid vs CAAFE's 75% multiply/divide; Fig. 4). Qualitative example (Fig. 7, diabetes): insulin_glucose_ratio = Insulin/Glucose ("insulin resistance is a well-known risk factor") and bmi_age_ratio = BMI/Age with per-feature Thought justifications — vs the domain-blind variant's unjustified sqrt(C1·C3) + dropping C2. Targets: 19 classification labels (accuracy), 10 regression targets (RMSE).

## 6. Validation design
80/20 splits × 5 seeds; all LLM methods fixed at 20 samples, no early stopping, best-of-budget reported; classical baselines timed out at >12h marked ✗. Wilcoxon signed-rank tests in Appendix D.4: LLM-FE statistically significant (95% CI) over the base XGBoost on all 10/10 regression datasets (p < 0.001) and 8/15 classification datasets (p < 0.05), marginal on 2 more — 25 paired observations per dataset (5 seeds × 5 folds). Memorization control (§5.4): Bordt et al. 2024 datasets constructed to detect memorization and confirmed absent from pretraining + post-cutoff Kaggle sets with hidden splits → "modest but consistent gains" (kidneystones 0.761→0.761, fico 0.715→0.719, healthinsurance 0.756→0.759, pharyngitis 0.655→0.660, acsincome 0.807→0.809), arguing evolution filters memorization artifacts. HPO control (Appendix D.1): Optuna 100-trial tuning — LLM-FE gains persist on 3/5 datasets *after* HPO, i.e. complementary to tuning, not a substitute.

## 7. Numerical results / baselines
- Classification, XGBoost (Table 2, accuracy, mean rank over 19 datasets): Base 3.95, AutoFeat 5.11, **OpenFE 3.63**, **CAAFE 3.47**, FeatLLM 5.11, OCTree 4.05 → **LLM-FE 1.42**. Standouts: balance-scale 0.856→0.990 (OpenFE 0.986), jungle_chess 0.869→0.969 (CAAFE 0.901), covtype 0.870→0.882.
- Regression, XGBoost (Table 3, RMSE, mean rank over 10 datasets): Base 4.55, AutoFeat 4.45, OpenFE 2.80, Base-LLM 4.40, OCTree 3.70 → **LLM-FE 1.10** (best on all 10, e.g. housing 4.845→4.525, wine 0.639→0.612).
- Ablation (Fig. 2, XGBoost + GPT-3.5, normalized accuracy): full LLM-FE 0.70 → w/o domain knowledge 0.626, w/o data examples ~0.66 (slight), **w/o evolutionary refinement 0.587** — refinement is the load-bearing component; trajectory plot (Fig. 6): no-refinement plateaus by iteration ~5, full keeps climbing through 20.
- Generalization (Table 5): gains hold for every predictor × backbone cell — XGBoost+Llama 0.820→0.832, XGBoost+GPT-3.5 0.820→0.840, MLP 0.745→0.791 (GPT-3.5), TabPFN 0.852→0.863; regression RMSE similarly; also generalizes to GPT-4o-mini, Qwen2.5-72B, Gemini-2.5-Flash, CatBoost, logistic regression (Appendix D.2).
- Efficiency (Fig. 3, Pareto): LLM-FE on the time–accuracy Pareto frontier — same runtime as OCTree, substantially faster than CAAFE and OpenFE (both far off-frontier on time).

## 9. Leakage & limitations
**Adversarial read (updated 2026-09-22 with appendix findings):** (a) Fitness is validation score with best-of-20 budget and *no multiple-testing correction* — the same selection-bias hole as CAAFE, now amplified by evolution explicitly optimizing the validation metric; the memorization-control gains (Table 4) are "modest" and partly within noise. However, the D.4 Wilcoxon results partially answer this: significance on 10/10 regression and 8/15 classification sets across 25 paired observations each, i.e. not a best-of-budget fluke on regression. (b) The evaluation function is *in the prompt* — the LLM sees the fitness criterion and can game proxy features; no train/validation/test hygiene is discussed beyond the 80/20 split (features selected on validation, reported on test — acceptable, but thin). (c) No temporal/cutoff discipline at all — static tabular framing; sports time-series leakage (the OneBM problem, 1845) is entirely unaddressed. (d) Island clustering by *identical validation scores* is a crude diversity proxy; Boltzmann τ_c is a free parameter with no sensitivity analysis shown in the main text. (e) Compute: 4× RTX8000 GPUs for the benchmark; the 20-sample budget × model retraining per sample is fine for ≤2k-row datasets but the cost model at nflverse scale (millions of play rows × LightGBM refits) is untested — the paper's largest win (covtype, 581k rows) suggests feasibility but no timing is given per dataset. (f) Data samples are serialized into prompts → privacy/API-exposure consideration the authors themselves flag; mitigation (local open-source LLM, anonymized samples) costs the "slight" ablation drop. (g) GPT-3.5-Turbo as default backbone is a 2023 model; results may shift with newer models, though Appendix D.2's broader backbone sweep is reassuring.

**Appendix findings added 2026-09-22 (were unread in first pass):** (i) LLM-baseline comparison (Appendix A): LLM-FE's multi-island population exploration vs CAAFE/OCTree single-path refinement; ~45% of LLM-FE's discovered features qualify as "complex" per Küken et al. (ii) Feature transferability (Tables 12–13): XGBoost-generated features transfer to MLP, TabPFN, CatBoost, Logistic Regression with consistent gains — MLP classification 0.745→0.791 and regression NRMSE 0.871→0.631; TabPFN 0.852→0.863 / 0.289→0.286 — so GSE can search cheaply on a tree model and deploy elsewhere. (iii) SHAP attribution (Table 15): 16.67% of generated features land in the top-10 by SHAP, 62.96% in the top-50 — evidence they are used, not spurious. (iv) Noise robustness (Figure 10): with Gaussian noise σ ∈ {0, 0.01, 0.05, 0.1} injected into numerical classification datasets, LLM-FE stays above OpenFE and CAAFE at every noise level — relevant for noisy tracking data. (v) Island-count ablation (Table 16): k = 1, 3, 5 all perform similarly, moderate counts slightly best — robust to the hyperparameter, exploiter choice validated. (vi) Evolutionary-refinement trajectory (Figure 12): the w/o-refinement variant plateaus after 7 iterations on PC1 and 5 on Balance-Scale; evolution escapes local optima. HPO control (D.1): Optuna 100 trials random sampling, XGBoost space (max depth 1–11, n_estimators 100–6100, lr loguniform 1e-5–0.7 etc.) + MLP space (layers 1–8, hidden 16–1024, dropout 0–0.5, 100 epochs early stopping) — Table 9: LLM-FE beats Base+OpenFE on 3/5 low-baseline datasets even after HPO (e.g., bloodtransfusion 0.791 vs 0.777, vehicle 0.780 vs 0.810 XGB — vehicle HPO shows OpenFE ahead on XGBoost, MLP side favors LLM-FE 0.694 vs 0.396).

## 10. GSE overlap
The lane's capstone method: it *contains* the CAAFE idea (1846) as its no-refinement ablation and beats it (0.587 vs full), and it beats the two numeric anchors (OpenFE 1842, AutoFeat 1844) head-to-head in the same tables. Per /home/hatch/workspace/arxiv-sweep/existing-research-map.md, GSE's analyst-driven feature ideation is exactly the "domain expert + no systematic search" setup LLM-FE automates — and the ablation proves the evolutionary refinement (not just the LLM) is what converts domain knowledge into performance. The island model gives a natural multi-analyst parallelization: one island per analyst-hypothesis family. The operator-bias finding (Fig. 4) is directly actionable: GSE's current hand-built features skew toward simple arithmetic; evolution toward groupby/residual/sigmoid-style transforms is the concrete upgrade path.

## 11. GSE implementation spec
Adopt the harness as-is (open code), GSE-ify the prompt layer: (1) Metadata M: nflverse schema with column descriptions + **cutoff annotations** (pre-kickoff only) — the paper's missing leakage discipline, backfilled from ledger 1845's rule. (2) Islands: m = 4, seeded with four hypothesis families (passing efficiency, rushing/matchup, market/odds movement, situational/weather). (3) Predictor: LightGBM (GSE's engine model) as f*; fitness = validation log-loss on 2023 season. (4) Budget: 20 LLM programs per weekly run; exec-time threshold per program; error-prone discarded automatically. (5) Local backbone first: Llama-3.1-8B-Instruct class model locally (no data leaves the VM — answers the paper's privacy flag); escalate to frontier API only if local stagnates. (6) Keep criterion upgraded per ledger 1846's fix: paired permutation test with Holm correction across the budget (the paper's raw best-of-20 is its weakest statistical link). Effort: ~1 week (harness exists; prompt + LightGBM evaluator + audit plumbing are the work).

## 12. Reproducible test
Dataset: nflverse 2020–2024 + odds snapshots, kickoff cutoffs enforced. Protocol: weekly LLM-FE runs (20 programs) on 2020–2022 train / 2023 validation; frozen best program per week; LightGBM baseline vs baseline + discovered features on held-out 2024 (log-loss). Controls: (a) no-evolutionary-refinement ablation (paper's 0.587 result predicts a plateau — replicate it: if GSE's no-refinement run matches the full run, the harness adds nothing); (b) domain-knowledge ablation (anonymized column names C1…Cn; paper predicts 0.626-level collapse — if not, the gains are numeric luck, not semantics); (c) leakage audit: kickoff-cutoff replay on 500 games.

## 13. Acceptance / rejection gate
ADOPT the harness iff (a) 2024 held-out log-loss improves ≥ 0.003, AND (b) both ablations replicate the paper's ordering (full > w/o-refinement, full > anonymized — proving the mechanism is real, not budget luck), AND (c) zero leakage-audit failures, AND (d) weekly runtime ≤ 6 hours on the VM (efficiency bound from the paper's Pareto claim). REJECT if the no-refinement ablation matches the full run, if any cutoff replay fails, or if the memorization-control analog (features proposed for the 2024 season that reference 2024-specific narratives in their docstrings — e.g. new kickoff rules — without validation gain) shows the LLM is story-fitting rather than discovering.

## 14. Improvement experiment
Beyond the paper: fix its weakest statistical link — replace best-of-20 validation selection with a **two-stage fitness**: stage 1 (within budget) ranks by validation log-loss; stage 2 takes the top-3 programs and re-scores them on a *sequestered* second validation season (2022) the LLM never sees during evolution, keeping the program only if it wins on both. This directly attacks the selection-bias hole in §3.3 while preserving the evolutionary dynamics. Second: make τ_c adaptive — start high (exploration) and anneal across the 20-sample budget, logging the operator-diversity curve (Fig. 4 analog); hypothesis: annealed τ_c discovers the groupby/residual-class operators faster than fixed τ_c. Both experiments are measurable against the paper's own ablations.
