# [0318] AdaSpot: Spend Resolution Where It Matters — Dual-Branch Adaptive Event Spotting (arXiv:2602.22073v1)

**Citation:** Artur Xarles, Sergio Escalera, Thomas B. Moeslund, Albert Clapés (2026). *AdaSpot: Spend Resolution Where It Matters*. arXiv:2602.22073v1. URL: https://arxiv.org/abs/2602.22073v1
**Ledger completed:** 2026-09-21. **Read:** full text (PDF text extract, 1151 lines, main paper + appendix).
**Verdict:** ADAPT — the dual-branch "spend resolution where it matters" design (low-res global context + training-free saliency ROI + high-res detail branch) is the right efficiency template for spotting NFL events (snap, pass release, catch, tackle) in broadcast clips; a direct port needs multi-ROI or player/ball conditioning because NFL scenes are multi-actor, and the paper shows multiple ROIs currently hurt.

## 1. Research question
The paper asks how to do precise event spotting in long sports videos without paying full-resolution compute on every frame. It proposes AdaSpot: a dual-branch architecture where a low-resolution full-frame branch (RegNetY + GSF) provides global context and a training-free saliency-based ROI selector crops one high-resolution region per frame for a detail branch; the two fuse (max) into a bidirectional GRU frame classifier. The claim: resolution spent only where it matters beats both single-branch and learnable-crop alternatives on five sports benchmarks.

## 2. Dataset / schema
Five benchmarks: Tennis — 3,345 clips, 28 matches, 33,791 events, 6 classes; FineDiving — 3,000 clips, 7,010 events, 4 classes; FineGym — 5,374 videos, 80,166 events, 32 classes; F3Set (table tennis) — 11,584 clips, 114 matches, 75 players, 42,846 events, 365 classes; SN-BAS (figure skating) — 7 matches, 12,422 events. All are standard public PES (precise event spotting) benchmarks with frame-level event annotations. Access: public benchmark datasets (per the paper's references; verify each license).

## 3. Method / model
Architecture: (a) low-res full-frame branch — RegNetY backbone + GSF (gate-shift-fuse) temporal module for global context and saliency; (b) training-free ROI selector — replicate padding, channel-averaged saliency, upsampling, spatiotemporal Gaussian smoothing, then an adaptive rectangle containing cumulative saliency threshold τ (minimum 112×112); (c) high-res branch on the single selected ROI per frame; (d) fusion — two-layer MLP projections per branch, max fusion, bidirectional GRU, per-frame classifier. Loss: L = λfLf + λlLl + λhLh with all λ = 1/3 (frame/global, low-res, high-res terms), positive-class weight 5. Training: clips of length 100, batch 4, AdamW, lr 8e−4, 5 warmup epochs, cosine decay, RTX 6000 Ada; epochs: 25 (FineDiving), 50 (Tennis, SN-BAS), 100 (FineGym, F3Set). Postprocessing: Soft-NMS with window ω (results sensitive to ω — Section 9). Two sizes: small (7.58M params, 29.78 GFLOPs) and big (10.63M params, 56.78 GFLOPs); inference memory 1.97 GB.

## 4. Equations & assumptions
Paper's equations (copied faithfully): composite loss `L = λfLf + λlLl + λhLh` (all λ = 1/3); ROI = adaptive rectangle over cumulative saliency ≥ τ with 112×112 minimum. Stated assumptions: (a) one ROI per frame suffices (single salient region contains the event); (b) training-free saliency (channel-averaged activations) localizes events without supervision; (c) spatiotemporal Gaussian smoothing stabilizes the ROI across frames; (d) max fusion of branch projections preserves the stronger signal. The single-ROI assumption is the binding one for NFL (Section 9).

## 5. Features / target
Inputs: video clips (100-frame windows). Intermediate features: low-res global features + saliency maps; high-res ROI features. Target: per-frame event classification (event class + precise timestamp) — mAP at temporal tolerances δ (mAP@0 strictest … mAP@2). Classes are sport-specific (e.g., 6 tennis strokes, 365 table-tennis actions, skating elements).

## 6. Validation design
Standard PES benchmark protocol: train/val/test splits per dataset, mAP@δ reported with means ± std over runs. Baselines: prior PES methods (E2E-Spot, F3ED, STARK, AF-v2, T-DEED per the comparison tables) and internal ablations (low-only, no smoothing, two ROIs, parameter reuse, learnable crop). The appendix adds tolerance-ablation (δ=0,1,2) and postprocessing-ablation (Soft-NMS ω). No time-series leakage concern (standard i.i.d.-ish benchmark splits); the postprocessing sensitivity (Section 9) is the methodological caveat.

## 7. Numerical results / baselines
Paper's main results (Table 1, mAP@0, strictest): AdaSpot-small — Tennis 73.49±1.2, FineDiving 27.26±1.9, FineGym 17.52±0.1, F3Set 53.55±1.2 (7.58M params, 29.78 GFLOPs); AdaSpot-big — 74.02±1.4, 27.07±1.8, 18.21±0.2, 55.38±0.3 (10.63M params, 56.78 GFLOPs). SN-BAS: small 53.12±1.4, big 56.24±0.3. F3Set comparison (mAP@0/1/2): F3ED 24.8/60.7/64.8; AdaSpot-small 53.55/67.76/68.41; AdaSpot-big 55.38/69.37/69.94 — a large strict-tolerance win. Ablations (Tennis/SN-BAS mAP@0): full 73.30/53.02; low-res-only 71.18/47.98 (high-res branch earns its keep, especially SN-BAS); no smoothing 71.67/49.99; two ROIs 72.06/49.19 (worse than one — the multi-actor warning); parameter reuse −37% params for −1.60/−1.12 strict mAP; learnable crop (AF-v2) high-res-only SN-BAS 23.1±15.1 vs. AdaSpot's 52.1±0.7 (training-free saliency far more stable). Postprocessing sensitivity: Soft-NMS ω=1 gives Tennis mAP@0 75.05 vs. ω=2's 73.30 — ~1.75 points ride on the NMS window choice. These are the paper's claims on public benchmarks.

## 8. Code / data availability
Code: https://github.com/arturxe2/AdaSpot (stated in paper). Data: the five benchmarks are public (verify per-dataset licenses).

## 9. Leakage & limitations
(a) Postprocessing sensitivity: ~1.75 mAP@0 points on Tennis depend on the Soft-NMS window ω — headline numbers are partly a tuning artifact; any port must fix ω (or the NMS scheme) before comparing. (b) Single-ROI assumption: the paper's own ablation shows two ROIs hurt (72.06 vs. 73.30 Tennis; 49.19 vs. 53.02 SN-BAS) — but NFL plays have 22 actors and the salient event (ball) is small and fast; the one-ROI design that wins on tennis/diving may fail on football, and the paper gives no multi-actor solution. (c) Benchmarks are all single-actor or sparse scenes (tennis, diving, gymnastics, table tennis, skating) — no dense team-sport evaluation. (d) Strict-tolerance performance is uneven: FineGym mAP@0 is only 17.52–18.21, suggesting the method struggles with fine-grained dense action vocabularies (365-class F3Set does better, but gymnastic elements are subtle). (e) External validity to NFL prediction: none directly — this is a perception/event-spotting system; its GSE value is as the front end of the film-analysis pipeline (feeding ledgers 0313/0316's pose and commentary stages), not the engine.

## 10. GSE overlap
Fits GSE's emerging film-analysis stack, not the prediction engine: ledger 0313 (Field Converter) needs per-frame event anchors (play boundaries), and ledger 0316 (TennisExpert's NFL port) needs an event-spotting front end — AdaSpot is the natural candidate for that role. The existing corpus has no event-spotting method; the NGS-replacement spec assumes tracking data exists rather than deriving events from video. Classification: new capability — precise broadcast-video event spotting — that composes with this wave's other ADAPT verdicts (0313 pose, 0316 commentary) into a full film-understanding pipeline.

## 11. GSE implementation spec
NFL event-spotting front end: (a) data — licensed NFL broadcast clips with frame-level annotations for snap, handoff, pass release, catch, tackle, whistle (annotate ~2,000 plays; reuse the parser annotation effort from ledger 0316); (b) model — AdaSpot-big recipe (RegNetY+GSF low-res, saliency ROI, high-res branch, BiGRU) from the public code, retrained on NFL classes; (c) multi-actor fix — condition the ROI selector on ball detection (track the ball, center ROI on it) or run K ROIs with a learned selector, since the paper's two-ROI ablation failed; treat this as the core research risk; (d) postprocessing — fix Soft-NMS ω on validation before any comparison, and report ω-ablated numbers; (e) serving — offline batch over game film, feeding play segmentation into the 0313/0316 pipeline stages; 1.97 GB inference memory fits a single GPU; (f) estimated effort: 6–8 weeks including annotation, sharing the annotation budget with the 0316 parser.

## 12. Reproducible test
Dataset: 5 licensed NFL games with frame-level event annotations (snap, pass release, catch, tackle), game-disjoint test (1 game held out). Metric: mAP@0/1/2 (frame tolerances) per event class, with the Soft-NMS ω fixed on validation. Baseline to beat: a single-branch low-res-only spotter (the paper's own low-only ablation analogue) and a naive audio-based snap detector. The test must report results at two ω values to expose postprocessing sensitivity.

## 13. Acceptance / rejection gate
Adopt as GSE's film event-spotting front end only if: (a) on the held-out game, mAP@1 ≥ 70 for snap and pass release (the two events downstream stages depend on) with ω fixed on validation; AND (b) the ball-conditioned/multi-ROI variant beats single-ROI by ≥3 mAP@1 points (proving the multi-actor fix works); AND (c) results hold within ±2 points across the two reported ω values (postprocessing robustness). If (b) fails, the single-ROI design is declared unfit for football and the lane reverts to simpler detectors (audio snap detection + heuristic play segmentation).

## 14. Improvement experiment
Beyond the paper: replace the training-free saliency ROI with a ball-track-conditioned ROI (a lightweight ball detector + tracker sets the ROI center each frame; the high-res branch then always sees the ball at full resolution), and test whether this fixes the multi-actor failure the paper's two-ROI ablation exposed. Rationale: in football the event-defining object (the ball) is small, fast, and unambiguous — conditioning on it converts the hard generic multi-actor problem into an easier tracking-conditioned one, directly attacking the paper's stated single-ROI limitation with domain structure the benchmarks lacked.
