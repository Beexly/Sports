# [0316] TennisExpert: Towards Expert-Level Analytical Sports Video Understanding (arXiv:2603.13397v2)

**Citation:** Zhaoyu Liu et al. (2026). *TennisExpert: Towards Expert-Level Analytical Sports Video Understanding*. arXiv:2603.13397v2. URL: https://arxiv.org/abs/2603.13397v2
**Ledger completed:** 2026-09-21. **Read:** full text (PDF text extract, 1498 lines, main paper + appendices A–B).
**Verdict:** ADAPT — the hierarchical-memory architecture (FIFO short-term memory plus deterministic long-term symbolic consolidation feeding a frozen-backbone MLLM) is a transferable design pattern for GSE's future NFL broadcast-film analysis and automated commentary; the tennis-specific parser, dataset, and "ground truth" (LLM-synthesized commentary) do not transfer.

## 1. Research question
The paper asks how to generate expert-level analytical tennis commentary from broadcast video with both rally-level tactical detail and match-long context. It introduces TennisVL (a 471.9-hour tennis commentary benchmark) and TennisExpert, a framework combining a video semantic parser (scoreboard OCR, event spotting, object trajectories) with hierarchical memory (short-term FIFO + long-term structured statistics) feeding a fine-tuned Qwen3-VL-8B model.

## 2. Dataset / schema
TennisVL: 202 matches, 471.9 hours of broadcast video (YouTube, 2019–2025, 1280×720, 25–30 FPS), 40,523 rally clips (average 7.68 s), average commentary 31.42 words, 94 unique players, 162,503 total shots. Construction: audio-based rally segmentation (neural network detecting racquet-ball impact signatures, trained with crowd/announcer-noise augmentation; clips retained only with standard top-down court view and visible scoreboard); commentary annotation via WhisperX transcripts + TennisAbstract shot-by-shot data + score + prior-rally context, synthesized by Gemini 3 Pro with a "professional tennis commentator and coach" system prompt; two-stage verification — automated consistency check plus human review of a random 2,000 pairs with >95% acceptance. Split is match-level: 182 matches / 35,687 clips train; 20 matches / 4,836 clips test. Critical caveat (Section 9): the "ground truth" commentary is LLM-synthesized, not human-written — the model is trained to imitate Gemini 3 Pro's synthesis of transcripts and shot data.

## 3. Method / model
TennisExpert = video semantic parser + hierarchical memory + MLLM. Parser: scoreboard OCR per rally (st=(ρA,ρB,v) — player names, scores, server); event spotting (et=(ci,τi) event class + timestamp; GRU-based detector, Edit Score 81.2); object detection (RF-DETR fine-tuned for players/ball) + court keypoints + homography projection. Memory: Ht=[St,Lt]; short-term St = {(Vi,Mi,Ci) | i=t−K..t−1} with K=4 (FIFO of recent rally video/metadata/commentary); long-term Lt = Φ(Lt−1, Mt−K) — deterministic consolidation of structured stats (aces, double faults, 1st-serve %, winners, unforced errors) carried across the match. Generation: Qwen3-VL-8B backbone, supervised fine-tuning for 3 epochs, lr 1×10⁻⁵, cosine schedule, 4× H200 GPUs, BF16, vision encoder/projector frozen. Inference: parser runs at up to 40 FPS on a single GPU; MLLM inference <2 s latency, ~20 GB VRAM, O(1) token complexity (~14k tokens) vs. O(T) for raw-video baselines.

## 4. Equations & assumptions
Paper's equations (copied faithfully): commentary generation `Ct = MLLM(Vt, Mt, Ht)` (Eq. 1); short-term memory `St = {(Vi,Mi,Ci) | i=t−K,..,t−1}` (Eq. 2); training objective `log p(Ct|Vt,Mt,Ht) = Σⱼ log pθ(wj | w<j, Zv, Zs)` (Eq. 3). Stated assumptions: (a) rally-level segmentation from audio impact detection is reliable; (b) scoreboard OCR + event detection + trajectories capture the tactically relevant state; (c) deterministic long-term stat consolidation Φ suffices for match context (no learned memory); (d) Gemini-3-Pro-synthesized commentary is an adequate training target. Unstated: the frozen vision encoder is assumed sufficient for tennis visuals without domain fine-tuning.

## 5. Features / target
Inputs per rally t: video clip Vt, structured metadata Mt (scoreboard state, event sequence, object trajectories), hierarchical memory Ht=[St,Lt]. Target: analytical commentary Ct (average 31.42 words) — tactical reasoning, momentum, score context, professional terminology. Evaluation metrics: traditional (BLEU-4, METEOR, ROUGE-L, CIDEr) and LLM-based (accuracy, coherence, excitement, professionalism, pacing, total).

## 6. Validation design
Match-level split (182 train / 20 test matches; 35,687 / 4,836 clips) — no match appears in both splits, so the split is clean against match memorization. Baselines: zero-shot and fine-tuned open-source MLLMs (Qwen3-VL-8B backbone ablations) and proprietary models (Gemini-3-Pro, GPT-5.2, Claude Opus 4.5 per references). Ablations (Table 4): Vt alone → Vt+Mt → +St → +St+Lt, in zero-shot and fine-tuned settings. Metrics on the held-out 20 matches. No temporal-leakage issue given the match-level split, but the ground-truth-validity issue (Section 9) dominates.

## 7. Numerical results / baselines
Paper's main results (Table 2): TennisExpert — BLEU-4 7.98, METEOR 31.54, ROUGE-L 29.16, CIDEr 43.71, LLM total 88.05 (Acc 15.79, Coh 19.29, Exc 16.84, Pro 16.73, Pac 19.40). Best proprietary zero-shot (Gemini-3-Pro): 1.78 / 20.02 / 17.41 / 10.11 / total 59.89; GPT-5.2 total 56.59. Ablation (Table 4, fine-tuned Qwen3-VL-8B): Vt alone 42.74 total → Vt+Mt 73.74 → +St 85.97 → +St+Lt 88.05 (CIDEr 7.86 → 24.15 → 41.92 → 43.71). Efficiency (Table 3): structured input ~14k tokens O(1), ~20 GB VRAM, <2 s latency vs. dense-video O(T) tokens, OOM, high latency. Event detector Edit Score 81.2. These are the paper's claims; the comparison is fair on compute, but all quality metrics measure similarity to LLM-synthesized references (Section 9).

## 9. Leakage & limitations
(a) Ground-truth validity: the "expert commentary" target is synthesized by Gemini 3 Pro from transcripts + TennisAbstract shot data + score context, then only spot-checked by humans (2,000 pairs, >95% acceptance). The model therefore learns to imitate an LLM's synthesis — metric gains partly measure LLM-to-LLM style matching, not true expert judgment. (b) No demonstration that generated commentary is factually reliable beyond the synthesized reference; hallucinations of tactics/stats are unmeasured. (c) Tennis-specific: the parser (court keypoints, tennis scoreboard grammar, serve/rally structure) does not transfer to football; an NFL port needs a from-scratch parser (down/distance/field position, formation detection). (d) External validity to NFL prediction: none directly — this is a commentary/understanding system, not a forecasting model; its GSE value is in content production and film analysis, not the engine. (e) Proprietary-model baselines are zero-shot only; a fine-tuned proprietary baseline is not compared.

## 10. GSE overlap
GSE has no video-understanding or automated-commentary lane: the corpus covers tracking/NGS data, DFS, calibration, and market microstructure, but nothing on broadcast-film parsing or MLLM commentary. The NGS-replacement spec (`docs/research/2026-09-18-ngs-replacement-spec.md`) is about data, not video understanding. The X content operation (voice/brand research in `2026-09-10-galaxy-commentary-brand/`) is about human-written copy, not generated film analysis. Classification: new capability — structured video understanding with hierarchical memory — applicable to GSE's content/film-analysis ambitions, not to the prediction engine.

## 11. GSE implementation spec
Port the architecture, not the tennis model: (a) NFL semantic parser — play segmentation (snap-to-whistle via audio/visual cues), scoreboard bug OCR (score, down, distance, quarter, clock), event spotting (snap, handoff, pass release, catch, tackle — train a GRU detector analogous to the paper's Edit-Score-81.2 event model), player/ball detection + field-yardline homography; (b) hierarchical memory — short-term FIFO of recent plays (K=4–8) with play metadata, long-term deterministic consolidation Φ of game state (score differential, timeouts, down/distance tendencies, personnel groupings, EPA by situation); (c) MLLM — fine-tune an open vision-language backbone (Qwen3-VL class) on NFL film with human-written analyst commentary as targets (NOT LLM-synthesized — avoid the paper's ground-truth flaw; source from GSE's own analyst notes or licensed broadcast transcripts); (d) serving — offline batch for content (film-room breakdowns, X/TikTok scripts) at the paper's <2 s/20 GB profile per play; (e) estimated effort: 8–12 weeks for the parser + memory schema, plus ongoing annotation cost for human commentary targets.

## 12. Reproducible test
Dataset: 10 licensed NFL games with broadcast film; human analysts write tactical commentary for a sample of ~500 plays (the test targets). Metric: same dual suite — traditional (CIDEr, ROUGE-L) + LLM-judged (accuracy, coherence, professionalism) vs. the human references; plus a factuality audit (score/down/distance/player-ID error rate, must be <5%). Baseline to beat: zero-shot proprietary MLLM on raw clips, and the paper's ablated Vt-only variant. Window: game-disjoint test (2 games held out).

## 13. Acceptance / rejection gate
Adopt the NFL port into GSE's content pipeline only if: (a) on game-disjoint test plays, the full system (parser + St + Lt) beats the Vt-only baseline by ≥10 points of LLM-total score AND beats zero-shot proprietary MLLM by ≥15 points; AND (b) factuality audit shows <5% score/down/distance/player-ID errors (commentary with wrong game state is worse than none); AND (c) inference stays within the paper's efficiency envelope (<2 s/play, single-GPU). If factuality fails, reject — fluent-but-wrong film breakdowns would damage the brand Garrett is building on trust-no-claims.

## 14. Improvement experiment
Beyond the paper: fix its ground-truth flaw with a human-preference loop — collect pairwise analyst preferences over generated vs. human commentary (or over two generated variants) and fine-tune with preference optimization, then test whether preference-tuned commentary beats the supervised-only model on the LLM-judged professionalism/total scores. Rationale: the paper's ceiling is "imitate Gemini's synthesis"; a preference loop targets actual analyst quality judgment, which is the real objective for GSE content, and it reuses the pairwise-preference machinery (cf. ledger 0315, Pref-MH) already inventoried in this wave.
