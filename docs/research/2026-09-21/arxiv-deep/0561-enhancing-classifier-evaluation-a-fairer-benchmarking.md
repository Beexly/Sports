# [0561] Enhancing Classifier Evaluation: A Fairer Benchmarking Strategy Based on Ability and Robustness (arXiv:2504.09759)

**Citation:** Cardoso, L. F. F., Santos, V. C. A., Ribeiro Filho, J. S., Francês, R. S. K., Prudêncio, R. B. C., & Alves, R. C. O. (2025). *Enhancing Classifier Evaluation: A Fairer Benchmarking Strategy Based on Ability and Robustness*. Information Sciences. arXiv:2504.09759. URL: https://arxiv.org/abs/2504.09759
**Ledger completed:** 2026-09-21. **Read:** full text (PDF text extract, 1701 lines).
**Verdict:** ADAPT — fit IRT difficulty/discrimination parameters to GSE's games so engine picks are evaluated against instance-level difficulty (which NFL games are genuinely hard to call), and use Glicko-2 round-robin tournaments to rank engine versions honestly; the methodology transfers, but the paper's 3PL-on-test-instances setup must be adapted from classification benchmarks to betting games.

## 1. Research question
How should classifiers be evaluated jointly with the difficulty of the test instances? The paper combines Item Response Theory (IRT — ability measured against per-instance difficulty/discrimination) with the Glicko-2 chess rating system (classifiers play round-robin "tournaments" per dataset, winner decided by IRT True-Score), producing a fairer ability-vs-robustness benchmark ranking than accuracy alone. Case study: the OpenML-CC18 benchmark (72 curated classification datasets).

## 2. Dataset / schema
OpenML-CC18: 72 curated classification datasets (2018; instance counts 500–100,000; filtered per 13 criteria listed in §2.2). The study used 60 of 72: 11 datasets with >30,000 instances excluded as too slow, and "Pc4" excluded because R's ltm package failed to converge even on <500 test instances. All tabular data. Response matrix built from: 120 MLP models (depth 1→120); 12 classifiers (GaussianNB, BernoulliNB, KNN-2/3/5/8, Decision Tree, RF-3, RF-5, standard RF, standard SVM, standard MLP); 7 artificial classifiers (optimal, pessimal, majority, minority, 3 random) as performance anchors. Stratified 70/30 train/test split, test sets capped at 500 instances. Supplementary materials: https://osf.io/wvptb/files/ ; tool "decodIRT" automates the pipeline.

## 3. Method / model
Three-step pipeline (decodIRT): (1) Classification & response matrix — classifiers trained on OpenML datasets (scikit-learn, 10-fold CV), binary right/wrong matrix per test instance. (2) Item parameter estimation — 3PL IRT model per dataset via R ltm package (rpy2 bridge); item parameters (difficulty b_i, discrimination a_i, guessing c_i) per test instance. (3) Dataset/model evaluation — classifier ability θ estimated with Birnbaum's two-step procedure (catsim package, instances sorted by difficulty in 10 ascending groups), per-instance correct-answer probabilities → True-Score TS_j = Σ_i P(U_ij=1|θ_j). Glicko-2 tournament: each dataset = one rating period, round-robin over classifiers, winner = higher True-Score (1/0/0.5 chess scoring), initial rating 1500 / RD 350 / volatility 0.06. Final ratings → classifier ranking. Six dataset-order/subset schemes tested, including two 30-dataset subsets (half the benchmark) with the smallest variation in difficulty/discrimination parameters.

## 4. Equations & assumptions
Copied faithfully:
- 3PL: P(U_ij=1|θ_j) = c_i + (1−c_i)·(1/(1+e^{−a_i(θ_j−b_i)})) — eq. (1).
- True-Score: TS_j = Σ_i P(U_ij=1|θ_j) — eq. (2).
- Glicko-2 95% interval: [R − 2RD, R + 2RD]; initial values 1500 / 350 / 0.06.
- Principle of Consistent Order: a respondent who gets a hard item right should get all easier items right; violations penalize ability (drives True-Score differences between same-accuracy classifiers).
- Assumptions: dichotomous right/wrong responses per instance; 3PL chosen as the "most complete and consistent" model (per Martínez-Plumed et al. 2019); item parameters stable across classifiers; Glicko-2 order-of-confrontation effects managed by dataset ordering schemes.

## 5. Features / target
No feature modeling — the "items" are raw benchmark datasets (60 tabular datasets with names listed in Table 4; e.g., ilpd, mfeat-morphological, spambase, dna). Target for IRT: per-instance right/wrong of each classifier. Target for Glicko-2: pairwise True-Score tournament outcomes. Analysis layer: correlation of 8 OpenML dataset metadata (NumberOfClasses, NumberOfInstances, NumberOfFeatures, ClassEntropy, Dimensionality, PercentageOfInstancesWithMissingValues, MajorityClassPercentage, MinorityClassPercentage) with IRT item parameters.

## 6. Validation design
No held-out validation in the ML sense; validation is by the artificial-classifier anchor test: a benchmark subset is "valid" only if the optimal classifier ranks first and pessimal last. Six tournament schemes compared: all 60 by increasing difficulty, all 60 by increasing discrimination, and the four 30-dataset low/high-variation subsets. Metadata–item-parameter correlations computed across the 60 datasets.

## 7. Numerical results / baselines
All numbers quoted exactly as in the paper:
- OpenML-CC18 via IRT: only 16.66% of datasets have mean difficulty >0 and only 3.33% >1 (∼1/6 of the benchmark truly challenging); >90% of datasets have positive discrimination.
- Difficulty–discrimination inversion: most-difficult bin (mean difficulty 0.63) has mean discrimination −2.44; easiest bin (mean difficulty −1.99) has mean discrimination 20.09 (Fig. 8).
- Negative-discrimination pathology: on the "ilpd" dataset, including negative-discrimination instances let the pessimal artificial classifier outscore the optimal one on True-Score (Fig. 9a); dropping those instances restores optimal-first/pessimal-last ordering (Fig. 9b).
- Glicko-2 rankings (rating / RD / volatility): increasing-discrimination full-benchmark — optimal 1799.001, SVM 1734.361, MLP 1700.412, RF 1697.411, KNN 1690.538, NB 1525.258, DT 1511.353, majority 1423.922, rand2 1257.671, rand1 1225.113, minority 1204.294, pessimal 1064.439 (Table 5). Increasing-difficulty full-benchmark — RF 1709.253, SVM 1708.006, optimal 1628.72 (170 pts below its discrimination-ranking value), pessimal rises ∼290 pts to 1291.399 (Table 6). Low-difficulty-variation subset (30 datasets) — optimal 1975.373 (RD 46.916), RF 1808.96, MLP 1762.407, SVM 1743.663, KNN 1667.219, DT 1560.567, NB 1557.156, majority 1377.26 (∼200-pt gap to NB), pessimal 947.97 (Table 7). Low-discrimination-variation subset — optimal 1904.183, RF 1772.354, MLP 1719.655, SVM 1676.283; the two low-variation subsets agree on all real-classifier positions and share 23 of 30 datasets (76.6% overlap). High-variation subsets are judged invalid (optimal falls to 6th in Table 9).
- The paper's headline claim: a reduced subset with 50% of the datasets offers comparable evaluation power; Random Forest has the highest real-classifier ability.
- Metadata correlations: NumberOfClasses with avg Guessing (−0.29) and Difficulty deviation (−0.20); PercentageOfInstancesWithMissingValues with guessing deviation (0.27); MajorityClassPercentage with guessing deviation (0.26) and discrimination deviation (0.29); MinorityClassPercentage with avg guessing (0.31) and avg discrimination (−0.24). ClassEntropy correlates highly with all item-parameter standard deviations.

## 9. Leakage & limitations
Adversarial notes: (a) the "fairer" claim rests on True-Score tournaments over *test instances from the same benchmark* — there is no external ground-truth difficulty, so difficulty is circular (defined by the same classifiers being ranked); (b) Glicko-2 is order-dependent by design and the authors hand-pick the ordering schemes, meaning the ranking is a function of the chosen tournament schedule, not just model quality; (c) dropping 12/72 datasets (the 11 largest — i.e., the hardest realistic scale tests — plus Pc4) is survivorship bias toward datasets small enough for ltm to converge; (d) the headline "50% of datasets suffices" is validated only by internal agreement between two hand-built subsets, not by external replication on a different benchmark; (e) for GSE transfer: the paper's items are test instances of classification datasets, not games — a 3PL's guessing parameter makes sense for multiple-choice tests but needs re-interpretation for binary game outcomes where "guessing" = coin-flip baseline; (f) Information Sciences (journal) paper but reads like an extended MSc-project write-up with heavy self-citation (Cardoso/Santos/Alves [8,9,20]).

## 10. GSE overlap
New capability. GSE's calibration/uncertainty lane covers CQR, grouping loss, temperature scaling, LRD, ECE-by-slice — all about model *confidence*, none about instance-level *predictability of games*. The corpus has no IRT work and no rating-system work (Glicko appears only as "mentioned" in the metrics inventory). This paper's IRT gives GSE two new tools: (1) per-game difficulty/discrimination parameters — i.e., a data-driven answer to "which games are genuinely hard to call vs just noisy"; (2) Glicko-2 tournaments as an honest model-selection protocol across engine versions, replacing headline-accuracy comparisons that overweight easy games. Relates to the repo's matchup-difficulty thinking but is not duplicating anything.

## 11. GSE implementation spec
1. Define items = NFL regular-season games 2018–2025 (nflverse play-by-play/win outcomes), respondents = GSE engine versions (v5.2.7 and predecessors) plus baseline models (market-implied, elo, SP+). 2. Response matrix: did each model beat the game's ATS/ML closing line (binary right/wrong)? 3. Fit 3PL via R ltm or a PyMC reimplementation; estimate per-game difficulty b_i and discrimination a_i, per-model ability θ_j. 4. Interpret: high-difficulty games → archetypes (divisional games? weather? short rest? backup QBs?) via correlation with game metadata (spread, total, rest days, weather, travel) — mirroring the paper's metadata-correlation step. 5. Glicko-2 tournament over engine versions across seasons (each season = one rating period, True-Score = Σ win-probability of beating close) to rank models honestly. 6. Use difficulty estimates to size bets: reduce stake on games with high estimated guessing parameter (coin-flip games). Effort: 1–2 weeks (data is in-house; IRT fitting via existing R/Python packages).

## 12. Reproducible test
Dataset: NFL games 2022–2024 (nflverse), respondents = 5 candidate engine versions + market baseline, response = beat-the-close (ATS). Fit 3PL on 2022–2023, estimate per-game difficulty; test on 2024. Metric 1: correlation between per-game difficulty b_i estimated on 2022–23 vs 2024-only fits (temporal stability of difficulty — must exceed r=0.5 to be a real game property rather than noise). Metric 2: Glicko-2 ranking of the 6 models from True-Score tournaments vs ranking by plain ATS hit rate — report rank-order disagreement (Kendall's τ between the two rankings).

## 13. Acceptance / rejection gate
Adopt IRT-for-games as a GSE model-evaluation layer if (a) per-game difficulty is temporally stable (r ≥ 0.5 across disjoint season blocks) AND (b) the IRT ability ranking of engine versions matches the Glicko-2 ranking and both disagree with plain accuracy by at least one rank flip among the top 3 — i.e., the method demonstrably corrects an easy-games bias. Reject if difficulty estimates are unstable (r < 0.3) or if the "optimal anchor" check fails (a perfect-ATS model does not rank first in the Glicko tournament — then the tournament setup is broken, as in the paper's negative-discrimination case).

## 14. Improvement experiment
Replace binary ATS right/wrong with a graded response model (ordinal IRT): categories = beat close by >3 pts / beat close / miss close / miss badly — extending the paper's dichotomous 3PL to a polytomous model that credits *how much* a model beat the market, directly tying model ability to CLV magnitude rather than just hit rate. This turns the Glicko tournament into a money-weighted ranking, which is the actual GSE decision metric (the paper never connects True-Score to economic value).
