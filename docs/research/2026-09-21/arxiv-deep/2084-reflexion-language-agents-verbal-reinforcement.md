# [2084] Reflexion: Language Agents with Verbal Reinforcement Learning (arXiv:2303.11366v4)

**Citation:** Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao (2023). *Reflexion: Language Agents with Verbal Reinforcement Learning*. arXiv:2303.11366v4. URL: https://arxiv.org/abs/2303.11366
**Ledger completed:** 2026-09-22. **Read:** full text (ar5iv HTML, Sections 1–7, Tables 1–5).
**Verdict:** ADAPT — verbal reinforcement (binary backtest outcome → textual self-reflection → persistent memory) is the cheapest high-leverage improvement loop for GSE's executor agent; the memory-bound (Ω=1–3) and false-positive/false-negative asymmetry are directly portable design rules.

## 1. Research question
Can LLM agents learn from prior failures without gradient updates — by converting binary/scalar environment feedback into verbal feedback (a textual summary) that is stored as additional context for the next episode, acting as a "semantic gradient signal" that gives the agent a concrete direction for improvement? The paper positions this as verbal reinforcement learning, analogous to how humans learn few-shot by reflecting on failures.

## 2. Dataset / schema
- **AlfWorld:** 134 text-based household environments across 6 tasks (find/move/manipulate objects). Agent = ReAct; self-evaluation = either an LLM natural-language classifier or a hand-written heuristic (same action + same response >3 cycles, or >30 actions in an episode → self-reflect).
- **HotPotQA:** Wikipedia-based QA, 113k pairs; evaluated on 100 questions. Setups: Reflexion+CoT (6-shot) for step-by-step reasoning, Reflexion+ReAct (2-shot + Wikipedia API) for holistic QA, CoT(GT) with ground-truth context to isolate reasoning; exact-match grading gives the binary signal.
- **Programming:** HumanEval (164 tasks), MBPP, Rust translations via MultiPL-E, and the new **LeetcodeHardGym**: 40 LeetCode hard questions in 19 languages released after GPT-4's Oct 8 2022 cutoff. Test suites are self-generated by the agent (CoT → diverse tests → AST-validity filter → max 6 unit tests), so pass@1 reporting stays valid.
- **WebShop:** 100 customer instructions (Figure 6).

## 3. Method / model
Three distinct models (Section 3, Figure 2): **Actor** M_a (generates text/actions; CoT or ReAct, with memory `mem` as extra context), **Evaluator** M_e (scores a trajectory: exact-match for reasoning, hand-written heuristics for decision-making, or an LLM-as-judge for programming/decision tasks), and **Self-Reflection model** M_sr (an LLM that, given {trajectory τ_t, scalar reward r_t} and current memory, writes a nuanced textual summary of what went wrong and what to try — the verbal reinforcement cue). Process: trial 0 → evaluator score r_0 = M_e(τ_0) → self-reflection summarizes {τ_0, r_0} into sr_0 → appended to `mem`. Loop until the evaluator deems τ_t correct. Memory is split into short-term (trajectory history) and long-term (stored reflections), bounded by Ω (usually 1–3 experiences; 3 for AlfWorld/HotPotQA, 1 for programming) to respect context limits.

## 4. Equations & assumptions
Equations are the formal loop definition, faithfully: r_t = M_e(τ_t); sr_t = M_sr({τ_t, r_t}, mem); mem ← mem ∪ {sr_t}, |mem| ≤ Ω. (Rendered in the paper as r t = M e ​ ( τ 0 ) and s r t appended to mem.) Assumptions: the evaluator's scalar/binary signal is trustworthy enough to reflect on (the paper's own analysis shows this breaks under false positives — see Section 9); the LLM's self-evaluation/reflection capability is adequate; Ω=1–3 stored reflections suffice; temperature 0.7 for retry diversity on HotPotQA.

## 5. Features / target
Not a prediction paper. Inputs per trial: trajectory (actions, observations, error traces), evaluator score, memory of past verbal reflections. Output: the improved trajectory / final answer / passing program. Reported targets: tasks solved (AlfWorld 130/134), accuracy (HotPotQA), pass@1 (HumanEval/MBPP/LeetcodeHardGym).

## 6. Validation design
- AlfWorld: 134 environments; ReAct-only vs ReAct+Reflexion, cumulative solved over 12 consecutive trials; heuristic vs GPT self-evaluation variants; failure-reason classification (Figure 3b).
- HotPotQA: 100 questions; baselines ReAct-only, CoT-only, CoT(GT)-only run with retries but no reflection; episodic-memory (EPM) ablation vs full self-reflection.
- Programming: Table 1 pass@1 vs previous SOTA (CodeT+GPT-3.5, GPT-4); Table 2 confusion-matrix analysis of self-generated test suites (TP/FN/FP/TN); Table 3 ablation on the 50 hardest HumanEval-Rust problems (test generation × self-reflection, 2×2).
- Time-ordered splits: not applicable (benchmark-based, fixed tasks); LeetcodeHardGym is explicitly post-cutoff to avoid contamination.

## 7. Numerical results / baselines
(Exact quotes.)
- **AlfWorld:** ReAct + Reflexion solves **130/134** tasks (heuristic self-evaluation); ReAct-only plateaus between trials 6–7; ReAct-only converges at a **22% hallucination rate** with no long-term recovery; Reflexion "eliminates almost all" possession-confusion failures, learning additional tasks across 12 consecutive trials.
- **HotPotQA:** Reflexion improves over strong baselines by **22% AlfWorld / 20% HotPotQA / 11% HumanEval** (headline). Baselines (ReAct-only, CoT-only, CoT(GT)-only) fail to probabilistically improve at all — zero failed tasks from trial 1 are solved in later trials at temperature 0.7. CoT(GT) cannot correctly infer the answer for **39%** of questions even with ground-truth context; Reflexion corrects mistakes without GT access, improving accuracy by **14%**. Episodic-memory ablation: self-reflection adds an **8% absolute** boost over episodic memory alone.
- **Programming (Table 1, pass@1):** HumanEval Python: Reflexion **91.0** vs GPT-4 80.1 vs prev-SOTA 65.8 (CodeT+GPT-3.5). HumanEval Rust: 68.0 vs GPT-4 60.0. MBPP Python: 77.1 vs GPT-4 80.1 (Reflexion underperforms here). MBPP Rust: 75.4 vs 70.9. LeetcodeHard Python: 15.0 vs GPT-4 7.5.
- **Table 2 (test-suite reliability):** false-positive test-execution rate — probability the submission fails given all unit tests pass — is 16.3% for MBPP Python vs 1.4% for HumanEval Python (explains the MBPP miss); baseline pass@1 82% vs 80% but overall Reflexion accuracy 91% vs 77.1%.
- **Table 3 (ablation, HumanEval Rust hardest-50):** base model 0.60; test-generation omitted + reflection on = 0.52 (worse than baseline — reflection without grounded signal is actively harmful); reflection omitted + test generation on = 0.60 (no gain — blind trial-and-error debugging is ineffective); full Reflexion = 0.68.

## 9. Leakage & limitations
The paper's own Table 2/3 is the key adversarial finding: reflection is only as good as the evaluator — false-positive test suites cause premature "success" reports (16.3% on MBPP), and reflection WITHOUT a grounded signal scores 0.52 < 0.60 baseline (actively harmful). The authors note reflection has no formal success guarantee; memory is a crude sliding window (they recommend vector/SQL stores as future work); policy optimization in language can still hit local minima. For GSE: the evaluator is the whole game — a backtest-based evaluator with lookahead leakage would have the agent "reflect" on contaminated signal, i.e., confidently learn leakage. The binary-signal amplification idea transfers, but only behind a leak-proof evaluator.

## 11. GSE implementation spec
Adapt the Actor–Evaluator–Self-Reflection triad as the **executor harness** inside the ledger-2082 discovery loop:
1. **Actor:** the code-writing agent editing the nflverse backtest template.
2. **Evaluator (deterministic, not LLM):** runs the backtest; returns binary/scalar signal — e.g., "ΔBrier = +0.0011 on 2025 holdout, FAIL (< 0.002)" — plus structured diagnostics (which season folds failed, sample sizes, calibration slope). Deterministic evaluation sidesteps the paper's false-positive-test problem as far as possible; ALSO compute a test-suite-reliability check: re-run the backtest with the feature's sign flipped / on a permuted target — if the "signal" persists under permutation, flag the evaluator output as suspect (a sports-domain version of the paper's FP analysis).
3. **Self-Reflection:** an LLM call that takes {failed trajectory (code diff + backtest output), evaluator score, memory} and writes a 3–5 sentence lesson ("the pace interaction failed because 2025 holdout had only 41 windy games; next attempt: pool 2020–2024 windy games as training and test on 2025 only"), appended to a bounded memory (Ω=3, per the paper).
4. **Memory store:** SQLite table (the paper's suggested upgrade from a sliding window): (signal_id, trial, reflection_text, evaluator_score, embedding). Retrieved by similarity at the next idea-generation step.
5. **Effort:** 1–2 days on top of the 2082 harness (the evaluator exists already; add the reflection call + memory table).

## 12. Reproducible test
**Dataset:** nflverse 2015–2024 + 2025 holdout. **Protocol:** fix 10 candidate signal ideas (hand-written, known-difficult). Run the executor twice per idea: (a) with self-reflection + memory (Ω=3), (b) retry-only (reset and re-attempt up to 12 trials, no reflection — the paper's baseline design). Cap 12 trials each, mirroring the paper's AlfWorld budget. **Metric:** fraction of ideas reaching a passing backtest (ΔBrier ≥ 0.002) within budget; and mean trials-to-pass.

## 13. Acceptance / rejection gate
**ADOPT if:** reflection arm resolves ≥6/10 ideas within 12 trials vs ≤3/10 for the retry-only arm (the paper's signature gap: baselines solve ZERO new tasks on retry), mean trials-to-pass is lower in the reflection arm, and the permutation-based evaluator-reliability check flags ≥80% of deliberately injected leaky backtests (proving the evaluator is grounded — the paper's Table 2 lesson). **REJECT the reflection layer if** the retry-only arm matches within 1 idea, or the reflection arm shows the Table-3 pathology (reflection without grounded signal degrading performance — detected via the permutation check failing), or reflections duplicate each other (cosine similarity > 0.9 across trials → memory is not adding information).

## 14. Improvement experiment
Beyond the paper's sliding-window memory: implement **reflection consolidation** — every 5 trials, a summarizer distills the Ω stored reflections into one durable "doctrine" entry (e.g., "wind interactions need ≥40 games per fold; never trust single-season splits"), while raw reflections expire. Hypothesis: consolidation prevents the context-window bloat the paper hits (Ω=1–3 is a crutch) and creates a transferable playbook that improves NEW ideas, not just retries of the same one — test by measuring pass-rate on a second, disjoint set of 10 ideas with and without the doctrine available.
