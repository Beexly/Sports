# [0440] LEAP: Likelihood Elicitation and Aggregation for LLM-based Probabilistic Forecasting (arXiv:2609.01337v1)

**Citation:** Yufei Chen, Yiran Zhao, Xiaogang Xu, Qipeng Xie, Jiafei Wu, Zhe Liu (2026). *LEAP: Likelihood Elicitation and Aggregation for LLM-based Probabilistic Forecasting*. arXiv:2609.01337v1. URL: https://arxiv.org/abs/2609.01337v1
**Ledger completed:** 2026-09-21. **Read:** full text (PDF text extract, ~1300 lines incl. appendices).
**Verdict:** ADAPT — the LLM-forecasting domain doesn't transfer, but the core mechanism (LLM as local likelihood-parameter elicitor per evidence item + closed-form conjugate Bayesian aggregation + leave-one-out auditability) ports directly to fusing qualitative news evidence into GSE's quantitative engine.

## 1. Research question
The paper asks: given a fixed evidence set already collected by an agent loop, how should it be converted into a probabilistic forecast? It contrasts "Monolithic Prediction" (one LLM call reads all evidence and emits a point forecast — opaque, collapses uncertainty, prone to long-context forgetting/hallucination) against the proposed LEAP: use the LLM as a local interpreter that reports likelihood parameters per evidence item in isolation, then combine these through a deterministic Bayesian update with an explicit prior into a posterior distribution. It also asks whether the posterior's per-evidence leave-one-out contributions provide an auditable trail.

## 2. Dataset / schema
- Constructed benchmark (347 retained tasks after manual review/quarantine): 157 FutureX forecasting tasks (future-event prediction, single-choice/multi-choice/continuous), 99 GAIA information-seeking tasks rewritten into structured probabilistic tasks, 91 BrowseComp browsing tasks rewritten into single-choice. Output-type distribution: 266 single-choice, 29 multi-choice, 52 continuous. Separate 60-task diagnostic subset for ablation/calibration analyses.
- No training data; models are not trained or fine-tuned on the benchmark (evaluation-only manifest).
- Evidence collection: a ReAct-style agent loop (budget B=10 turns, research budget 6, ≤4 tool calls/round) using web search + page fetch with strict temporal isolation (all evidence timestamped ≤ tfreeze; models' knowledge cutoffs precede evaluation timestamps). Temporal leakage audit found no violations.
- Base models (hosted API inference, temp 0): DeepSeek-V3.2, Gemini-3.1-Flash-Lite, Claude-Haiku-4.5, GPT-5.4-mini, Grok-4.20-Fast. Second setting: LEAP as a probability skill over unmodified traces from four external agent CLI frameworks (DeerFlow, Hermes, OpenClaw, MiroFlow).
- Code: https://github.com/layingfish/LEAP (footnote in abstract).

## 3. Method / model
Two-stage decomposition: collection stage yields evidence set E={e1…en}; prediction stage maps (T,E)→forecast. LEAP's prediction stage: (1) Prior elicitation — parameters of P0 from historical data when available (e.g., recent market prices), otherwise one blind LLM call with no evidence (prompt forbids conditioning on evidence to avoid double-counting). For discrete tasks without a base rate, a uniform conservative prior. (2) Per-evidence likelihood elicitation — one isolated LLM call per evidence item (the call sees T and only ei; never other items or partial posteriors) returning a structured schema: for continuous targets a target-scale observation µi with σi from a fixed metadata map; for single-choice, qualitative support labels per option mapped to non-normalized likelihoods Li(k)=P(ei|θ=k); for multi-choice, support/opposition labels mapped to log-likelihood ratios. Reliability sampling: repeat the query R times; agreement shrinks likelihood magnitude toward uniform. (3) Safeguards: dependency clustering (canonicalize dependency keys → retain one representative per source group; only retained set R enters the update), outlier rejection for continuous targets (drop items with elicited mean >4 prior σ from µ0 when prior is data-derived). (4) Deterministic closed-form aggregation: tempered conjugate posterior update (Gaussian for continuous, categorical+softmax for single-choice, independent Bernoulli per option for multi-choice), global likelihood-strength η (default 1.0), evidence role weights wi∈[0.05,1.5]. Forecast is a direct readout (quantiles / normalized probabilities / Bernoulli marginals). Per-evidence contribution Δj = leave-one-out change (e.g., Δj = µpost − µpost^{(-j)} for continuous; signed shift in top-option probability for single-choice), reproducible by re-running the update on R\{j}. All mapping constants fixed before final evaluation; no hyperparameter search.

## 4. Equations & assumptions
- Task tuple: T = (q, tfreeze, τ, O) (eq. 1); evidence set E = {e1,…,en} (eq. 2).
- Bayesian model (eq. 3): θ ∼ P0(θ), ei | θ ∼ Pi(ei|θ) (i.i.d. conditional independence working assumption; dependency clustering partially addresses violations).
- Posterior (eq. 4): P(θ|E) ∝ P0(θ) ∏_{i∈R} Pi(ei|θ).
- Continuous (App. A.1): θ ∼ N(µ0,σ0²), L̃i(θ) ∝ N(θ;µi,σi²). Posterior precision τpost = τ0 + η Σ_{i∈R} τi; mean µpost = (1/τpost)(µ0τ0 + η Σ_{i∈R} µiτi) (eqs. 5–6), with τx = 1/σx². Forecast: quantiles of N(µpost,1/τpost). Contribution: Δj = µpost − µpost^{(-j)} (eq. 7).
- Single-choice (App. A.2): log πpost(k) ∝ α log π0(k) + η Σ_{i∈R} wi log Li(k) (eq. 8), softmax-normalized. Contribution: Δj = πpost(k̂) − πpost^{(-j)}(k̂), k̂ = argmax_k πpost(k) (eq. 9).
- Multi-choice (App. A.3): logit πpost(k) = logit π0(k) + η Σ_{i∈R} wi ℓi(k), ℓi(k) = log(ptrue_{i,k}/pfalse_{i,k}) (eq. 10); forecast fk = σ(logit(πpost(k))); contribution: Δj = Σ_{k=1}^{K} |πpost(k) − πpost^{(-j)}(k)| (eq. 11).
- Metrics (App. D.6): Accuracy = (1/N)Σi 1[argmax_k pik = ci] (eq. 12); Brier = (1/N)Σi(1/Ki)Σk(pik−yik)² (eq. 13); Spherical = (1/N)Σi Σk pik yik / √(Σk pik² Σk yik²) (eq. 14); NCRPS = min(1, CRPS/max(|v|,1)).
- Assumptions: conditional independence of evidence given θ (partially mitigated by dependency clustering); the LLM's local likelihood schemas are trustworthy signals (no calibration of the elicitation itself beyond reliability sampling); closed-form conjugate families suffice; temporal isolation of evidence holds.

## 5. Features / target
- Prior: historical time series (e.g., last 7 daily highs for price targets) or blind LLM base rate. No hand-crafted ML features; the "features" are the structured likelihood parameters elicited per evidence item: continuous — observation µi and metadata-mapped σi (Table 7: measurement_scope/observation_type/source_tier/strength/reliability/target_match/recency multipliers, clamped r∈[0.03,1.25]); discrete — support/opposition labels mapped via fixed table (Table 8: strong support for option k → Li(k)∈[0.70,0.95], strong opposition → ℓi(k)≈−1.735, etc.), plus dependency keys and evidence-role weights.
- Target: posterior distribution over θ — probability vector over K options (single-choice), K Bernoulli marginals (multi-choice), or quantile levels (continuous).

## 6. Validation design
Shared-evidence protocol: collection stage run once per task to produce one E; both Monolithic and LEAP applied to the same (T,E) — score differences attributed only to prediction-stage design. Two settings: (a) own ReAct loop × 5 base models; (b) LEAP as plug-in probability skill over 4 external agent CLI framework traces. Metrics: FutureX composite score (headline), Accuracy, Brier, Spherical, NCRPS; calibration diagnostics (ECE, Adaptive ECE, overconfidence = positive part of confidence−accuracy gap). Controlled comparisons: prior-matched Monolithic (same prior, one/two-sample), token-budget-matched Monolithic (two-sample mean), linear-opinion-pool aggregation baseline, likelihood-strength sensitivity (η∈{0.5,1.0,2.0}), evidence-grouping sensitivity (no/source-key/domain clustering), horizon-split analysis (7/30/60 days). Component ablation (remove prior, dependency clustering, reliability sampling). All cells averaged over N=5 independent seeds (median run-to-run σ≈0.010; ordering preserved in 48/50 cells).

## 7. Numerical results / baselines
- Cross-model (Table 1): LEAP improves FutureX for every base model — DeepSeek-V3.2 0.4895→0.6701; Gemini-3.1-Flash-Lite 0.6004→0.7069; Claude-Haiku-4.5 0.6211→0.6569; GPT-5.4-mini 0.6456→0.7222; Grok-4.20-Fast 0.6533→0.7503. Spherical gains 2.5–15.1 pts. NCRPS improves for all (e.g., GPT-5.4-mini 0.5413→0.0200; Gemini-3.1-Flash-Lite 0.4916→0.1419). Brier improved on 3/5 models (DeepSeek-V3.2: 0.2308 vs 0.2374, close).
- External frameworks (Table 2, macro-average): FutureX 0.4491→0.5471 (+9.8), Accuracy 0.3721→0.4186 (+4.7), Brier 0.4806→0.3157 (−16.5), Spherical 0.4712→0.6117 (+14.1), NCRPS 0.7598→0.6312 (−12.9). FutureX gains per framework 7.0–13.8 pts; Brier reductions 12.9–23.7 pts.
- Calibration (Table 6, diagnostic subset, GPT-5.4-mini): ECE 0.1840→0.0876 (halved), Adaptive ECE 0.1765→0.0912, overconfidence 0.3167→0.1500 (>halved).
- Horizon analysis (Fig. 3): FutureX gain rises 6.8→11.9 pts as horizon grows 7→60 days; overconfidence gap widens 13.3→23.3 pts.
- Ablation (Table 3): removing the prior drops FutureX below Monolithic (0.6427 vs 0.6512, ECE 0.2134) — the most important component; removing dependency clustering: FutureX 0.7284→0.7089, ECE 0.088→0.158; removing reliability sampling: FutureX→0.7136, ECE→0.1219. Full LEAP: FutureX 0.7284, Brier 0.2057, ECE 0.0876.
- Controlled baselines (Table 4): LEAP (0.7284/0.2057/0.0876) beats Monolithic+same-prior (0.6742/0.2510/0.1508) and Monolithic two-sample budget-matched (0.6736/0.2497/0.1471). LEAP (η=1.0) beats linear opinion pool (FX 0.7284 vs 0.6808, Brier 0.2057 vs 0.2389, ECE 0.0876 vs 0.1117; Table 5). Latency: LEAP 11,508 tokens/task, median 10.4s vs Monolithic 5,733 tokens, 6.2s.
- Source-wise (Table 14): gains hold on all three sources (FutureX/GAIA/BrowseComp), ECE 0.1010–0.1090 for LEAP vs 0.1600–0.2050 for Monolithic.
- Expanded AAPL case: prior P0=N(250.74, 7.5222²) from last 7 daily highs; outlier E12 (analyst target $190, z=8.07>4) rejected; posterior N(250.157, 5.7031²); posterior precision weights 57.5% prior / 20.7% E1 / 21.2% E5; LOO Δ: E5=−0.6727, E1=+0.1520, E8=+0.0680.

## 9. Leakage & limitations
- The evaluation only covers English tasks, fixed collection protocol, and 5–6 model families; generalization to other languages/domains/agents is unverified (authors state).
- Cost: LEAP needs many more inference calls (one per evidence item + reliability samples); main practical tradeoff (11,508 vs 5,733 tokens/task; p95 latency 27.8s vs 12.1s).
- LEAP cannot recover from bad upstream collection — sparse/outdated evidence just yields wider posteriors; it improves aggregation, not retrieval.
- The local likelihood elicitation itself is uncalibrated LLM judgment; reliability sampling only shrinks magnitude, and the fixed mapping constants (Tables 7–8) were "fixed before final evaluation" without per-task tuning — but also without any principled validation of their values.
- Conditional independence is a working assumption only partially patched by dependency clustering; domain clustering gave the best ECE (0.0798) but the authors default to source-key.
- Case studies (e.g., AAPL, Rugby Europe) are cherry-picked illustrative cases, not representative samples.
- External validity to NFL: the forecasting tasks are trivia/information-seeking/future-events, not sports; the transferable piece is the mechanism, not the benchmark results.

## 11. GSE implementation spec
Build a news-fusion layer on the engine's pick pipeline: (1) prior P0 = the quantitative engine's probability (or de-vigged market consensus) for the pick at freeze time; (2) collect a fixed evidence set per game (injury reports, beat-writer blurbs, weather updates, line-move notes) via the existing Grok-briefs pipeline, each timestamped ≤ lock; (3) LLM elicits per-item support/opposition likelihoods for {cover, don't cover} (single-choice, 2 options) — isolated calls, fixed mapping table à la Table 8, dependency clustering by source domain; (4) closed-form tempered Bayesian update (eqs. 8–9, η≈1) yields a posterior pick probability; (5) record LOO Δj per item for the audit trail shown with each posted pick. Training protocol: no training — mapping constants fixed; validate on 2024–2025 seasons. Serving: batch run once daily before locks; cost-bounded (one LLM call per evidence item, ~10 items/game, top-slated games only). Effort: ~2 weeks for the fusion layer + LOO audit trail, ~1 week to wire into the daily pick verification pipeline.

## 12. Reproducible test
Dataset: all 2024–2025 regular-season NFL games. Evidence set: Grok daily briefs + injury reports timestamped before kickoff (frozen corpus). Baseline: engine probability alone. Metric: Brier score and ECE on {cover} outcomes using the posterior vs the engine-only forecast; secondary: accuracy at the posted pick. Time window: 2024–2025 seasons, evaluated game-by-game with per-game evidence freeze. Ablate the prior (remove engine prior, uniform prior) to test the paper's finding that the prior is the load-bearing component.

## 13. Acceptance / rejection gate
ADOPT if on the 2024–2025 window the posterior achieves Brier improvement ≥0.010 over the engine-only forecast AND ECE improves by ≥25% relative (mirroring the paper's halving of ECE), with no accuracy degradation. ADAPT-fallback: if Brier is flat but overconfidence drops ≥30% relative with accuracy preserved, adopt as a calibration/auditability layer only. REJECT if Brier worsens on the test window, or if removing the engine prior performs comparably (meaning the LLM evidence adds nothing beyond the prior), or if per-game latency/cost exceeds $0.50/game without a Brier gain.

## 14. Improvement experiment
Beyond the paper: replace the fixed mapping constants (Table 8-style) with a learned calibration of elicited likelihoods — fit a per-source-tier shrinkage parameter on 2024 games by minimizing Brier of the posterior (a meta-calibration step), then evaluate on 2025. The paper fixes these constants a priori; learning them from outcomes should tighten calibration further and is directly analogous to source-quality weighting in news-fusion. Second direction: hierarchical evidence grouping by beat-writer beat (team-specific) rather than domain, mirroring the paper's domain-clustering ECE win, to model correlated reporter errors.
