## 2. What Is WRONG or Mis-Prioritized, and the Fix

| Issue | Why It's Wrong | Fix |
|-------|----------------|-----|
| **Lane 0 (Go Live) runs before Lane 3 (Gate) is built** | The forward prompt says "Lane 0 runs first" but Lane 3 (gate) is a prerequisite for *every* family's weight. The W4 champion uses 4 families (market, QB, Elo, injury) with *hand-set* weights ("shrunk"). This violates "wiring is immediate, weight is earned." | **Reorder:** Lane 3 (gate harness) must land *before* Lane 0 mints. The W4 champion should be the output of the gate, not a manual assembly. If Lane 3 isn't ready, Lane 0 publishes *unweighted* market-offset + raw signals with weight=0, and the gate assigns weights Sunday night. |
| **Pretraining (Lane 12) targets next-play EPA, not the downstream task** | Pretraining on "next play EPA, drive outcome, player stat line" with 1.28M plays sounds good, but the downstream test is "engine log loss with vs without encodings." This is a proxy gap: play-level prediction ≠ game-level calibration. The encoder will overfit play noise. | **Change pretraining objective:** Multi-task: (a) next-play EPA, (b) *game-level* win probability, (c) *player-game* stat lines. Use the replay's graded rows (2,300 games) as the supervised head. Freeze pretrained trunk; fine-tune only the game/player heads on graded data. |
| **CV fine-tune (Lane 16c) uses pseudo-labels from YOLO-World/Grounding-DINO on broadcast frames** | Broadcast frames have scorebugs, replays, camera cuts, compression artifacts. YOLO-World on this domain will produce noisy pseudo-labels → distilled student inherits noise. No human verification of 200 boxes is enough. | **Add a verification gate:** Before distillation, run teacher on 500 frames, *human-verify* 200 boxes (formation, route, coverage). Only distill if teacher mAP@50 > 0.75 on verified set. Otherwise, collect 1k human labels first (use CVAT, 2 hours). |
| **Madden ontology (Lane 17) assumes playbook source exists with usable terms** | "Founder has said one exists" is not a contract. EA playbooks are proprietary; community exports (Madden DB, MUT.GG) have inconsistent structure and no redistribution rights. The ontology may be unusable or illegal. | **Week 1 task:** Coding agent must *find and verify* the source, record license terms in `intelligence/ontology/madden/SOURCE_TERMS.md`. If no clean source, fall back to nflverse `participation` route+formation+concept clustering (unsupervised) as the coaching-scheme encoder. |
| **Lane 21 (Joint Distribution) is gated behind Lane 1, but Lane 1 replay has no props/DFS targets** | The replay harness (Lane 1) only grades ML/spread/total. The joint model needs props/DFS targets to train the player-share heads. Without them, the joint model is untestable on its core value prop. | **Extend Lane 1 replay:** Add prop targets (player yards/TDs from nflverse `player_game_stats`) and DFS targets (DK/FD salaries + actual fantasy points). Write all to replay table. Lane 21 tests on *all* targets. |
| **Lane 13 (Social/Cognitive) uses LLM extraction but no validation loop** | "50 hand-checked events" is a one-time receipt. Extraction drift (model updates, source format changes) will silently corrupt signals. No monitoring = silent degradation. | **Add continuous eval:** Weekly, sample 20 extracted events, human-label accuracy. If F1 < 0.85, alert + pause family weight. Log extraction confidence calibration (predicted vs actual correctness). |
| **Lane 22 (Line Movement Grader) uses post-mint movement as "low-variance learning signal"** | Line movement *after* mint is endogenous: the engine's own picks (if published at sharp books) move the line. This creates a feedback loop where the engine grades itself on its own footprint. | **Restrict to pre-mint movement only:** Use movement from open → T−90min (engine mint time) as signal. Post-mint movement is for *CLV tracking only*, not learning. |
| **Lane 24 (Live In-Game) uses pbp + CV but no market odds feed** | Live win probability needs live odds to calibrate. The plan has no live odds ingestion (only pre-game snapshots). Without live market, the engine cannot price live props or measure live CLV. | **Add live odds feed:** WebSocket from The Odds API or Kalshi (if available) for in-game lines. Ingest at 30-sec intervals. Live pricer = pre-game prior + live pbp/CV updates, calibrated to live market. |
| **Lane 26 (Decision Layer) uses fractional Kelly but no uncertainty shrinkage on p** | "Fractional Kelly on calibrated p with uncertainty shrinkage" is stated but not implemented. The calibration map (Lane 2) outputs point estimates. No posterior variance → no shrinkage → overbetting on low-n games. | **Lane 2 must output predictive distributions:** Use conformal prediction or Bayesian calibration (Dirichlet for multinomial, Beta for binary) to emit `p ± σ`. Decision layer uses `p_adj = p - k*σ` for Kelly fraction. |
| **Lane 28 families built "one per PR through G1–G3" but no prioritization** | 14 families listed, all equal priority. Some (travel/body clock, altitude) are computable in 1 hour with high PIT safety. Others (contracts, coaching changes) need legal review and NLP. Building sequentially wastes weeks. | **Prioritize by (PIT-safe × build_hours⁻¹ × expected_Δ):** 1) travel/body clock (computable, PIT-safe, 2h), 2) altitude (computable, 1h), 3) special teams (pbp, 4h), 4) officials (nflverse, 2h), 5) turnover luck (pbp, 3h), 6) venue/crowd (needs data), 7) contracts (legal review), 8) coaching changes (NLP), 9) public attention (API). |

## 5. The Single Change That Would Most Raise Accuracy in 30 Days

**Build the Joint Distribution Simulator (Lane 21) — but scope it to *game-level only* first: a bivariate points distribution (home/away) calibrated on nflverse pbp 2018–2024, emitting `p(home_score, away_score)` per game. Read ML, spread, total, team totals, halves, quarters off this one distribution.**

**Why this beats everything else:**
- Current engine: 1 graded row/game (ML) → 2,300 rows total. Calibration learns from noise.
- Joint model: 1 distribution → 250+ gradeable targets/game (every score combo, every half/quarter, every team total). Calibration learns from **~500k rows** (2,300 games × 200+ targets).
- Fixes market contradiction: ML/spread/total/props *cannot* disagree — they're marginals of one distribution.
- Enables real parlay/SGP pricing: correlation is model-derived, not assumed.
- The gate (Lane 3) can now test *every market* on the same holdout. A family that helps the joint model helps *all* markets.
- **Measured precedent:** The 20K review (§A1) calls this "the biggest single unlock." The plan already has the pbp data (1.28M plays), the drive simulator modules (2410.09068, 2601.07980), and the calibration harness (Lane 2).

**30-day execution path (no new data, no GPU):**
1. **Week 1:** Extract drive-level outcomes from nflverse pbp 2018–2024: start field pos, down, distance, score diff, time → drive result (TD, FG, punt, TO, safety, end of half). ~200k drives.
2. **Week 2:** Fit a drive simulator: multinomial logistic (drive outcome) + gamma (yards gained) + Bernoulli (turnover). Inputs: offense/defense EPA ratings (per-QB, per-unit), home, weather, time remaining. Calibrate isotonic on drive outcomes.
3. **Week 3:** Simulate 10k games per matchup: sample drives until time expires. Output `p(home_score, away_score)`. Marginalize → ML, spread, total, team totals, halves, quarters.
4. **Week 4:** Run Lane 3 gate on *all* markets simultaneously. Receipt: Δ log loss vs market close on ML/spread/total/team totals/halves/quarters, with paired CI. Promote if joint model beats market-offset champion on *pooled* log loss.

**No GPU needed.** Drive simulator is tabular (XGBoost / LightGBM / sklearn). Simulation is CPU-parallel (joblib). Calibration is isotonic (sklearn). All run on the laptop in <2 hours.

**If this works, the engine jumps from "parity with market on ML only" to "beats market on 10+ markets simultaneously with 100x more calibration data."** That is the step change.
