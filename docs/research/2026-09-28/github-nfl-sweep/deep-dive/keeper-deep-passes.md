## 1. cbratkovics/fantasy-football-ai (MIT)

Core: `ffai/features/asof.py`, `ffai/models/train.py`, `ffai/models/tiers.py`, `ffai/decision_lab/policy.py`. Production-grade fantasy projection pipeline: 15 base nflverse stats each get L1 / L3_avg / L5_avg / season_avg computed on a *shifted-by-one-game* series inside `groupby("player_id")` — lookahead leakage is enforced by construction AND by `tests/test_asof_no_leakage.py` on real data. Position-specific subsets (QB 44, RB 40, WR 27, TE 27 features). Training is frozen comparability: train 2019–22, validate 2023, test 2024; per position, RF (100 trees, max_depth 10) vs XGBoost (100, depth 6, lr 0.1) champion/challenger chosen by validation MAE; prediction intervals = validation residual 10th/90th percentiles added to the point (floor clipped at 0); drift reference = feature deciles globally + per week-bucket. Preseason tiers = StandardScaler→PCA(≥90% var)→GMM with BIC-selected k∈[4,12], evaluated by Spearman correlation of tier rank vs realized PPR/game. The decision policy (`policy.py`) is a *pure function* mapping decision-inputs to RECOMMEND/REVIEW/HOLD with a hard precedence chain (invalid→HOLD, <2 comparables→REVIEW, projection gap vs `min_projection_gap`, floor guardrail), and a content-hashed decision ID over canonical inputs for auditability.

**Portable idea:** port the as-of feature contract + leak test pattern into GSE's projection layer immediately — one `build_features(stats, targets)` function with the shifted-groupby invariant and a `test_asof_no_leakage.py` equivalent is the single highest-leverage antifragility move before any new signal ships, and it plugs straight into the total-signal doctrine's "backtest every rule" gate since rolling-origin refits (`fit_predict_for_week`) are already implemented there.
*Deeper verdict: confirmed, actually better than pass 1 — the decision-policy + receipt system is the differentiator.*

## 2. ryanpmcintire/nfl_py3 (MIT)

Core: `src/nfl_ats/graph_ratings.py`, `src/nfl_ats/modeling.py`, `src/nfl_ats/market_decomposition.py`, `src/nfl_ats/weak_signals.py`, `src/nfl_ats/experiment_runner.py`. ⚠️ **Contradiction on pass 1:** the "Bayesian team model" label is overstated — the team rating is a PageRank-style graph model (damping 0.85, half-life 8 weeks, offseason retention, ridge α=8, min 16 games) over a margin adjacency, i.e. prior-weighted shrinkage, not Bayesian inference. The cover model is plain sklearn: LogisticRegression (C=0.25, median imputation + missingness indicators, StandardScaler) or HistGradientBoosting (lr 0.04, 100 iters, 15 leaves), with a *time-ordered* 20% calibration split where the final fit trains on all rows but a Platt-style logit calibrator is fit on the holdout tail. Market decomposition fits ridge (α=10) on margin/spread/residual targets with mandatory feature-family attribution (every feature claims exactly one family) and a reconciliation atol of 1e-4. The real gold: `weak_signals.py` is a versioned signal registry (WEAK_SIGNAL_REGISTRY_VERSION=1) with a binding AGENTS.md rule — "an interval containing zero is NOT grounds for rejection; only resolved wrong sign, zero split-half reliability, or a proven positive control may close a line of work; everything else is `unresolved_below_power`" — and `experiment_runner.py` (3,704 lines) runs agentless experiments from JSON specs (20,000 default samples, block-bootstrapped over week/season, split-half reliability method).

**Portable idea:** adopt the weak-signal registry schema + closing rule verbatim into GSE's signal intake — it is the exact operational form of the total-signal doctrine (ingest everything, kill nothing on thin evidence, record sample blocks and probability-positive) and gives the fleet's rule backlog (TRIGGER→AFFECTED→DIRECTION→MAGNITUDE→LOG) a provenance contract with effect units already enumerated (ats_points, brier, log_loss, …).

## 3. chmoses98/nfl-edge-finder (no license)

Core: `nfl_edge/sim/simulate.py`, `nfl_edge/arms/crn.py`, `nfl_edge/engines/joint.py`. (No license — method described, code not copied.) The Monte Carlo engine draws every game on one shared row index so margin, total, team plays, game script, Dirichlet-multinomial player opportunity allocation (with questionable players sitting out on exactly the rows their availability draw fails), per-touch outcomes from empirical efficiency banks, and TD reconciliation all cohere — enforced invariants include sum of player carries == team rush attempts, QB yards == sum of receiving yards, every count a non-negative integer. The CRN arm (`arms/crn.py`) draws all randomness ONCE per (snapshot, game) as uniforms and pushes them through each line-center's logic, so A/B tests of two centers differ only by center, not by Monte Carlo noise; challenger centers are snapped to the half-point grid because the residual bank's weights key on fractional class. The joint engine refuses to price composites by multiplying marginals: every leg of a composite must be evaluated as an indicator AND across the SAME draws of one simulation, else it returns JOINT_MODEL_REQUIRED. ⚠️ **Minor correction to pass 1:** the CRN arm's docstring references **40,000 draws** (±0.5pp on a coin-flip contract), not 20,000.

**Portable idea:** implement the CRN shared-draws discipline for GSE's DFS payout simulator and parlay pricing — evaluate every candidate lineup/parlay leg against one shared simulation batch so comparisons are variance-free; this is what makes `payout-sim.ts`'s simulated-field comparisons trustworthy and is a strict prerequisite before any "stack double-stack is 39.5% of top-100" claim ships as a rule.

## 4. mtsilverstein/Megatron (no license)

Core: `src/ffmodel/model/net.py`, `src/ffmodel/model/dataset.py`. (No license — method described, code not copied.) Encoder-only PyTorch transformer: input is a player's previous 16 games (left-padded, most-recent-last, strictly prior games only, leak rules inherited from a shared features module) projected to d_model=96, plus a never-masked target-week context token (is_home, rest_days, week, games_prior, opponent-allowed last-4/season, position one-hots), learned positional embeddings, 3 TransformerEncoderLayers with 4 heads and norm_first, and a head outputting 11 stats × 3 quantiles (p10/p50/p90) trained with pinball loss, with per-stat head weights to stop yardage heads dominating TD heads; outputs are re-sorted along the quantile axis so p10≤p50≤p90 always holds. A Poisson-NLL log-rate mean head shares the trunk because "median(sum) ≠ sum(medians)" — fantasy points are linear in components, so the engine needs E[points] = Σ w·E[X]. Scaler is fit on non-padded entries only, padded tokens zeroed post-scaling, rookies with all-padding history still yield finite predictions via the unmasked context token.

**Portable idea:** add the never-masked context-token pattern to any GSE sequence model so rookies/zero-history players (the DFS-process-system's noted edge cases) get finite predictions from target-week context alone, and pair any quantile head with the Poisson mean head — GSE's DFS optimizer needs expected points, not medians, and this is exactly how to get both from one trunk pass.

## 5. mattleonard16/nflalgorithm (MIT)

Core: `confidence_engine.py` (229 lines). The full mechanism: four 0–100 sub-scores — edge (`edge_pct/0.25` capped), stability (`(1 − σ/μ)·100` from CV, defaults 50 on bad input), volume (`target_share/0.30` capped), volatility (100 − volatility_score) — combined with weights from config (defaults: edge 0.35, stability 0.25, volume 0.20, volatility 0.20) into a 0–100 score, tiered Premium≥90 / Strong≥75 / Marginal≥60 / Pass<60, with a `filter_by_confidence(df, min_tier=2)` bulk-scoring API. All inputs NaN-safe with sane defaults; the frame is never mutated.

**Portable idea:** drop this in as the GSE pick-posting gate for @GalaxySportsHQ — it maps 1:1 onto the 9.2 Hold floor and the "post the card" workflow: score every engine pick with this exact formula (edge vs CLV, stability from prediction-interval width, volume from target/carry share), publish only Strong+, and log the sub-scores so the X engagement mandate has "the numbers disagree with other analysts" receipts built in.

## 7. jlattanzi4/nfl-survivor-optimizer (MIT)

Core: `pipeline/optimizer.py` (74 lines), `pipeline/simulate.py` (125 lines). Path optimizer objective: maximize Σ_weeks [log p − λ·log fs], where p is the pick's win probability and fs = expected fraction of the field surviving that week *given the pick wins* (own pick-share + Σ others share·p); λ=0 maximizes pure win-out probability, λ=1 maximizes the product of weekly pool EVs (SurvivorGrid's EV), rewarding contrarian picks. Assignment solved exactly by the Hungarian algorithm (scipy `linear_sum_assignment`) over a weeks×teams cost matrix — plus a `-1e3` cost hack for forced picks. The companion Monte Carlo field simulator uses common random numbers: the field's trajectory is drawn once and every candidate path scored against the same outcomes; the field picks proportional to pick shares with Binomial(alive, Σ share·won) draws for small-pool variance; supports multi-life pools (strike buckets) and split-pot payouts (1/S survivors, or that week's entrants split if all lose). A JS port in `docs/js/` is parity-tested against the Python.

**Portable idea:** the λ-dial is the generalizable mechanism — GSE's DFS optimizer already has `exposure-control.ts` and `payout-sim.ts`; add an explicit contrarian-dial λ to `diversePool` that trades off pure win-probability vs field-survival-weighted EV, calibrated against the DK ownership barbell (one sub-5% slate-breaker) from the 2026-09-25 GPP research.

## 8. sportsdataverse/nfl-ngs-raw (no license)

Core: `python/ngs_raw/fetch.py`, `python/ngs_raw/store.py`, six `ngs_0N_*_scrape.py` entry points. (No license — method described, code not copied.) Method: the NGS public API (`nextgenstats.nfl.com/api`) takes no auth — the entire HTTP contract is a same-origin Referer plus a browser User-Agent; pacing is env-var-only (sleep after every attempt, success or not, default 0.25s; 4 retries on 408/429/5xx including 503). Six endpoint scrapers cover schedules, teams, statboard, leaders, gamecenter, and highlights; raw JSON lands in a date-partitioned tree via atomic tmp+rename writes; validity is data-derived (a file existing doesn't count — 3,347 empty `{}` payloads once blocked a refetch, so `has_rows` checks the envelope's record lists, and pre-2016 statboard answers with empty category lists are detected via an any-list-nonempty sentinel).

**Portable idea:** for Garrett's NGS mega-research program this is the canonical acquisition pattern — raw-first, validity-by-content-not-presence, and the "pace after every attempt including successes" rule are directly reusable for the 48-post @NextGenStats profile inventory continuation and any new NGS endpoint the program adds; the empty-envelope sentinel should be adopted as a standing data-QC rule in the Sports repo.

## 9. sumedhk0/PanopticPigskin (AGPL-3.0)

Core: `nfl_gsplat/calibration/{field_detect,joint_solve,decompose_homography}.py`, `docs/RULERS.md`. (AGPL-3.0 — study only; method described, no code reproduced.) Method: broadcast camera calibration from field geometry alone — detect painted markings per frame (yard lines via HoughLinesP with length gates measured against the short side so portrait frames don't break, hash ticks as bright connected components with players masked), map detections to world coordinates on the z=0 plane, decompose the field→image homography into (K, R, t) with a relative-conditioning gate (absolute gates blow up because H carries arbitrary scale — measured: a 0/0 blowup averaged 1.14e6 in and shifted focal 2600→1990), then a multi-frame joint solve with a shared camera center via scaled least-squares (center in meters, rotation in hundredths of radian, focal in thousands of pixels — solving all three at unit scale stalls), initialized from a multi-start grid of plausible camera positions. Quality is judged by "rulers" computed from renders, not from the tracks underneath: census error (|drawn−11| per team), steps, hops, root/joint jitter, hinge angles, pelvis-acceleration surges — and critically, pose is scored by reprojection into the camera that did NOT fit it, defeating depth ambiguity.

**Portable idea:** the two ruler doctrines are directly importable to GSE's movement/video lane — (1) judge every tracking/rendering change on numbers read from the *render*, never the internal tracks; (2) always validate pose/placement in a held-out camera view — plus the conditioning lesson: gate homography decompositions on relative conditioning, never absolute values.

## 10. Twoos123/draftkings-live-odds (no license)

Core: `cmd/dkfeed/main.go`, `internal/dkfeed/client.go`. (No license — method described, code not copied.) Method: subscribes to DraftKings' public New Jersey push websocket (`sportsbook-ws-us-nj.draftkings.com/websocket?format=json&locale=en`) with a JSON-RPC `subscribe` on entity "events", filtered to NFL (`leagueId eq '88808'`), all markets except SportcastBetBuilder, `initialData: false`, sportsbook projection. Frames arrive as add/change/remove deltas on events/markets/selections with display odds; the client instruments both wire latency (DK socket sent → received) and trading-system latency (created → received) plus clock-offset sync against DK's clock, with keepalive ping/pong and a 10s subscribe-ack timeout; the reference implementation reports ~0.2s end-to-end with parse medians in microseconds.

**Portable idea:** this is the live-odds feed GSE's DFS/pick'em wiring has been missing — the subscription shape (entity events + league filter + delta updates + latency instrumentation) is directly portable to a Go or Python collector feeding GSE's market-updated model and the CLV/line-movement tracking; the wire-vs-created latency split is the right metric for the feed's health dashboard, and it resolves "register live DFS slate provider" needs on the odds side.
