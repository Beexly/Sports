## What the `signals` writer cost, and what it bought

`signals` had **0 rows, no writer anywhere in the repo, and no reader**. Spec item 4 is the prop pipeline's fuel and none of it existed. Every row is a measured column off the four tables the census already reads; `value` is stored verbatim with `valueRaw` retained; upsert on the schema's unique tuple so re-runs converge. It does **not** weight or rank — a weight is a prior, and inventing priors would fabricate the ranking the tuner is meant to measure.

**Three bugs, all found by running it, none visible by reading it:**

1. Every upsert failed: `Argument 'fetchedAt' is missing`.
2. First live tick: **504**. One row at a time over ~71k candidate rows. Fixed with a wall-clock deadline — safe only *because* every write is an upsert, so the next run resumes and converges.
3. **200 proves nothing.** I added the read surface, because an empty table and a full one looked identical from outside — which is precisely the condition that let this table sit empty for the life of the project.
