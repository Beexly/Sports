## 3. PRODUCT DEFINITION — locked

**Galaxy Sports Edge is an NFL-first product that publishes three things:**

1. **NFL player props** — the validated model, graded against posted lines (Phase 3).
2. **Market-anchored NFL game probabilities** — the engine shrunk 90% toward the market, with published calibration and a vig-free exchange reference. Sold as *calibration*, never as edge.

## 4. THE FACTOR FOUNDRY — how "ten things worth 0.2%" becomes real

Your standard is right and it was unmeetable under the old process. A 0.2% improvement is invisible one-at-a-time against 52.4% and invisible in training score against anything. It is visible in exactly one place: a joint model, scored once, on data it never saw. This is the machine that does that, and it is the only way an idea gets into or out of the product from now on.

### 4.1 One spec per hypothesis — `docs/factors/<id>.yaml`

```yaml

hypothesis: A WR/TE targeted more when playing on/near his birthday or against a team that cut/traded him.
estimand: residual target_share vs the player's trailing-5-game baseline, pooled, cluster-robust by player
unit: percentage points of target share
data: [nflverse.rosters(birth_date, team history 2017-2024), nflverse.player_stats(target_share)]
discover_era: 2017-2020
validate_era: 2021-2024
kill_line: "validate-era effect <= 0 or 95% CI includes 0 with n >= 300"   # written BEFORE the script runs
mde_80pct_power: null    # filled by the script from the realised n
script: scripts/factors/A1.mjs
status: UNTESTED         # UNTESTED | CANDIDATE | LIVE | DEAD | BLOCKED
number: null             # the validate-era point estimate
ci: null
n: null
run_sha: null            # must postdate the commit that wrote kill_line
run_at: null
blocked_on: null         # named dataset when status is BLOCKED
notes: >
  Components already measured separately on YARDS (F6): birthday ±3d +1.11 yds p=0.57 (dead);
  former team +2.01 yds n=336 p=0.11 CI[-0.72,+4.73] (unresolved, power to +3.0). The
```
