## Correct core method

The object is **which fourth-down action maximizes win probability**, not whether absolute WP exceeds 0.5. A first-down-only, monotonic-constrained XGBoost WP model is combined with fourth-down transition models: regression for punt destination; logistic regression for field-goal/conversion success; conditional regressions for yards gained on successful/failed conversions. The latter use expected destinations rather than full transition distributions, an explicit approximation (sections 2.3–2.5).

Section 3 resamples **games, then drives within games**, with replacement (randomized cluster bootstrap), and discusses fractional-bootstrap tuning to address undercoverage. Each replicate refits the full decision model. It reports **boot%**, the fraction of replicated argmax decisions agreeing with the original action, plus percentile intervals for the WP *difference between actions*. It does not just bootstrap predictions from a fixed model. B=101 is chosen by a stability analysis (Appendix C: mean category stability 0.9). The text warns that even cluster bootstrap intervals can undercover; neither nominal coverage nor optimal decisions are proven universally.

## Exact reported results

- Section 3: **600,825 plays; 229,635 first-down plays**. Section 2.4's model contest uses **2006–2021**, a random 50% game-level test split; the remaining games are split for training/validation. This is game-disjoint, **not a chronological deployment backtest**.
- Table 1, printed out-of-sample log-loss / printed reduction versus fair coin: proposed first-down XGBoost **0.440 / 36.54%**; all-down Random Forest **0.446 / 36.50%**; Baldwin XGBoost **0.476 / 31.27%**; pre-game spread logistic regression **0.609 / 12.10%**; fair coin **0.693 / 0%**. **Source inconsistency:** the RF printed reduction does not match its displayed log losses: `(0.693-0.446)/0.693*100 = 35.6421%`, calculated locally. Preserve the printed table rather than silently fixing it.
- Section 4.1, Patriots–Colts example: point estimate favors Go over FG by **1.1 percentage points**; **44%** of bootstrap models instead favor FG; **90%** gain interval **[-4%, 5%]**.
- Section 4.2 classifies boot% as confident **[83%,100%]**, lean **[67%,83%)**, uncertain **[0%,67%)**. These are communication buckets, not 95%-confidence decision thresholds.
- Across 2018–2022 fourth downs: **44%** have estimated WP gains below 1 pp; **87%** below 4 pp; only **48%** are confident and **27%** uncertain. About **20%** of sub-1-pp decisions and **50%** of 1–2-pp decisions are confident.
- Among confident decisions, coaches selected the recommended action on **91%** of kick recommendations but only **49%** of Go recommendations. Uncertainty does **not** reverse the overall finding that coaches are too conservative.

## Dossier / Build Plan corrections

**Ranked by Relevance row 43 (High):** its broad uncertainty summary is accurate; the claim that this is a near-exact foundation for GSE confidence caps is an adaptation, not a validated transfer. The paper's boot% is decision stability, not a capped forecast probability.

Compared against `live-export.json`, **Grok 58 Dossiers row 43**, and **Build Plan row 26**:

1. Dossier “do not lock a pick whose **95% interval crosses 0.5** (or market implied p)” is **not the paper's rule**. It studies action-relative WP gain, boot% categories and illustrated **90%** intervals. Absolute 0.5 has no universal betting meaning; any betting adaptation must use the executable price's break-even probability and relevant costs, not a generic threshold.
2. “Challenges maximize win probability” is overbroad: it challenges maximization of an uncertain **point estimate**, not the objective of winning. It still estimates and compares WP across actions.
3. “CIs include punt” is loose shorthand; intervals are on numeric WP gain, while discrete action disagreement is captured by bootstrap counts.
4. Build Plan's **1,000 resamples / require 95th percentile Brier and ECE below launch floors** is a proposed GSE governance experiment, **not a reported paper algorithm or validated gate**. No paper evidence establishes that repeated windows are independent or that this gate yields a specified launch error rate.
