2. **Mislabelled output.** `bookmakerFor()` returned `title: "Caesars (Action Network)"` for a
   DraftKings line — false in any UI disclosure, ledger row, or attribution.
3. **`?bookIds=15,30` requests Consensus + Open** — the two synthetic aggregates — the opposite of what

**Note the failure class, it generalises — and there was a live test that "covered" this and missed.**
`src/__tests__/action-network-live-smoke.test.ts` is a real network test against this very module, and
it would **not** have caught the book-id error:
1. Its hardcoded expectation comment (line 20) reads *"attached with Caesars/BetMGM/FanDuel"* — i.e.

2. It asserts only `book.key =~ /^action_network_\d+$/` and that *some* market exists — it **never
   asserts which book**. A Caesars label on a DraftKings line satisfies it.
3. Its failure branch logs "acceptable soft miss" and **still passes**, so a total network failure and
   a correct success are indistinguishable from the outside. That is worse than no test, because it
   reads as coverage.

So the transport *was* verified (HTTP 200, byte count, game count — all correct and still correct), and
the *meaning* was not — and the one test positioned to catch it asserted the false label instead. A
live check that does not assert semantics can pass forever while being wrong. If you touch this area,
add an assertion on the **book identity** (e.g. resolved `source_name`), not just on shape.
