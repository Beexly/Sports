## Cadence

**Primary cadences are not restated here.** This file used to carry a
hand-maintained cadence table; it drifted from `apps/web/vercel.json` and stayed
wrong for months while this same file said "do not hand-edit schedules". Read the
live values instead:

- Every Vercel schedule → [`CRON_MATRIX.generated.md`](./CRON_MATRIX.generated.md),
  regenerated by `node scripts/ops/cron-matrix-from-vercel.mjs`.
- Backstop schedules → the `on.schedule` block of `.github/workflows/external-cron.yml`,
  which carries a per-entry comment naming the job each cron fires.

Which jobs have a scheduled backstop at all (as opposed to `workflow_dispatch`
only) is the one fact worth stating, because it is not derivable from either file
alone — the workflow defines more jobs than its schedule triggers:

| Job | Scheduled GH backstop? |
|-----|------------------------|
| settle-picks | yes |
| free-spine-health | yes |
| refresh-player-stats | yes |
| autonomy-cycle | yes |
| board-fill | yes |
| generate-signal-slate | yes |
| refresh-odds · health-alert · calibration-metrics · backfill-independent-trueprob | no — `workflow_dispatch` only |

**I8:** free-spine durable SLA = **120 minutes**. Verify the margin against the two
files above rather than trusting a number here: as of this writing the Vercel
primary and the GH backstop both run on a 2-hour cycle offset by 5 minutes, so
worst-case snapshot age sits at the SLA boundary with almost no margin. Widening
either cadence breaches I8 immediately.
