# Tool runs — the four that were filed and never executed

2026-10-28. CloakBrowser, maigret, sherlock and github-dorks were all given a verdict in the
repo vetting without ever being run. This is what happened when they were.

## CloakBrowser — the one that paid

Installed and tested. **Clears PFR headless in 6.9 s with no wall shown at all (448,776 bytes),
and whoscored — 403 to curl — in 6.6 s. 2/2.**

That is the thing patchright cannot do: headless patchright fails the interstitial, which is why
the wall-clear was headed-only. CloakBrowser passes it because fingerprints are patched at C++
source level rather than injected at runtime.

Free tier, no key, no account. It downloads its own Chromium (146.0.7680.177.5) to
`~/.cloakbrowser/`. Backend order in `wall_clear.py` is now cloakbrowser headless, then patchright
headed as fallback. Forced solve on PFR went from 51–67 s headed to 12.5 s headless.

Caveat: the binary is downloaded and unsigned by anything we control. Provenance is still
unaudited — it runs, that is all that is established.

## maigret — runs, unreliable here

Installed, ran against `AdamSchefter` over the top 120 sites:

```
[!] Too many errors of type "Request failed" (76.92%)
Search by username AdamSchefter returned 1 accounts.
```

One account (a TikTok mirror) and 77% request failures. So it works but is not usable as-is from
this IP without proxy or retry tuning. `--cloudflare-bypass` exists and was not tried.

## sherlock — not run

maigret is the superset and it underperformed, so sherlock was skipped rather than spending the
same request budget on a weaker tool. Recorded as skipped, not as passed.

## github-dorks — CLI broken in local mode, dictionaries good

`pip install github-dorks` does not exist; it must be cloned. It then needs `feedparser` and
`github3.py`, neither declared in a way pip resolves. With both installed, `-l <path>` local mode
runs silently and produces an empty report — a real bug, not a config error.

The **dictionaries are the useful part** and they work fine fed to `gh search code` by hand: 196
dorks across ten categories (`private-keys`, `cloud`, `identity`, `saas`, `databases`, `devops`,
`frameworks`, `observability`, `ai`, `system`).

`gh search code` itself is strict — multi-term queries return nothing, single-term queries work.
A sports-targeted dork sweep needs single-term dorks, which the shipped set mostly is not.

## What this changes

- CloakBrowser: concept-adopt → **adopted and wired**. It is now the primary backend.
- maigret: reference-only stands, but with a measured caveat rather than a guess.
- sherlock: still unrun, deliberately.
- github-dorks: concept-adopt downgraded to **dictionaries only** — the CLI does not work locally.

## Open

- CloakBrowser binary provenance unaudited.
- maigret needs a proxy or `--cloudflare-bypass` before it is worth a real sweep.
- No sports-specific dork set exists yet. The shipped categories are generic.
