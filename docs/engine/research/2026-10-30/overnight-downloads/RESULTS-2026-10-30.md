## 0. Verdict

**KILL — Laya does not earn a shadow-mode seat (design §5.2). The experiment is complete and the result is a clean, honest negative.**

Laya, zero-shot, does not gate — it ratifies. Across all 3,081 candidates it issued **3,077 PASS / 4 REJECT / 0 ABSTAIN** (median `should_pass` probability = 1.000; 99.2% of rulings ≥ 0.90). Its passed set is the whole set: mean **−0.0873 u/pick** on Tier A, statistically indistinguishable from passing everything (−0.0859). Two independent pre-registered kill conditions triggered:

- **§5.2.1** — passed-set mean units ≤ 0 (−0.0873; cluster-bootstrapped 95% CI [−0.183, +0.012]).
- **§5.2.2** — ECE 0.407 (> 0.10) with extreme top-bin overconfidence: it asserts ~0.95+ confidence on candidates that realized "good" only ~55% of the time (top-bin gap +0.40). This is the exact failure the corpus warned about in October — schema-valid rulings delivered "with a confident face," calibration inverted from reality.

It also failed 12 of the 17 §5.1 seat checks. This is **not** INCONCLUSIVE: the confidence interval is not the problem — the point estimates sit at pass-all level with a 99.6% false-pass rate. Per the design's own terms, the verdict is on *this checkpoint, for this task, on this data*; the eval set and harness remain the standing test for the next candidate (see §6).

## 2. What ran, exactly (methods — read before citing any number)

- **Arm executed:** Arm 1 (Laya local, zero-shot) + Arm 2 (pass-all) + Arm 3 (edge-threshold rule) scored through the identical harness. Arms 4 (Verdict backend) and 5 (hosted Jev/Codiv) were not run: Verdict is a separate proprietary-lineage checkpoint with no local package on this host, and no Codiv/hosted credential exists in this environment. Neither arm is required for the §5 verdict, which is defined on Arm 1 vs the baselines.
- **Serving path (documented deviation from the design's letter, not its substance):** the design named Openjev's `laya-1.0` backend as the serving route. Openjev's flagship self-host requires an NVIDIA GPU ≥24 GB VRAM; this host has no GPU (2 vCPU @ ~1.5 GHz, 7.9 GB RAM). The arm was instead served by the model's own PyPI package (`laya` 0.4.17, `Router`, checkpoint pinned to `convaiinnovations/laya` — the same English 421M ModernBERT checkpoint Openjev wraps; checkpoint file sha256 verified against its HF blob hash `891102d3…`). Identical states, identical three typed questions (`should_pass` Noul, `quality_score` Score over 5 labeled levels ×25 → 0–100, `primary_risk` Choice from the design's fixed list), identical frozen decision rule (PASS ≥ 0.50, REJECT ≤ 0.35, ABSTAIN between). Cross-path consistency was verified: PyTorch Agent and Router return identical probabilities on the same states (e.g. 0.9596 on state E1-0001 under both).
- **Precision:** served with the package's own CPU autocast knob (`LAYA_CPU_AMP=bf16`) after measuring fp32 impractical on this host (11.3 s/state → ~9.7 h). bf16 measured 5.0 s/state. **Drift check:** bf16 vs fp32 `should_pass` probabilities on 16 states — max |Δ| 0.0022, mean |Δ| 0.0010. Immaterial against the frozen 0.35/0.50 boundaries; a boundary-sensitivity count is reported in §3.
- **Tokenizer re-count (design §3 requirement):** states re-counted with the checkpoint's actual tokenizer (HF repo `tokenizer/` subfolder): **max 184 tokens, mean 102** over all 3,081 states — the design's chars/4 estimate (≤152) understated slightly; every state is far under the 700-token target and the 800-token hard refusal cap. Zero states refused; zero states anywhere near Laya's 1,024-token silent-truncation limit.
- **Truncation canaries (design §3):** 3 sentinel pairs — a real Tier A moneyline state, and the same state with a decisive void fact appended at the very end ("…this candidate was voided before publication because its quoted price was stale. A voided candidate must never pass the publication gate."). **All 3 pairs passed under the run's own bf16 configuration:** base P(yes) 0.957–0.961 → tail P(yes) 0.111–0.137 (drops ≈ 0.82; ruling flips PASS → REJECT on every pair). The model reads the end of the state; no tail-blindness. (Also replicated under fp32: tails 0.111–0.140.)
- **Library warning observed (recorded verbatim):** on load, the package warns: *"this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated."* The clamped entry is a **choice** bucket (the diagnostic `primary_risk` question). The scored confidence in this eval is the **noul** probability, which the warning does not name. Recorded here because it is the vendor's own calibration caveat for this checkpoint.
- **Scorer validation:** before any model output existed, the scorer (`score.py`) was fed synthetic pass-all rulings and reproduced the 2026-10-15 deterministic-arm results to 4 decimals (pass-all pooled −0.0859 u/pick; edge-rule passed mean −0.1249, false-pass 0.5212, false-reject 0.6084, passed-spread beat-close 0.4453; Tier B pass-all win rate 0.5480). The scoring side of this run is therefore the same instrument as the October partial run.
- **Inference failures:** **zero.** All 3,081 states produced valid typed rulings (3,081 ruling records, 0 error records, run exit 0). Total wall time ≈ 4.4 hours on this 2-vCPU host (≈2.8 s/state on Tier B's short states, ≈5.0 s/state on Tier A's, after model load).

## 3. Full metrics and failure anatomy

**Ruling distribution (the whole story in one line):** PASS 3,077 · REJECT 4 · ABSTAIN 0. `p_yes` percentiles: p1 = 0.906, p5 = 0.943, **median = 1.000**, p99 = 1.000. The frozen abstention band (0.35–0.50) never fired once in 3,081 rulings — this checkpoint's probability mass lives at the extremes (~1.00 or ~0.10), so the design's three-way decision rule collapses to a coin it almost always lands on PASS. **H2 (abstention informativeness) is therefore untestable on this run**, and the §5.1.6 H2 check is recorded as failed-by-vacuity rather than passed or refuted: a gate that never abstains has no uncertainty signal to grade. (Kill 5.2.3, "abstentions realize better than passes," is likewise vacuous — not triggered.)

**The 4 rejections were mostly wrong.** E1-0091 (ML, p = 0.209, realized +0.290u), E1-0167 (ML, p = 0.095, realized +0.253u), E1-0540 (SPREAD, p = 0.336, realized +0.909u), E1-0168 (SPREAD, p = 0.101, realized −1.000u). Three of its only four acts of discrimination removed winning picks.

**It is not echoing the engine.** Tier B correlation between Laya's `p_yes` and the engine's own stated probability is **−0.342**; Tier A correlation with the bridge probability is −0.078 and with model-vs-market edge −0.032. Nor is it keying on the features a gate should use. The canary pairs prove the mechanism *can* reject — an explicit "this pick was voided" fact drops it from 0.96 to 0.11 instantly. What it lacks is any working discrimination of pick quality from ordinary pre-game state: every plausible-looking candidate is a 0.96+ pass. On Tier B's thin states it is, if anything, anti-correlated with reality (AUC 0.437).

**`quality_score` is no better.** AUC vs realized quality: 0.523 (Tier A), 0.498 (Tier B — chance). Mean quality score for realized-good Tier A picks: 63.0; for realized-bad: 62.4. The secondary signal carries nothing the primary doesn't.

**`primary_risk` diagnostics.** On Tier A's 258 false passes, Laya named `market_already_prices_it` 157 times and `none` 95 times — it frequently *names the correct risk and passes anyway*. On all 2,511 Tier B rows it answered `none` — with thin state it sees no risk anywhere, ever.

**Boundary sensitivity (bf16 check).** Zero of 3,081 rulings fall within ±0.005 of the 0.35/0.50 decision boundaries; the measured bf16-vs-fp32 drift (max 0.0022) cannot have changed any ruling. The verdict is identical under fp32.

**Reliability shape.** ECE 0.407 pooled Tier A (ML 0.348, SPREAD 0.466) is not a mild miscalibration: the top confidence bin holds ~99% of rulings at ~0.95 mean confidence against a ~0.55 realized-good rate. Brier 0.411 is worse than the 0.25 of a constant 0.5 predictor and far worse than the bridge model's own 0.2512 candidate-outcome reference from the October run. AUC by market (ML 0.490 / SPREAD 0.535) says the residual ranking signal, such as it is, lives only in spread rows and is still below the 0.58 bar.

## 6. What this means for wiring Laya as the board gate

1. **Do not wire it. Not in shadow, not as advisory.** The §6 rollout plan does not start: Phase 1 shadow exists to measure a gate that discriminates, and this checkpoint demonstrably does not (false-pass 0.9961 — a shadow seat would log 2 weeks of rubber stamps and add a "~0.96 confidence" number to the review surface that means nothing). The incumbent gates keep the seat. Nothing about the board changes.
2. **The judge seat stays vacant, and now it has a tested bar.** The durable asset from this run is not the model verdict — it is the *instrument*: a frozen 3,081-row leakage-controlled eval set, a validated scorer (reproduces October's deterministic arms exactly), a working CPU serving harness (~2.8–5.0 s/ruling on a 2-vCPU VM — a full re-run costs ~4.4 hours of background compute, no GPU needed), and a pre-registered bar any future candidate must clear. The next audition (the design's Arm 4 Verdict backend, hosted Jev, or a future checkpoint) runs through the same harness unchanged.
3. **The one path that could change this answer is the fine-tune arm** (design §2.3, arm 6): Laya fine-tuned on pre-2025 settled seasons only, as its own separately pre-registered experiment. Zero-shot Laya has no model of pick quality; whether RLCD fine-tuning on GSE's own settled history installs one is a genuinely open question — but it is a *new* experiment, not a re-run of this one with friendlier thresholds. Tonight's thresholds stay frozen and this verdict stands as the zero-shot record.
4. **The §7.1 CLV completion pull is no longer on this eval's critical path.** It was prescribed for an INCONCLUSIVE verdict; the verdict is KILL, so the pull reverts to "useful regardless" (it supersedes Tier B with full-state records for whatever candidate runs next). Its blocker is unchanged and precisely documented in §4 — a Vercel team-authorization tap. The staged export lane waits; no further action tonight.
5. **A doctrine note worth keeping:** the failure mode measured here — maximal confidence, no discrimination, risks named and ignored — is the generic failure of small judge models on specialist distributions, and this eval caught it *because* the bar was pre-registered in units and calibration rather than vibes. The corpus's October warning ("schema-valid ≠ correct") is now a measured fact with numbers: Brier 0.411, ECE 0.407, AUC 0.535 against bars of 0.24 / 0.07 / 0.58.
