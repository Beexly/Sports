## ON1B pos 25 — @ariacodez — reel — "Use every internet connection at the same time" (adapter bonding) — LEARN-ONLY
- URL: https://www.instagram.com/reel/Dez-Ev2y0Xn/ · 3,276 likes · feed position 25
- **1. WHAT IT IS:** A how-to reel for channel bonding: install a free open-source tool on Windows/Mac/Linux, plug in Ethernet while keeping Wi-Fi on, add a phone hotspot, flip a "Use all adapters" toggle, and the tool merges the links; run a speed test to see the difference. The mechanism class is real and well understood — either flow-based load balancing (each connection routed over a different adapter; total throughput across parallel flows rises, a single download does not speed up) or true bonding (packets striped across links through a tunnel to a relay server, which can speed a single stream). The reel does not say which class its tool is, and that distinction is the whole ballgame for whether the speed-test claim is honest.
- **2. WHERE TO FIND IT:** The reel's own repo is **UNRESOLVED**: the caption routes it through "the link I send you" — a DM gate, not engaged (no-messaging rule). The two closest verified open-source matches, found by GitHub search and read at primary source: **dikeckaan/internetmerge** (5★, Go, no license file, pushed 2026-06-09) — a local SOCKS5 proxy spreading connections across selected interfaces (macOS-first, Connectify-Dispatcher-style), whose README is admirably honest: single downloads do NOT get faster, and no gain when both links share one upstream. And **Donovoi/Bonding** (13★, 1 fork, Apache-2.0, Rust, pushed 2026-04-23) — a Windows-first true-bonding overlay: a Wintun TUN adapter encapsulates packets (ChaCha20Poly1305) across Wi-Fi + Ethernet to a Linux server side, with STRIPE / PREFERRED / REDUNDANT modes; the server can NAT onward, including to a Tailscale interface. Neither is asserted to be the reel's repo — recorded as candidates, not a match.
- **3. HOW TO USE IT:** InternetMerge: run the proxy, select interfaces, point apps at the local SOCKS5 endpoint. Bonding: install the Windows client, stand up the Linux server component (a VPS or home server), configure mode, connect. Both from their own READMEs; neither was installed this pass.
- **4. WHICH SYSTEM IT PLUGS INTO:** **Garrett's home/VM connectivity resilience** — the two-host fleet (this VM + his Windows box) and the Kingwood home connection. Bonding's server side is the interesting seat: Garrett already runs a Linux VM and Tailscale, so the relay the true-bonding design requires is infrastructure he owns, and its README explicitly supports forwarding to a `tailscale0` interface. InternetMerge's seat is narrower: parallel-flow throughput on one machine with zero new infrastructure.
- **5. CREATIVE ANGLES:** (a) Failover, not speed, is the real prize for an always-on agent fleet: a REDUNDANT-mode bond keeps sessions alive when one link dies mid-job — the overnight-sweep class of work fails silently on a dropped connection today. (b) The reel itself is a specimen of the creator economy around sysadmin tooling: a gated repo link traded for DMs, with the capability fully reproducible from ungated sources — the corpus keeps proving the gate is marketing, not scarcity.
- **6. RISKS AND LIMITS:** The reel's implied claim (merge links, watch a single speed test jump) is only honest for true bonding with a relay; for flow balancing it is the classic misleading demo. InternetMerge carries **no license** (all-rights-reserved by default) and is 5★/single-author. Bonding is 13★, young (created Dec 2025), and a custom tunnel protocol from a small project is a trust decision, not a default. Both candidates are unverified as the reel's artifact.
- **7. FIRST TEST AND VERDICT:** Smallest test, if Garrett ever wants the capability: install Donovoi/Bonding's server on this VM, connect the Windows client over Wi-Fi + Ethernet, and measure a single-stream download against each link alone — that one measurement settles whether true bonding pays on his actual links. **Verdict: LEARN-ONLY** (capability class and both verified shapes cataloged with their trade-offs; the reel's own repo unresolved behind its gate, recorded not guessed).
