## Area 1 — Galaxy Sports Edge (NFL/NCAAF prediction & reasoning engine; TypeScript monorepo, Postgres/Neon, published picks board, props/spreads/totals, calibration measurement)

### oddsphereai-sketch/oddsphere
- **Stars / license / activity:** 2 stars · no license detected (API: none) · TypeScript · created 2026-05-18 · last push 2026-10-27 · 2,025 commits.
- **What it does mechanically:** Next.js app plus a worker, with per-sport research trees (football, NHL, WNBA) and a `docs/model-audits/` directory. The root README is the stock create-next-app template (verified on the repo page) — the methodology lives in the audit docs, not the README. The 2026-07-24 audit doc covers an MLB player-props calibration pass: negative-binomial prop distributions fit on pre-game information only, a "peer consensus" pitcher-outs model, date-clustered ROI confidence intervals, and results reported in units.
- **Comparison points:** Same overall job shape as GSE — a props model whose changes are gated by a written audit before release. Its model-change safety protocol is explicit: a change ships only as a validated bundle, and a demotion with no validated paired promotion cannot ship (its HRR candidate failed two of four validation windows and was blocked). Design premise stated in the doc: calibration matters more than classification accuracy for betting decisions (citing Walsh & Joshi 2023). Difference: MLB-first; the audited surface is player props only, with no published reasoning-prose layer and no NFL board visible in the repo's public docs.

### tylerherman19/Sport3
- **Stars / license / activity:** 1 star · no license detected · Python + static JS · created 2026-03-13 · last push 2026-10-27 · 748 commits.
- **What it does mechanically:** A 12-model NFL ensemble — logistic regression with isotonic calibration (30% weight), XGBoost (25%), Pythagorean expectation (15%), efficiency (10%), Elo with margin-of-victory multiplier, Bayesian/TrueSkill ratings, Monte Carlo (10,000 sims), rest/travel adjustments, time decay — fed by FiveThirtyEight's historical Elo dataset, ESPN public APIs (scores, standings, injuries), and optionally The Odds API. Runs daily at 08:00 UTC in GitHub Actions, writes four JSON files (predictions, Elo leaderboard, model metrics, injuries) back to the repo, and a GitHub Pages dashboard renders them, including log loss, Brier score, AUC, and a calibration curve.
- **Comparison points:** Same end-to-end shape as GSE (model → published board → public accuracy metrics) with a different storage architecture: JSON files as materialized views, no database, vs GSE's Postgres/Neon-backed board. Ensemble weights are fixed constants printed in the README; GSE's current doctrine is measured weights from settled-game samples. Sport3 shows "model edge vs market" on the dashboard but has no props market and no per-pick reasoning trail.

### martineastwood/penaltyblog
- **Stars / license / activity:** 244 stars · MIT · Python (Cython-accelerated) · last push 2026-10-19.
- **What it does mechanically:** A modeling library, not a publishing system. Goal models (Poisson, Dixon-Coles with time decay, bivariate Poisson, negative binomial, Weibull copula, zero-inflated Poisson) fit by maximum likelihood; Bayesian hierarchical variants via Stan; team ratings (Elo, Massey, Colley, Pi); implied-probability extraction that removes bookmaker margin (devigging); evaluation metrics (ranked probability score, ignorance score, multiclass Brier); a backtest framework; scrapers for FBref, Understat, Club Elo, and Fantasy Premier League; and MatchFlow, a lazy streaming pipeline for nested JSON data.
- **Comparison points:** Soccer-only, so the goal-model family maps onto GSE's totals/spreads problem only by analogy (low-count Poisson scoring vs NFL margin distributions). The overlap is in the pricing/measurement layer: devigging, ratings, and proper scoring rules (RPS/Brier) are the same instrument classes GSE uses for calibration measurement (CRPS/Brier on its locked filter). Extra capability relative to GSE's stack: a maintained backtest framework as a library primitive. Missing relative to GSE: any publishing, board, or live-picks surface — it is a toolkit other systems build on.

### georgedouzas/sports-betting
- **Stars / license / activity:** 823 stars · MIT · Python · created 2019-01-08 · last push 2026-09-24 · 577 commits.
- **What it does mechanically:** Two-part library. Dataloaders pair a statistics source with an odds source (both pluggable) and extract train/fixtures data with identical columns. Bettors wrap any scikit-learn estimator, backtest with TimeSeriesSplit (reporting yield/ROI per fold), and return value bets for upcoming fixtures. It also ships an MCP server (`sportsbet-mcp`) so an AI agent can run the whole loop — explore data, backtest, extract fixtures, produce value bets — and an execution module that can place a bet through a bookmaker API or by driving the bookmaker's website with Playwright; the README itself warns that website automation breaches most bookmakers' terms of service.
- **Comparison points:** The closest public analog to an agent-driven betting-model loop: an MCP-exposed model pipeline is the same interface pattern as GSE's engine surfaces on Garrett's MCP bus. Differences: data sources are soccer-first (football-data.co.uk); the "model" is an interchangeable sklearn estimator with no reasoning layer over signals; and it crosses from prediction into automated bet placement, which GSE does not do (GSE publishes picks; placement is a separate manual act).

### nflverse/nflfastR

### nfelo/nfelo.github.io
- **Stars / license / activity:** 0 stars · MIT · Python-generated static site · created 2026-07-14 · last push 2026-10-27 · 810 commits.
- **What it does mechanically:** International soccer ratings and forecasts. A full-covariance dynamic Gaussian opponent network produces one published rating used everywhere on the site; a separate attack/defence state refines match probabilities without altering ratings.
