## Challenges

### Second-hand and unverified claims
- **1112's 0.55 correlation is snooped and the ledger says so.** Channel/metric selection was optimized on the same six-month series used to report it; no held-out backtest; six months is one regime; crypto ≠ sports news. The ledger's own acceptance gate (|r| ≥ 0.10 out-of-sample, REJECT if <0.05) is a 5–10× haircut — appropriate. **INFERENCE:** the portable idea is the *disagreement* (variance-across-channels) metric, which the paper never tested; the sentiment-level result should be treated as a negative example of selection bias until the GSE port runs.
- **1142's model rankings have no uncertainty.** No CIs, no significance tests on XGBoost-vs-RF differences, exact numbers figures-only, no carry-forward baseline in the paper. The ledger's GSE port correctly adds the baseline and coverage validation the paper skipped. **INFERENCE:** treat "XGBoost best for quality, RF best for value" as a prior, not a finding.
- **0624's training data is GPT-5-generated** (71,249 samples). The evaluator (Gemini-3 Flash) agrees with blind humans at 94/91/83%, which mitigates but doesn't eliminate the circularity: a model trained on GPT-5's hazard judgments evaluated by another LLM. For the NFL pilot, human annotation of the 300 plays is the expensive but necessary version.
- **0964 is pure Monte Carlo with independent contracts.** The 1/m decay, the AABRP'→0 hedging result, and the σ(m) fit (R²=0.993) all assume independence; the ledger flags correlated perils as the weakening case. NFL pick portfolios are *structurally* correlated (same-slate exposure, divisional weather, QB-WR stacks). **INFERENCE:** use 0964's numbers as the optimistic bound and 1212's correlation matrix as the realistic one; the monitor in Buildable #16 exists to detect which regime you're in.
- **1102's NFL port is a plan, not a result.** The LR numbers (10^19, 10^30) are retrospective on selected scandals with hand-set p (0.9/0.8) and independence assumptions the ledger admits are violated. Sensitivity to p is "extreme" per the ledger. The proposed 2024-line-move test hasn't run.

### Method problems
- **1008's headline contradicts its own Table 1.** "CARL reduces baseline adversarial error by more than half at equal natural error" is the MNIST headline; on CIFAR-10 at low abstention CARL is *worse* than the margin-threshold baseline (55.2% vs 50.9% adv err at λ=1/2; 35.8% vs 29.2% at similar abstention for λ=1). - **1559 never isolates the smoothing gain.** No plain-BOA comparison; the λ-selection curve is asserted, not tabled; 30-day test; ρ=0.01/60-day/30-day all hand-chosen; MAE objective transfers to point forecasts, not probability calibration. **INFERENCE:** adopt the *event-adjustment front-end* (the cleaner idea) with more confidence than the *smoothing* (the asserted idea); gate the two separately.
- **1182's transfer to log-loss/Brier is untested** (point forecasts + squared loss only), and the diversity corrections "sometimes hurt" in the paper's own ablations. The ledger's gate (≥0.003 log-loss beat of plain EW + stability veto) is the right skepticism; don't ship the diversity bonus without the ablation.
- **0693 removes up to 75% of training data at 0.8 noise.** On NFL-scale samples (hundreds of games, not 50k images), DAC's cleaning could delete the season. The ledger's gate (abstained fraction ≤25%) is load-bearing, not decorative.
- **1192's headline is likely a pooling artifact** — the ledger's own limitation section notes English-only data fits Poisson/NBD fine, so the 169-league Fréchet tail is manufactured by mixing heterogeneous leagues. Correctly REJECTed; the mechanism (mixture → heavy tail) is a standing warning for any pooled-league NFL analysis (e.g., pooling preseason/regular/postseason).
- **0725's quantile summation requires comonotonicity**, holidays were ignored, and trend uncertainty was negligible (0.008 vs 0.1 log-scale) — the NFL port's value is entirely in the remainder model; the trend component is nearly decorative for week-to-week totals.

## Integration notes

What the Buildable systems need from a unified intelligence API (qb-behavior + coaching + trust-signals + reasoning in one callable interface). Each need is keyed to the systems above.

**Ordering dependencies (pipeline direction).** The evidence in this chunk supports a strict conditioning order: **availability/trench state → scheme/coaching fingerprints → QB behavior → pair trust (chemistry) → projections → calibration → combination → sizing → no-bet gate.** Concretely: S23/S3/S4/S5 (ratings + HFA) are the base layer; S2 (chemistry) conditions on the QB-receiver interaction set that the QB behavioral profile defines; S10→S11 (residual post-processing → GP-PIT recalibration) is the calibration chain with the FAM gate between them; S7 governs how S6/S8/S9/S24 combine; S13→S14→S16 is the sizing chain (size → fraction → monitor); S18's abstention stages wrap the pipeline at train (DAC), inference (SPTD), and decision (CARL) time; S15 attributes staking outcomes afterward. **INFERENCE:** OL is the missing head of this chain — the map's gap #4 (no continuity/attribution beyond injury lists) means the pipeline currently starts at "scheme" with trench state as an unmodeled confounder. Any unified API should expose an `ol_state` slot now (populated by injury flags today) so the attribution layer (S26/S25) can measure its absence rather than silently absorbing it.

**Cross-module contracts.**
- **QB behavioral profile (map #1, `deep/qb-full-pool-2026-09-19.md`) is the consumer schema.** S2 must emit JOI/dropback keyed by `(qb_id, receiver_id, week)` joinable to the profile's EPA/db, CPOE, pressure-to-sack, first-read, scramble, aggressiveness, aDOT, and man/zone/pressure splits. S27's release-type labels attach at `(qb_id, play_id)`. S28's hazard cues attach at `(player_id, play_id)` as an availability modifier, not a performance feature.
- **Trust-signal contract.** S2's trust score is a *measured on-field* quantity (pair production vs shared field). S22's disagreement metric is a *public-signal* quantity. The unified API should keep them namespaced (`trust.on_field.chemistry` vs `trust.public.disagreement`) — the map's trust-signal gap is specifically about the public side, and conflating the two would let S2's numbers launder S22's unproven ones.
- **Rating contract.** S1/S3/S4/S5/S24 all emit `(team_id, week) → (strength, uncertainty)`. The API needs ONE canonical team-strength object with a `method` tag and a `decay` tag (pseudodiffusion / AR(1) / recursive-prior — the trilemma from Cross-file connections), because downstream consumers (S9's event adjustment, S19's distillation baseline, S13's edges) must know which decay produced the number they're conditioning on. The 0715 doctrine is a contract clause: *no module may claim to improve pick ranking via a monotone transform* — ranking improvements must arrive as new features with ε_rank attribution.
