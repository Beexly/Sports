## Cross-cutting findings

1. **Two distinct tables, two very different states.** `game_signals` is written by exactly one code path (2 SCHEDULE keys), read by 4 surfaces, and holds 5,002–5,142 rows (count from docs, numbers disagree). `signals` is written by one hourly cron (84,500 rows per `docs/ops/AGENT_LEDGER.md:563`, count from docs), read for counting by exactly one route, and **composed by nothing**.

2. **The biggest structural gap is not a missing writer — it is a missing composer.** `signals` is populated and `composeLedger` has zero production readers. The table is fuel with no engine.

3. **A third of the registry is ACTIVE-but-structurally-inert.** 8 base definitions have `evaluate` bodies that unconditionally `return null` (rows 16f/16g), and all 22 extensions read per-game scalars from `process.env` keys that nothing in the repo ever sets (row 17). Both classes are marked ACTIVE with real `trustWeight`s. This is the same failure shape as the eight always-false snapshot families, at a different layer.

4. **The production bundle builder supplies 2 of 14 input fields.** `intelligence-enrichment.ts:116-145` sets only `market` and `extraObservations`; `engine.ts:63-75` declares 12 raw-DB surfaces (`homeInjuries`, `homeNgs`, `homeRatings`, `weather`, `gameSignals`, `homeSnaps`, …) that no production caller fills. Rows 21/23/24 therefore compute over empty arrays in production. The readers and the math are real; the wiring is not.

5. **Asymmetric devig regression tests are still missing** even after the fix. Both adapter tests use symmetric inputs (`-110,-110` / `[-110,-110]`), and the oracle adapter test passes `"proportional"`, an invalid method that falls through to multiplicative. Neither test would fail if either bug were reintroduced.

6. **Adapter-layer provenance was corrected but is not load-bearing.** All adapter barrels (`extended-signal-adapters.ts:496`, `market-odds-adapters.ts:212`, `market-inplay-sizing-adapters.ts:431`) are exported through `index.ts:2522` and have no importer. Zero production risk, zero production value.
