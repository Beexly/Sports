## VERDICT: ADAPT

LEAP's per-evidence LLM-call pipeline is not what GSE needs, but its deterministic Bayesian aggregation machinery — prior + per-source likelihoods + dependency clustering + reliability shrinkage + closed-form tempered posterior + leave-one-out contribution audit — is a directly implementable blueprint for upgrading GSE's multi-market ensemble into a calibrated Bayesian aggregator. The numeric maps in Appendix B are fixed constants, not learned weights, so the core can be built with zero LLM inference.

---

## 1. Research question

How should a *fixed* evidence set be converted into a final probabilistic forecast? The paper isolates the prediction stage of LLM-based forecasting systems from evidence collection and asks whether per-evidence likelihood elicitation plus deterministic Bayesian aggregation beats the standard "Monolithic Prediction" design (one LLM call reads all evidence and emits the forecast). The target use cases are forecasting (future events, e.g. financial markets, sports outcomes), plus information-seeking and browsing tasks (GAIA, BrowseComp) reframed as probabilistic tasks.

## 2. Dataset/schema

Benchmark is a **constructed evaluation-only manifest of 347 retained tasks** (no train/dev/test splits — authors do not train or select models on it):

| Source | Initial pool | Final retained | Construction rule |
|---|---|---|---|
| FutureX | 160 | 157 | removed ranking resolutions; retained native single-choice, multi-choice, continuous tasks; excluded manually verified label conflicts |
| GAIA | 103 | 99 | text-only mirror; open-ended tasks rewritten into single-choice, multi-choice, or continuous targets; reviewed conversions only |
| BrowseComp | 100 | 91 | sampled public pool; short-answer browsing tasks rewritten into single-choice with plausible distractors |

Output-type distribution: **266 single-choice, 29 multi-choice, 52 continuous** (Table 10). A separate **60-task diagnostic subset** (stratified across output types, GPT-5.4-mini base model) is held constant across the calibration/horizon/ablation analyses.

Task tuple schema (Eq. 1): `T = (q, tfreeze, τ, O)` where q = question, tfreeze = cutoff time (usable info must be timestamped ≤ tfreeze), τ ∈ {continuous, single-choice, multi-choice}, O = optional candidate options. Evidence: `E = {e1, …, en}` (Eq. 2), each ei a text passage timestamped ≤ tfreeze. FutureX items use the original question time as tfreeze; for GAIA/BrowseComp, tfreeze is "assigned from the benchmark snapshot … acts as a retrieval cutoff for the converted task, not as a forecast resolution date." Three FutureX items and three GAIA continuous items were quarantined for label conflicts.

## 3. Method/model

LEAP replaces the monolithic final prediction call with a pipeline:

1. **Prior track** — parameters of P0 come from the most informative source available: computed from recent numerical history (market price / macro index) when one exists; otherwise a *blind* LLM call with no evidence visible; for discrete tasks lacking even a background base rate, an unbiased conservative prior. The prior call is forbidden from seeing evidence (would double-count it in Bayes' rule).
2. **Elicitation & safeguards track** — each evidence item ei is sent to the LLM **in isolation** (sees T and exactly one ei; never other items, accumulated evidence, or partial posteriors). The LLM does not predict; it returns a structured qualitative likelihood schema (support/oppose labels per option, or a target-scale observation for continuous targets) plus a **dependency key** identifying the source family.
3. **Safeguards before inference** —
   - *Dependency clustering:* items sharing a canonicalised dependency key (lowercased, tokenised, stopwords removed, tokens sorted) are grouped; one representative per group is retained → retained set R.
   - *Reliability sampling:* the same (T, ei) query is repeated R times (10 reliability samples in experiments); agreement across draws only *shrinks* the local likelihood magnitude toward neutral, never increases it (agreement on top option × exponential penalty on average L1 disagreement; shrinks toward uniform).
   - *Outlier rejection:* for continuous targets with a data-derived prior, an item with |µi − µ0| > 4σ0 is excluded as a likely elicitation error. Not applied when the prior is blind.
4. **Deterministic aggregation** — closed-form tempered conjugate Bayesian update over R (no LLM call), yielding a posterior forecast f in the form required by τ, plus **per-evidence leave-one-out contributions** Δj = forecast change when item j is excluded.

Three output families: Gaussian conjugate pair for continuous (forecast = quantiles, e.g. median and 10th/90th percentiles), categorical + multinomial likelihood for single-choice (forecast = normalised probability vector), independent Bernoulli pairs for multi-choice (forecast = per-option marginals, need not sum to 1).

## 4. Equations & assumptions (copied faithfully from the text)

Task and evidence (Eqs. 1–3):

> T = (q, tfreeze, τ, O)  … (1)
> E = {e1, …, en}  … (2)
> θ ∼ P0(θ),   ei | θ ∼indep Pi(ei | θ),  i = 1, …, n  … (3)

Posterior over retained set R (Eq. 4):

> P(θ | E) ∝ P0(θ) ∏_{i∈R} Pi(ei | θ)  … (4)

The paper notes the **working conditional-independence assumption** `ei ⊥ ej | θ` for i ≠ j, and states it "can fail when evidence items share a source," which dependency clustering is meant to repair. Experiments use a tempered version with role weights that reduces to Eq. (4) at unit temperature and weights.

Continuous targets (Appendix A.1, Eqs. 5–7), θ ~ N(µ0, σ0²), L̃i(θ) ∝ N(θ; µi, σi²), precision τx = 1/σx²:

> τpost = τ0 + η Σ_{i∈R} τi,   µpost = (1/τpost)(µ0τ0 + η Σ_{i∈R} µiτi)  … (6)
> Δj = µpost − µpost^(−j)  … (7)

Single-choice targets (Appendix A.2, Eqs. 8–9), log-space for stability; α = prior power, wi = evidence weight based on role:

> log πpost(k) ∝ α log π0(k) + η Σ_{i∈R} wi log Li(k), followed by softmax normalisation … (8)
> Δj = πpost(k̂) − πpost^(−j)(k̂), where k̂ = arg max_k πpost(k)  … (9)

Multi-choice targets (Appendix A.3, Eqs. 10–11), ℓi(k) = log(ptrue_i,k / pfalse_i,k):

> logit πpost(k) = logit π0(k) + η Σ_{i∈R} wi ℓi(k)  … (10)
> Δj = Σ_{k=1..K} |πpost(k) − πpost^(−j)(k)|  … (11)

Scoring metrics (Appendix D.6, Eqs. 12–14), pik predicted prob for option k on task i, yik ground-truth indicator:

> Accuracy = (1/N) Σ_i 1[arg max_k pik = ci]  … (12)
> Brier = (1/N) Σ_i (1/Ki) Σ_k (pik − yik)²  … (13)
> Spherical = (1/N) Σ_i (Σ_k pik yik) / √(Σ_k p²ik √(Σ_k y²ik)) … (14)

Continuous metric: NCRPSi = min(1, CRPSi / max(|vi|, 1)). The FutureX composite FX score uses the scoring rule from Zeng et al. (2026): indicator for single-choice, F1 for multi-choice, squared distance normalised by past-week SD for continuous, averaged into [0, 1]. ECE = gap between top-option confidence and empirical accuracy (Guo et al., 2017); overconfidence = average of the positive part of this gap.

**Assumptions the paper names:** conditional independence given θ (mitigated by dependency clustering); conjugate family choice per output type; tempering η and role weights are fixed constants (η = 1.0 default; evidence weight in [0.05, 1.5]); all mapping constants in Appendix B "fixed before the final evaluation runs and not tuned separately for individual test tasks or base models."

## 5. Features/target

- **Target:** posterior forecast f over θ — quantiles for continuous, probability vector for single-choice, per-option marginals for multi-choice — plus Δj leave-one-out contributions per retained evidence item.
- **Per-evidence LLM outputs (features → likelihood parameters):**
  - Continuous: LLM extracts target-scale observation µi (explicit reported value or qualitative assessment); σi assigned by the **fixed metadata map** (Table 7): initial relative SD ri ∈ {0.08, 0.18, 0.45} by observation_type (point/interval/bound/other), multiplied by factors for source_tier (A 0.80 / B 0.95 / C 1.15 / other 1.10), strength (strong 0.85 / weak 1.20), reliability (high 0.85 / low 1.15), target_match (exact/direct 0.90 / partial 1.05 / unknown/indirect 1.10), recency (≤7d 0.80 / ≤30d 1.00 / older 1.25); clamped to [0.03, 1.25]; contextual-only evidence floored at 0.35·si. With reliability sampling, σi = √(σ²_data,i + σ²_elicitation,i).
  - Single-choice: qualitative support labels → raw likelihoods Li(k) via a fixed table; base values: support 0.90 / oppose 0.08 / neutral 0.12 for direct evidence (mixed by reliability); deterministic verifier support 0.99 / oppose 0.01; fallbacks down to 0.85/0.12/0.35 (Table 8).
  - Multi-choice: log likelihood ratios; base ±1.735 (i.e. log(0.85/0.15)); deterministic verifier ±log(0.995/0.005) clipped at 5.30; direct results clipped at 3.00 (Table 8).
- **Inputs to aggregation:** elicited prior params, per-item likelihood params, dependency keys, evidence role → weight wi ∈ [0.05, 1.5].

## 6. Validation design

- Strict **temporal isolation**: retrieval restricted to material timestamped ≤ tfreeze; base models chosen so knowledge cutoffs precede evaluated timestamps; temporal leakage audit over evidence snapshots found "no cutoff violations and no suspected leakage cases."
- **Shared-evidence protocol:** for each task the collection stage runs once producing a single E; Monolithic and LEAP are applied to the same (T, E) — score differences attributed to prediction-stage design, not retrieval. N = 5 independent passes per (model, method) cell with different seeds; "no hyperparameter search"; mapping constants fixed before final runs. Run-to-run σ median ≈ 0.010 (IQR [0.007, 0.014]); LEAP-vs-Monolithic ordering preserved in 48/50 cells.
- **Two settings:** (a) authors' ReAct-style agent loop (budget B = 10 turns, ≤6 evidence items entering likelihood stage, ≤60 likelihood calls/task, 10 reliability samples) across five base models (DeepSeek-V3.2, Gemini-3.1-Flash-Lite, Claude-Haiku-4.5, GPT-5.4-mini, Grok-4.20-Fast); (b) LEAP as a downstream probability skill over **unmodified traces** from four external agent CLI frameworks (DeerFlow, Hermes, OpenClaw, MiroFlow).
- **Controlled baselines:** Monolithic given the same prior, Monolithic with doubled token budget (two-sample mean), and linear opinion pooling; inference-budget table (tokens/task, p50/p95 latency).
- Metrics: FutureX composite (headline), Accuracy, Brier, Spherical (discrete), NCRPS (continuous), ECE / adaptive ECE / overconfidence (diagnostic subset).

## 9. Leakage & limitations (adversarial)

1. **The "prior" is doing most of the work, and its blind-LLM form is unprincipled.** Ablation shows removing the prior drops FutureX *below* Monolithic (0.643 vs 0.651) and makes ECE the worst of all variants (0.213). When no historical data exists the prior comes from "a single LLM call with no evidence visible" — i.e., the most important component of the system is an unconstrained vibes-estimate. The paper frames this as a feature ("stable starting point"); it reads as the method being a prior with evidence-flavoured decoration.
2. **GAIA/BrowseComp are not forecasting tasks.** The paper admits tfreeze for these is a "retrieval cutoff … not a forecast resolution date." Rewriting static QA into "probabilistic targets" with synthetic distractors measures QA-with-uncertainty, not forecasting. The horizon analysis (Fig. 3) is only meaningful on actual forecasting items.
3. **No held-out split discipline.** "We do not define train/dev/test splits." Constants were "fixed before the final evaluation runs," but the diagnostic subset was also used for the η-sensitivity, grouping-sensitivity, and ablation analyses — the same 60 tasks that motivated design choices are the ones reporting the gains.
4. **No significance testing.** Results are seed means ± informal σ; "all remaining pairwise differences exceed 2σ" is asserted, not tested (no t-test / bootstrap / multiple-comparison correction over 50 cells).
5. **Conditional independence is violated by design, and clustering only patches the easy case.** Canonicalised dependency keys catch near-duplicate sources but miss semantic correlation (two independent outlets citing the same underlying report with different wording; beat-reporter echo chambers). Correlated-but-distinct evidence still double-counts.
6. **Brier results are mixed on their own loop** (LEAP worse/tied on 2 of 5 models) — the paper's explanation (LEAP is "conservative," Monolithic concentrates mass) is plausible but means the headline gains partly come from betting-against-overconfidence rather than better discrimination. On external frameworks Brier improves strongly, suggesting the effect is trace-quality-dependent.
7. **LLM-in-the-loop is a load-bearing assumption.** Every likelihood, dependency key, and blind prior is an LLM judgment; the elicited "likelihoods" inherit model bias. Their reliability sampling only *shrinks* noisy estimates — it cannot detect systematic directional bias shared across draws (same model, same item).
8. **Cost: ~2× tokens per task** (11,508 vs 5,733) and worse p95 latency (27.8s vs 12.1s) because of slowest-evidence-level-call stragglers. Fine for research, a real constraint for a per-pick production pipeline.
9. **Model pool is bleeding-edge and unreproducible on older knowledge:** Grok-4.20-Fast, GPT-5.4-mini, Gemini-3.1-Flash-Lite — 2026 model versions whose behavior may not transfer to smaller/older models GSE could afford at scale.
10. **The FutureX composite scoring rule lives in Zeng et al. (2026), not in this paper** — headline metric is not self-containedly defined, and FX "points" are on a 0–1 average that mixes indicator/F1/distance scores, so "18.1 points" is less interpretable than it sounds.
## 10. GSE overlap

GSE's prediction pipeline is an *ensemble of sources*, not an LLM reading evidence — which is exactly where LEAP's machinery transfers and where its LLM angle doesn't.

- **multi-market-ensemble (…/src/multi-market-ensemble.db.ts):** LEAP *is* a formalisation of this module's job — combine per-source signals (market-implied probabilities across books, model v5.2.7 sub-model outputs) into one calibrated posterior. The tempered Bayesian update (Eq. 8/10) with role weights wi ∈ [0.05, 1.5] and global strength η is a cleaner, calibration-first replacement for whatever linear/weighted averaging currently combines markets. The paper's calibration result (ECE halved, overconfidence cut 0.317 → 0.150) is the strongest argument: if GSE's ensemble is overconfident, LEAP's conservatism is a feature, not a bug. **Uncertainty:** I have not read this module's contents; if it already does Bayesian-style updating, the transfer value shrinks to the safeguards (clustering, reliability shrinkage, LOO audit).
- **source-reliability (…/src/source-reliability.db.ts):** maps to LEAP's reliability sampling + role weights. LEAP's shrinkage rule (agreement × exp-penalty on disagreement, only ever shrinks toward neutral) is a concrete, implementable weighting scheme for per-source trust — more principled than a static weight. **Uncertainty:** I have not read this module; the overlap may duplicate existing work.
- **calibration-ladder (…/src/calibration-ladder.db.ts):** LEAP's post-aggregation calibration story complements it. Note the paper's cautionary point: better Brier from spreading probability can mask worse discrimination — the calibration ladder should evaluate Brier *decomposition* (calibration vs. resolution), not headline Brier alone, before/after a LEAP-style aggregation.
- **pick-clv, oos-split, synthetic-fade (…/src/{pick-clv,oos-split,synthetic-fade}.db.ts):** CLV logging and out-of-sample splits are the natural evaluation harness for the gate in §13 (CLV improvement as the decision metric). No direct method overlap.
- **What does NOT transfer:** per-evidence LLM elicitation calls (~2× token cost, 27.8s p95). GSE's "evidence items" are numeric (lines, model probs, injury flags), not prose — the discrete likelihood maps in Appendix B Tables 7–8 are *already numeric*, so GSE can skip the LLM entirely and use the fixed constants directly.

## 11. GSE implementation spec

Build a new module `packages/prediction-engine/src/leap-aggregation.db.ts` (name TBD by repo conventions). No LLM calls; all "elicitation" is deterministic mapping from existing engine inputs.

**Inputs:**
- `prior`: base-rate probability vector for the pick (e.g., from picks-table history: home favourite cover rate, or per-team rolling rates). Shape: `{ probs: number[K], source: 'historical' | 'neutral' }`. When no history: uniform.
- `sources`: array of per-source likelihood signals, one per evidence family: `{ key: string (dependency key, e.g. 'draftkings-line', 'model-v5-sub', 'injury-feed'), support: 'support'|'oppose'|'neutral', strength: 'strong'|'weak', reliability: 'high'|'low', role: string }`. Numeric signals map to qualitative labels by thresholds (e.g., model edge ≥ 4% → strong support).
- Config: `eta` (default 1.0), `priorPower` α (default 1.0).

**Method:**
1. **Likelihood map** (from Appendix B Table 8, single-choice row for spread/moneyline/total picks which are binary choices): support → Li = 0.90, oppose → 0.08, neutral → 0.12; *deterministic verifier* role (closing-line / official injury confirmation) → 0.99 / 0.01 / 0.02; weak/fallback → 0.85 / 0.12 / 0.35. Mix toward uniform by reliability: `L = reliability * L_raw + (1 - reliability) * 0.5` with reliability ∈ {high: 1.0, low: 0.5}.
2. **Dependency clustering:** canonicalise keys (lowercase, split on separators, sort tokens, join); group sources; retain one representative per group (highest reliability). Retain set R.
3. **Role weights:** wi ∈ [0.05, 1.5] per role (default 1.0; deterministic verifier 1.5; context-only 0.3).
4. **Posterior (Eq. 8):** `log πpost(k) ∝ α·log π0(k) + η·Σ_{i∈R} wi·log Li(k)`, softmax-normalise.
5. **LOO contributions (Eq. 9):** for each j ∈ R, recompute without j; `Δj = πpost(k̂) − πpost^(−j)(k̂)`; log `{ key, delta, retained }` as the audit trail attached to the pick record.
6. **Outlier rule (continuous targets only, if extended to totals/projections):** reject items with |µi − µ0| > 4σ0.

**Output shape:**
```ts
{
  posterior: number[],        // length K, sums to 1
  pick: number,               // argmax
  confidence: number,         // posterior[pick]
  prior: number[],            // for audit
  contributions: { key: string; delta: number; retained: boolean; weight: number }[],
  config: { eta: number; alpha: number }
}
```

## 12. Reproducible test

Fixture: synthetic 2-option (spread cover) case with hand-computed expectations.

1. **Posterior correctness:** prior [0.5, 0.5]; one strong-support source for option A (Li(A)=0.90, Li(B)=0.08, w=1.0, η=1.0) → expected πpost(A) = 0.9/(0.9+0.08) ≈ 0.9184. Assert |actual − 0.9184| < 1e-9.
2. **Prior matters:** same source with prior [0.3, 0.7] → expected ∝ [0.27, 0.056] → [0.8282, 0.1718]. Assert within 1e-9.
3. **Dependency clustering:** two sources with keys `draftkings_line` and `line_draftkings` (same token set) both strongly supporting A; assert posterior equals the single-source case and only one contribution entry has `retained: true`.
4. **LOO audit reproducibility:** for a 3-source fixture, assert Δj values equal recomputation with j removed, and Σ is not required (only the identity Δj = πpost(k̂) − πpost^(−j)(k̂)).
5. **Outlier rejection (continuous path):** prior N(250.74, 7.5222²), item µi=190 → z = 8.07 > 4 → excluded from R. Assert exclusion. (Mirrors the paper's AAPL case.)
6. **Neutrality floor:** all sources neutral → posterior == prior. Assert.

Pass criteria: all six fixtures green, plus property test that posterior always sums to 1 over 1,000 randomised fixtures.

## 13. Acceptance/rejection gate (numeric)

**ADOPT** the module into the production pick path if, on a backtest of the existing `picks`-table history (SPREAD/MONEYLINE/TOTAL, model v5.2.7 era) under the engine's standard out-of-sample split, Bayesian aggregation vs. the current multi-market-ensemble combination satisfies **all three**:
- Brier score reduced by ≥ 5% (relative),
- ECE reduced by ≥ 30% (the paper's headline transfer: 0.184 → 0.088 ≈ −52%),
- CLV per pick not worse (ΔCLV ≥ −0.1¢ per $1 stake — calibration must not cost edge).

**REJECT** if Brier is flat or worse *and* ECE improvement < 15%, or if CLV degrades > 0.5¢/$. If only calibration improves with neutral Brier/CLV, keep as an audit-only lane (log contributions per pick without changing the pick) and re-test after role-weight tuning.

## 14. Improvement experiment (GSE-specific)

1. **Learn the weights instead of fixing them.** LEAP's constants (η=1.0, wi ∈ [0.05,1.5], the 0.90/0.08/0.12 maps) are hand-set and "not tuned." GSE has 3,411 labelled picks: fit η, per-role wi, and the support/oppose magnitudes by maximum likelihood on the posterior (log-loss) over the picks history with the OOS split. Test whether learned weights beat the paper's constants — the paper's "no hyperparameter search" is an invitation.
2. **Market as deterministic verifier.** LEAP gives verifier evidence 0.99/0.01 with cap 5.30. For GSE, treat the *closing line* as the verifier source: its likelihood should dominate the posterior on line-derived picks, turning the module into "model edge blended against closing line with calibrated uncertainty" — a direct CLV play.
3. **Replace reliability sampling with sub-model disagreement.** LEAP's R repeated LLM draws shrink noisy elicitations; GSE's analog is cheaper and real: run the engine's sub-models (or bootstrap resamples of the input features) and shrink each source's likelihood toward neutral by inter-run disagreement. This is reliability sampling with actual variance instead of an LLM's self-agreement.
4. **Prior as a learned base-rate engine.** LEAP's blind-LLM prior is its weakest component; GSE replaces it with empirical priors from the picks table (per-team, per-situation, per-market rolling base rates, decayed by recency). Ablation showed the prior is the single most important component (removing it dropped FutureX below Monolithic) — investing in the prior is the highest-leverage GSE extension.
5. **Δj-driven source triage.** Log leave-one-out contributions per pick over a season; sources with consistently near-zero Δj are dead weight (cut them); sources with large |Δj| on losing picks are miscalibrated liabilities (re-weight or quarantine). This turns LEAP's auditability into a standing source-reliability feedback loop.

## VERDICT: ADAPT

The LLM elicitation layer is overhead GSE doesn't need; the deterministic Bayesian aggregation machinery — fixed-constant likelihood maps, dependency clustering, reliability shrinkage, tempered conjugate posterior, leave-one-out source audit — ports cleanly to the multi-market ensemble as a calibration-first upgrade, with the paper's halved-ECE result as the reason to build it and CLV-neutrality as the gate to ship it.
