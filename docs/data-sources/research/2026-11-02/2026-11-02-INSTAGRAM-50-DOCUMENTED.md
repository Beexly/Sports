### #1 — @vyzual.ai — DfM7Zv-DRBn
Post: https://www.instagram.com/p/DfM7Zv-DRBn/
Source of item: IG self-DM 2026-11-02

1. WHAT IT IS — Vercel Labs' **agent-desktop**: a Rust CLI + C library (Apache-2.0, v1.0.2, released late Oct 2026) that gives any terminal-capable AI agent "computer use" over native desktop apps on macOS, Windows and Linux — but instead of screenshots/pixel coordinates, it reads the OS accessibility tree (macOS AX API, Windows UI Automation, Linux AT-SPI). Each `snapshot` returns JSON where every actionable element carries a stable ref (e.g. `@s8f3k2p9:e8`); the agent clicks/types/scrolls by ref, then re-snapshots to verify. A `--skeleton` mode returns only container structure so dense Electron apps (Slack, VS Code, Notion) don't blow the context window. There is no model inside it — it is purely the observe/act layer. The post's carousel demos Claude Code and Cursor driving Notes, Reminders and Apple Maps, including two agents working in the same app with separate cursors.
2. WHERE TO FIND IT — Post URL above. Primary source: https://github.com/vercel-labs/agent-desktop (Vercel Labs' own repo; README and v1.0.2 release confirmed via multiple independent write-ups that read the repo directly).
3. HOW TO USE IT — `npm install -g agent-desktop` (native binaries for x64/ARM64). Core loop: `agent-desktop snapshot --app <App> -i` → `agent-desktop click @<ref>` / type / scroll → snapshot again to verify. Dense apps: `snapshot --skeleton --app Slack -i --compact`, then `snapshot --root @<ref>` to drill into one region. The binary carries version-matched docs: `agent-desktop skills get desktop` and `agent-desktop skills get platform`; it can also be installed as an agent skill via `npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop`. Requirements: macOS needs an Accessibility permission grant (`agent-desktop permissions --guide` walks it); Windows needs no grant for apps at the terminal's integrity level; Linux needs a graphical session + at-spi2-core. Actions are headless by default (accessibility API, no pointer theft); `--headed` opts into real input. ~56 commands total (observation, input, windows, clipboard, notifications, sessions).
4. WHERE TO USE IT — **Agent fleet infrastructure.** This is the missing hands layer for exactly the jobs that currently stall on "Garrett's Windows box": Hermes-side desktop tasks, native-app QA of GSE surfaces, and operating desktop-only tools (DraftKings/native apps, CleanCloud-type dashboards, SiriusXM-type players) where no API exists. It also gives the fleet a way to *test* applications it builds, not just write them. It extends — does not replace — the browser lane: web pages stay with the browser tools; agent-desktop explicitly does not automate web content.
5. CREATIVE ANGLES — (a) Pair with the fleet MCP bus: an agent-desktop session per machine turns Garrett's Windows box into a remotely taskable fleet node without him relaying clicks. (b) Accessibility-tree snapshots are structured data — log them as test evidence, so "the agent clicked X" becomes an auditable artifact instead of a claim. (c) The skeleton-snapshot pattern (structure first, drill into one region) is a general token-economics trick worth copying into other fleet tooling that dumps big trees (DOM, file trees, DB schemas). (d) Multi-agent same-app operation maps onto parallel QA passes on a Kit client preview or the GSE packages page.
6. RISKS AND LIMITS — Very young (v1.0.x; a Windows COM-teardown crash bug was reported against 1.0.1 and its fix status in 1.0.2 was not confirmed by reviewers). Apps that expose no accessibility tree are invisible to it — coverage is only as good as each app's accessibility implementation. Snapshots and clipboard reads can contain private desktop content, so session logs need the same care as screenshots. The post's headline efficiency number (a 52-step task dropping 198K → 31K tokens, ~84%) is a single builder-reported demo; independent coverage puts skeleton savings at 78–96% on dense Electron apps but stresses these are self-reported, with no public computer-use benchmark comparison yet.
7. FIRST TEST AND VERDICT — Smallest test: install on this VM (Linux) or the Windows side, snapshot one native app, and run one observe→act→verify loop (e.g. open a notes app, add a line, re-snapshot to confirm). Verdict: **TEST** — direct fleet leverage, free, Apache-2.0, but v1.0.x maturity means prove it on one machine before wiring it into any standing workflow.
