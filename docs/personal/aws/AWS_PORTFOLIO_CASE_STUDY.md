# Building a Zero-Spend AWS-Governed Sports Intelligence Architecture

## Problem

GSE/FABLE needs a credible way to evaluate AWS services for sports intelligence without turning learning into hype or letting cloud work outrun evidence, source rights, cost controls, or security gates.

## Constraints

- No AWS credentials in the repo.
- No live AWS account mutation.
- No deploy.
- No paid resources.
- No private personal learning records.
- No provider or partner data unless rights are documented.
- No model-performance claim without measured evidence.

## What I Learned

The learning path is being used to improve practical AWS judgment:
- S3/storage learning improves artifact-retention and data-rights thinking.
- EC2/compute learning improves compute sizing and rejection criteria.
- VPC/networking learning improves blast-radius and private-surface design.
- RDS/database learning improves managed database tradeoff language.
- Cloud operations and cost learning improves budget, audit, and kill-switch gates.
- Cloud Practitioner learning improves service-fit vocabulary.
- IAM/security learning improves least-privilege review habits.
- Amplify learning improves no-deploy preview planning.
- Bedrock/AgentCore learning improves agent permission boundaries.
- SageMaker learning improves local-first MLOps artifacts.
- Clean Rooms learning improves partner-safe aggregate collaboration design.

## What I Built In GSE/FABLE

- AWS service scorecard with adopt/reject/spike decisions.
- AWS cost and security gates that default deploy and paid resources off.
- AWS decision engine for action tiering and blast-radius risk.
- Amplify preview-only investigation.
- Bedrock/AgentCore firebreak and tool permission matrix.
- SageMaker local-first MLOps ladder.
- Clean Rooms synthetic partner demo docs.
- Personal AWS learning evidence schema and templates.

## AWS Services Evaluated

- Amplify for preview hosting.
- S3 for future approved artifact storage.
- IAM for least-privilege boundaries.
- CloudWatch, CloudTrail, Cost Explorer, and Budgets for operations and cost control.
- Bedrock and AgentCore for governed agents.
- SageMaker for artifact governance and future MLOps.
- Clean Rooms for future partner-safe aggregate analysis.

## What I Rejected And Why

- Full hosting migration: too much product and infrastructure risk before a concrete need.
- DNS changes: high blast radius without owner approval.
- Hosted training: cost and data-rights risk before local artifacts mature.
- Paid model calls: unnecessary before local deterministic evaluators and fake-agent tests.
- Live Clean Rooms collaboration: impossible without partner, contract, and legal review.
- Cloud storage of source data: blocked until source rights permit it.

## Security And Cost Guardrails

- Deploys default off.
- Paid resources default off.
- Monthly AWS cost cap defaults to zero.
- Read-only discovery requires a specific need, profile, and region.
- IAM wildcard, admin, public-resource, and broad PassRole signals raise risk.
- Storage and partner sharing are blocked when data rights are unknown.
- Live AWS work requires owner approval, rollback, cost ceiling, and audit plan.
