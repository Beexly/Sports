## The one real architectural decision this map forces

**`credit-pool.ts` (this session's work) and `monetization.ts`/`policy.ts` (#146) both independently answer "is this credit real and usable?"** — the former from a model-ID string shape at RUNTIME, the latter from an evidence-gated OPPORTUNITY lifecycle at DISCOVERY time. They currently cannot contradict each other only because neither has been asked the same question yet. The moment both are wired to production, they will diverge (e.g. `credit-pool.ts` reporting "$400 spent via aws_activate this month" purely from model-ID shape, while NOVA's opportunity ledger still shows the AWS Activate grant as `applied`, not `activated`). **Resolution: `credit-pool.ts` must be renamed to reflect what it actually proves (provider class, not payer) and must query NOVA's credit-grant state — once that exists — before ever labeling spend as credit-covered.** Until NOVA's credit persistence exists, `credit-pool.ts`'s pool labels should be treated as unverified hints only, never displayed as confirmed savings.
