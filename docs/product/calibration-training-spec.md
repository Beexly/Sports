# Calibration Training — Specification

**Status:** Phase 4 build. Radical #5: calibration training disguised as a picks product.
**Owner of code:** Codex.
**Owner of UX copy + insight surface text:** Claude.
**Location:** `apps/web/lib/calibration-training/`, `/picks/[pickId]/calibrate`, `/calibration/me`.
**Decision reference:** master plan Part 2.C.5.

---

## TL;DR

Every pick view prompts the user "What's YOUR confidence in this?" before showing ours. Tracks user estimates vs model estimates vs actual outcomes. Builds a personal calibration curve over weeks. Surfaces insights like *"You're well-calibrated on NFL spreads but overconfident on MLB totals."*

The product **makes you a sharper bettor**, not a more passive consumer.

---

## Why this matters

Most bettors don't know how calibrated they are. They have a feeling about a game ("I like this side") that they can't translate into a probability. The training surface forces translation, then provides feedback at settlement.

Over weeks, users learn:
- Their personal calibration curve at each confidence band.
- Which sports / pick types they're under- or over-confident on.
- Whether their gut beats the model on specific patterns.

This is the inverse of every other sports betting product, which optimizes for "you trust the service and follow." We optimize for "you become better at the underlying skill."

## User flow

### Pre-show confidence prompt

When a Pro/Elite user opens a pick detail page (and the pick is still pending), the page shows a modal/inline prompt BEFORE the model's confidence number.

```
Before we show our number:

What's YOUR confidence this hits?

[slider 50% — 95%]

Submit  Skip
```

Submitting:
- Stores `UserPickEstimate { userId, pickId, userConfidence, submittedAt }`.
- Reveals the model's number, factor breakdown, pre-mortem, etc.
- Highlights the delta (user vs model).

Skipping:
- No data captured; page renders normally.
- User can opt back in via `/calibration/me` settings.

### Settlement feedback

When the pick settles, a notification + email summarizes:

```
The pick settled [W/L].

You estimated 71% confidence. The model published at 73%. The pick [hit/missed].

Your calibration curve this week: [link]
```

For users who have submitted 20+ estimates, the email includes one specific insight ("you were 8% under-confident on NFL spreads this week").

### Personal calibration curve page (`/calibration/me`)

Pro/Elite users get a personal calibration page showing:

- Their personal calibration chart (same shape as the public Live Calibration chart, but plotting their estimates).
- A comparison overlay with the model's chart (where they outperform, where they underperform).
- Per-sport breakdown.
- Per-pick-type breakdown (spreads, totals, moneylines, props).
- Weekly insight summary ("This week, you were well-calibrated at 60-70% but overconfident at 75-85%").

## Data model

```prisma
model UserPickEstimate {
  id                String   @id @default(cuid())
  userId            String
  pickId            String
  userConfidence    Int      // 50-95, integer
  submittedAt       DateTime @default(now())
  pickConfidenceAtSubmit Int   // model's confidence at the moment user estimated
  pickGradeAtSubmit String

  // Settlement-aware
  outcome           PickOutcome?    // populated when pick settles
  estimateAccuracy  Decimal?        // computed at settlement

  user              User    @relation(fields: [userId], references: [id])
  pick              Pick    @relation(fields: [pickId], references: [id])

  @@unique([userId, pickId])
  @@index([userId])
  @@index([submittedAt])
}

model UserCalibrationSnapshot {
  id                String   @id @default(cuid())
  userId            String
  weekOfYear        Int
  yearOf            Int

  totalEstimates    Int
  bandData          Json     // { "60-65": { sampleSize: N, actualWinRate: N, userMidpoint: N }, ... }
  insightText       String?  // Claude-generated weekly insight, one sentence
  generatedAt       DateTime @default(now())

  user              User    @relation(fields: [userId], references: [id])

  @@unique([userId, yearOf, weekOfYear])
  @@index([userId])
}
```

## Weekly insight generation

The `UserCalibrationSnapshot.insightText` is generated by Claude API.

Pipeline:

1. Every Saturday, the weekly job iterates users with 20+ estimates this week.
2. For each, computes the calibration delta vs the model + vs perfect calibration.
3. Identifies the single most actionable pattern (e.g. "overconfident on MLB totals" or "well-calibrated on NFL spreads").
4. Sends to Claude API with a one-sentence-insight prompt.
5. Persists to `UserCalibrationSnapshot.insightText`.

### Prompt for weekly insight

```
You are generating a one-sentence calibration insight for a sports bettor.

Input: structured data about the user's confidence estimates and the actual
outcomes for one week.

Output: one sentence. ≤ 25 words. Identifies the user's most actionable
calibration pattern. Examples:

"You were well-calibrated on NFL spreads this week but 12% overconfident on
MLB totals."

"Your confidence on Pro picks tracked the actual win rate almost exactly —
that's calibration."

"You were under-confident across the board this week; the picks you rated
at 65% hit at 72%."

Voice rules:
- Direct. No hedging.
- Specific. Name the sport, the pick type, the magnitude.
- No marketing language. No "great job!"
- Past tense.
- One sentence. Hard limit.
```

## Surfaces

### Pre-show prompt UI

Lives inline on the pick detail page above the model's confidence number when:
- User is Pro or Elite tier.
- Pick is still pending (not settled).
- User has not yet submitted an estimate for this pick.

If the user has opted out via settings, the prompt does not show.

### Settlement notification

When a pick the user has estimated settles:
- Email (transactional via Resend).
- In-app notification on the dashboard.
- Optional Discord DM (if Discord linked and DM-alerts enabled).

### `/calibration/me` page

Pro/Elite tier. Renders:

- Personal calibration chart (Recharts or hand-built SVG).
- Comparison vs model chart.
- Sport breakdown (table view).
- Pick-type breakdown (table view).
- Weekly insight (the most recent `UserCalibrationSnapshot.insightText`).
- Historical insights archive (link).

FREE tier sees a teaser: "Calibration training is a Pro feature. Upgrade to track your estimates."

---

## Privacy + opt-out

- Calibration training is OPT-IN. The first time a user is shown the pre-show prompt, they see a one-time "What is this?" explainer with a clear opt-in choice.
- Opt-out at any time via `/settings/calibration`.
- Data is per-user only; never aggregated and shown to other users without explicit anonymization + consent (Phase 5+ leaderboard, if it ships, uses display names users explicitly opt into).
- Estimates are not shared with the model. The model's published confidence is independent of any user estimates. (No "wisdom of crowds" pollution.)

---

## Anti-patterns we're avoiding

- **No "your win rate" framing.** The page does not display "you hit 67% this week." That's outcome luck, not calibration. The page measures calibration.
- **No competitive leaderboard by default.** Calibration is personal training, not a contest. Phase 5+ may add an opt-in leaderboard but ranking is by calibration accuracy, not win rate.
- **No coaching language.** No "improve your edge by 3% this month" or "level up your betting." This is a tool for the curious bettor, not a coaching service.

## Acceptance criteria (Phase 4 calibration training v0 → green)

1. Pre-show prompt renders on pick detail pages for Pro/Elite tier.
2. `UserPickEstimate` rows persist correctly.
3. Settlement updates `outcome` and `estimateAccuracy` automatically.
4. Settlement email + in-app notification fire.
5. `UserCalibrationSnapshot` weekly job runs and generates insight text.
6. `/calibration/me` page renders for Pro/Elite users.
7. Per-sport + per-pick-type breakdowns work.
8. Opt-out flow works from settings.
9. Weekly insight evals pass (Claude-generated text respects voice rules).
10. FREE tier sees the teaser, not the data.

When all 10 hold, calibration training is v0-live.

## Open items

- **OPEN-CAL-1:** Should the pre-show prompt be modal or inline? Default: inline above the model number, with a "show me the model's number" button. Modal feels intrusive. Codex confirms.
- **OPEN-CAL-2:** Should the slider default to the model's confidence value (so the user has to actively move it)? Default: no — defaults to 50%, forces a real estimate. Codex confirms.
- **OPEN-CAL-3:** What's the minimum sample size for the per-sport breakdown? Default: 10 estimates per sport. Below that, the section shows "Not enough data yet."
- **OPEN-CAL-4:** Should we let users compare their calibration vs other Pro users on average (without identifying anyone)? Default: yes, Phase 5+ as an aggregate stat, behind opt-in.
