# Galaxy Team-of-One Operational Templates

**Audience:** Garrett.
**Purpose:** Galaxy is single-operator. The templates below address the small operational moments where a team-of-1 needs structure that bigger companies handle through delegation or meetings.

**Use:** Reference when the specific situation arises.

---

## Template 1 — The "decide it now or later" filter

When an incoming request or decision arrives, ask:

1. **Does this decision have a deadline within 72 hours?**
   - Yes → handle today.
   - No → continue to question 2.

2. **Will this decision be cheaper to make once I have more data?**
   - Yes → defer, note in priority list, set follow-up date.
   - No → continue.

3. **Is making this decision now blocking other work?**
   - Yes → make the decision.
   - No → defer to weekly retrospective.

4. **Default if all three say "defer":** defer. Galaxy can wait. Most non-urgent decisions are better made on a calendar block than reactively.

## Template 2 — The "is this a Galaxy expense or a personal expense" filter

Per `galaxy-founder-financial-discipline.md`. When buying something:

1. **Is this >75% used for Galaxy?** Galaxy expense.
2. **Is this <25% used for Galaxy?** Personal expense.
3. **In between?** Split (Galaxy pays the percentage; personal pays the rest), or personal pays the whole thing (conservative).

Don't over-claim. The accountant's preference is "obvious Galaxy expenses only."

## Template 3 — The "should I respond to this email today or batch it" filter

Per `galaxy-daily-operations-checklist.md`. When email arrives:

1. **Billing issue affecting access?** Same business day.
2. **Refund request?** Acknowledge same day; resolve within 2 business days.
3. **Press inquiry?** 24-hour acknowledgment; substantive response within 48 hours.
4. **Member feedback / question on content?** 1-2 business days.
5. **Partnership inquiry?** 48-hour acknowledgment.
6. **Spam / cold pitch / generic marketing reach-out?** Silent no-response.

Don't reply to non-urgent items between blocks. Batch reactive work in 11:00-12:00 block.

## Template 4 — The "do I take this meeting" filter

When a meeting is requested:

1. **Is there a specific decision Galaxy is making that this meeting informs?**
   - Yes → take it. Schedule in the 14:30-15:30 partnership-meeting slot.
   - No → ask for an email summary instead. "Can you outline what we'd discuss in 200 words? If a meeting is needed after that, happy to schedule."

2. **Is the requester someone Galaxy needs an ongoing relationship with?**
   - Yes → take it.
   - No → decline politely.

3. **Is the requester a Vault member?**
   - Yes → if it's a substantive product question, office hours is the right venue; offer that. If it's a personal-relationship matter, respond by email.

Default: don't take it. Galaxy's brand position depends on protected blocks. Most meeting requests are better handled via email or office hours.

## Template 5 — The "should I post this on Twitter" filter

Per `copy/galaxy-twitter-content-discipline.md`. Before posting:

1. **Does this post link to a specific Galaxy surface?**
   - Yes → continue.
   - No → consider posting via email or Discord instead. Twitter is for surface-linking.

2. **Would this post survive `galaxy-brand-voice-canonical.md` § "What never goes in"?**
   - Yes → continue.
   - No → revise or don't post.

3. **Is this responding to an external event?**
   - Yes → wait 24 hours. Most reactive posts are mistakes.
   - No → continue.

4. **Read aloud. Does it sound like Galaxy?**
   - Yes → post.
   - No → revise.

## Template 6 — The "should I sunset this feature/product" filter

When a Galaxy feature isn't working:

1. **Has it been operating long enough to assess?** (At least 90 days for new features, 180+ for products.)
   - No → wait.
   - Yes → continue.

2. **What does the data say?** (Calibration drift, member adoption, engagement metrics.)
   - On-track → don't sunset.
   - Mixed → continue assessment for next period.
   - Off-track → continue to question 3.

3. **Does the kill criterion apply?** Per `04-kpi-decision-rules.md`.
   - Yes → sunset.
   - No → active intervention.

4. **If sunsetting: which sunset playbook applies?** Per `launch/vault-sunset-playbook.md`.
   - Vault → Scenarios A-D depending on trigger.
   - Almanac → digital-only fallback or full sunset.
   - Live → defer or partner-handoff.

5. **Has the operating-values brand position been preserved through this process?** Per `galaxy-operating-values.md`.

## Template 7 — The "what to do when someone disagrees with me" filter

When a Vault member, partner, contractor, or external party disagrees with a Galaxy decision:

1. **Is the disagreement substantive?** (Specific evidence / reasoning, not generic objection.)
   - Yes → continue.
   - No → polite acknowledgment; move on.

2. **Did Galaxy have a process for this decision?** (Decision-log entry, etc.)
   - Yes → reference the decision-log entry in the response.
   - No → acknowledge that the decision-making could have been clearer; consider whether to add a decision-log entry retroactively.

3. **If the disagreement is genuinely insightful, does Galaxy's position need to change?**
   - 24-hour cooling-off period before deciding.
   - If yes → write a new decision-log entry documenting the change + the reasoning + the influence.
   - If no → write a 200-word response demonstrating the brand position rather than asserting it.

4. **Don't argue in the moment.** Per `founder-resilience-playbook.md` § "Anti-spiral protocol."

## Template 8 — The "I'm feeling overwhelmed" filter

When operator capacity is strained:

1. **What's the trigger?**
   - Workload spike → identify what can be deferred to next week's peak block.
   - Member criticism → activate `founder-resilience-playbook.md` anti-spiral protocol.
   - Personal life → activate appropriate boundary (Saturday off held, etc.).
   - Calibration: are personal kill criteria approaching? Check `01-runway-scenarios.md`.

2. **What's the minimum operational commitment?**
   - Wednesday digest: ship.
   - Office hours: hold if scheduled.
   - Vault Discord engagement: maintain at floor level (10 min/day; not the typical 90/week).
   - Other: defer unless directly time-bound.

3. **What gets cut from the current week?**
   - Almanac essay work → defer.
   - Partnership outreach → defer.
   - Press response → defer (48 hours becomes 72 hours).
   - Methodology revisions → defer.

4. **Saturday OFF held?** Yes / No. If no, the overwhelm signal is real; reset routine.

5. **Designated emergency contact notified?** If overwhelm has structural cause (illness, family event, etc.), per `galaxy-business-continuity-plan.md`.

## Template 9 — The "should I ship this faster" filter

When something feels urgent:

1. **Why does it feel urgent?**
   - Calendar deadline → ship on calendar.
   - External pressure (press cycle, competitor moving, etc.) → continue to question 2.
   - Internal anxiety (vague sense of "should be done") → defer to weekly retrospective.

2. **Will rushing this compromise brand position or quality?**
   - Yes → don't rush. Galaxy's brand depends on slow + correct.
   - No → continue.

3. **Is the additional time before "right" actually material?**
   - 1-2 days additional → take it. Worth more than the urgency.
   - 1-2 weeks additional → consider rushing if the urgency is genuine.
   - 1+ months additional → check whether the project is on the right path.

The default is don't rush. Galaxy's restraint applies to operational pacing too.

## Template 10 — The "should I update this document" filter

Documentation grows over time. Updates need discipline:

1. **What changed in the world that this document captures?**
   - A specific event (engineering change, decision made, member feedback pattern surfaced) → update.
   - General sense that the doc could be better → don't update; documents don't get "freshened up."

2. **Will the update preserve brand voice + cross-references?**
   - Yes → continue.
   - No → consider whether the document is the right place for the change.

3. **Will this update trigger updates in other documents?**
   - Yes → bundle the cascade; document in decision log.
   - No → continue.

4. **Is the update increasing complexity?**
   - Yes → reconsider. Galaxy's docs benefit from restraint.
   - No → continue.

5. **After update: cross-references still resolve?** Run validation script if available.

## Template 11 — Garrett's weekly priority order

When Friday afternoon retrospective sets next week's priorities:

1. **Wednesday digest** — peak priority. Cannot slip.
2. **Office hours** (if applicable) — peak priority.
3. **Quarterly data review** (if approaching) — peak priority.
4. **Almanac production** (during production windows) — high priority.
5. **Member support** — high priority, batched.
6. **Methodology updates** — medium priority, scheduled to peak blocks.
7. **Partnership outreach** — medium priority, scheduled to lower-energy blocks.
8. **Press response** — medium priority, 48-hour SLA.
9. **Discord engagement** — ongoing, low priority per-day.
10. **Decision-log entries** — same-day discipline; never deferred more than 48 hours.

If the week is unusually heavy, items 6-9 can flex. Items 1-5 don't flex.
