# Galaxy Sports Edge — native SwiftUI iOS app

Branch: `feat/ios-swiftui` · Xcode project: `ios/GalaxySportsEdge.xcodeproj`
Target: iOS 17.0+ · Swift 5.9+ · Xcode 16+ · zero third-party dependencies.

Origin: UI scaffold generated by DeepSeek from the GSE website/repo (2026-09-26),
then compile-fixed and project-wrapped by Motif. The scaffold is a starting point,
not gospel — see "What DeepSeek got wrong" below.

## What the app is

Five-tab SwiftUI app (The Edge / Scores / Reads / My Bets / Profile) on the FIELD
design system. Clean seam: every screen reads from `AppEnvironment.service`
(`SportsService` protocol). Flip `AppConfiguration.useMockData` to `false` to go live.

## What DeepSeek got wrong (fixed in this branch)

1. `GameRow` referenced `game.homeSpread`, which did not exist on `Game`.
   Fixed: `Game.homeSpread` is now a computed inverse of `awaySpread`.
2. `GameStatus` (enum with associated values) declared `Codable` — Swift cannot
   synthesize that. Fixed: hand-written `Codable` with a string discriminator.
3. `Keychain` used Security-framework APIs with only `import Foundation`.
   Fixed: added `import Security` in `APIClient.swift`.
4. `Theme.nebula.opacity(...)` in two places — `LinearGradient` has no `.opacity`.
   Fixed: opacity moved to the enclosing view.
5. `ScoresView.leagueHeader` referenced `vm`, which was not in scope.
   Fixed: `vm` is now a parameter.

## Backend contract (to build or remap)

The scaffold expects these routes under `AppConfiguration.baseURL` + `/v1`:

| Method | Path | Returns |
|---|---|---|
| GET | /v1/picks?date=YYYY-MM-DD&sport=nfl | [Pick] |
| GET | /v1/games?date=YYYY-MM-DD&sport=nba | [Game] |
| GET | /v1/articles?page=1&limit=20 | [Article] |
| GET | /v1/articles/{id} | Article |
| GET | /v1/me | UserProfile |
| POST | /v1/picks/save | 204 |

These do **not** exist on the GSE backend yet. Two options: (a) implement them on the
Next.js API, or (b) remap `LiveSportsService.swift` (the only file with path strings)
to the existing web/mobile routes. JSON uses snake_case → camelCase automatically
(`convertFromSnakeCase`); dates must be ISO 8601.

## Deliberately stubbed (integration checklist)

- **Auth/sign-in** — `AuthTokenStore` is Keychain-wired and `APIClient` sends Bearer.
  Still needed: a `SignInView` that POSTs credentials and stores the token.
- **Subscriptions** — `ArticleDetailView.premiumGate` is an alert. Wire StoreKit 2
  (`Product.products(for:)` + purchase button) here.
- **Push notifications** — add `UIApplicationDelegateAdaptor`, request authorization
  on first launch, register the token with the backend.
- **Article images / team logos** — `heroImageURL` / `Team.logoURL` are nil in mock
  data; `AsyncLogo` already handles loading + monogram fallback.
- **Live odds on games** — add an odds field to `Game`, render in `GameRow`.

## App Store notes (from DeepSeek's brief — keep)

1. **Gambling / age rating.** Set 17+. If the app displays odds or links to
   sportsbooks, Apple requires either a gambling license per territory or a purely
   editorial/analytical posture with no wagering facilitation. Read guidelines
   4.7 and 5.3 (5.3 requires geo-restriction where gambling content is illegal).
2. **Account deletion.** Guideline 5.1.1(v): in-app account deletion is required if
   users can create accounts. Add a "Delete Account" row in `ProfileView` hitting
   `DELETE /v1/me`.
3. Also required: `PrivacyInfo.xcprivacy` manifest, working support URL, privacy
   policy URL in App Store Connect.
