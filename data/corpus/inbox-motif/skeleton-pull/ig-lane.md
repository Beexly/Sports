## SK-01 — arXiv:2602.21193 "On Data Engineering for Scaling LLM Terminal Capabilities" (NVIDIA Nemotron-Terminal)

- **Source:** @seanyoung161 (Sean Young, 3 followers), single image post, 2026-03-02. https://www.instagram.com/p/DVaFd1OjYBp/ — 0 comments; the post is a screenshot of the paper's first page. **Poster role: recreator** — a screenshot repost of NVIDIA's paper; the caption's framing ("failure driven Terminal Task Gen engine… intensive error correction training") does **not** match the paper. The paper is about synthetic task generation + filtering/curriculum, not error-correction training. Flag stands.
- **What it is (primary source, VERIFIED via arXiv + Hugging Face):** Paper by Renjie Pi, Grace Lam, Mohammad Shoeybi, Pooya Jannaty, Bryan Catanzaro, Wei Ping (NVIDIA), submitted 24 Feb 2026. Method: **Terminal-Task-Gen** (seed-based + skill-based synthetic task construction) → **Terminal-Corpus** (~366K executable terminal trajectories) → train Nemotron-Terminal 8B/14B/32B (Qwen3 bases). Terminal-Bench 2.0 results: 8B 2.5% → 13.0%, 14B 4.0% → 20.2%, 32B 3.4% → 27.4%. The 32B beats Qwen3-Coder-480B (23.9%) — the caption's headline claim is TRUE per the paper; its mechanism framing is not. Dataset is live: `huggingface.co/datasets/nvidia/Nemotron-Terminal-Corpus`, CC-BY-4.0.
- **Where to find it:** arXiv:2602.21193 · dataset on Hugging Face (URL above) · Nemotron-Terminal checkpoints in NVIDIA's HF collection.
- **How to use it:** The reusable asset is twofold: (1) a ready-made SFT corpus of executable, verifiable agent trajectories; (2) the data-engineering recipe itself — generate tasks from seed skills, execute, filter by verified outcome, curriculum by difficulty. That recipe is domain-portable: the same pipeline over GSE's own task space (settlement, grading, lineup construction) produces an equivalent verified-trajectory corpus.
- **Which system it goes with:** stealth-skeleton training data lane; the continual-learning loop's public-data intake.
- **Creative angles:** Verified-outcome filtering is the exact discipline the skeleton's user-input queue needs: only trajectories whose end state checks out become training rows. Seed/skill taxonomy maps cleanly onto engine task families (market grading, calibration checks, DFS construction).
- **Risks / constraints:** Terminal tasks are shell/agent tasks, not forecasting tasks — transfer to sports reasoning is via the *method*, not the data itself. CC-BY-4.0 requires attribution. Benchmark numbers are the paper's own Terminal-Bench 2.0 harness runs.
- **First test / verdict: TEST.** Download the corpus, fine-tune a small open base on a slice, and run it through the standard harness on Terminal-Bench-style tasks vs. the untuned base — the paper gives the exact comparison protocol.
- **Engine-training value:** Dataset = Nemotron-Terminal-Corpus, ~366K trajectories, on Hugging Face, **labels exist** (each trajectory carries a verified task outcome — pass/fail is intrinsic, not annotated after the fact). Metric carried: Terminal-Bench 2.0 pass rate at three model sizes.
- **Skeleton value:** Directly informs the skeleton's **training-data component** and the continual loop's **data-generation pattern**: synthetic task generation + execution-verified filtering is a working, published recipe for growing training data between benchmark runs.

## SK-02 — CLiF (CopilotKit): continual learning from agent traces + user actions

- **Source:** @farsitechnologynews (Persian-language tech news), video, 2026-10-15. https://www.instagram.com/reel/DehX6_Sh8vC/ — caption links its source directly: a MarkTechPost article (Oct 15, 2026). **Poster role: recreator** (translated re-report of MarkTechPost coverage).
- **What it is (primary source, VERIFIED via MarkTechPost):** **CLiF**, from **CopilotKit** (the open-source AG-UI agent framework, 38K+ GitHub stars). It treats the **full-stack trajectory** — agent trace plus the user's actual product actions, on one timeline — as the learning signal. From those trajectories it produces: human-reviewed **skills** (SKILL.md format; no skill ships without a human reviewing it), production-based **evals**, **fine-tuning datasets**, and raw trajectory exports. Early access; self-hostable (Kubernetes/ECS).
- **Where to find it:** CopilotKit (GitHub org CopilotKit; CLiF via their site / early-access program); origin write-up: MarkTechPost, 2026-10-15 (URL in the post's caption).
- **How to use it:** Instrument the product surface so every agent action and every user correction lands in one trajectory store; mine trajectories into candidate skills and eval cases; route skill candidates through human review; export accepted trajectories as fine-tune data.
- **Which system it goes with:** stealth-skeleton **continual-learning loop** — this is the closest commercial analog found in this run to Prompt 2's consented user-input learning design.
- **Creative angles:** The "one timeline" move is the key idea: GSE's equivalent is member behavior on the paywall surface (which teases get opened, which packages get bought, which picks get followed) joined to the engine's reasoning traces — one trajectory, not two logs. Human-reviewed SKILL.md outputs also match how this fleet already stores procedures.
- **Risks / constraints:** Early access — availability and terms can change. User-input learning carries the consent/ZDR obligations already specified for the skeleton program; CLiF's public material does not settle those for us. Vendor framework: adopting the pattern does not require adopting their stack.
- **First test / verdict: TEST (pattern) / WATCH (product).** Test the pattern on our own traces first; watch the product's early-access terms before any dependency.
- **Engine-training value:** The trajectory store it defines is a dataset schema: (agent trace, user action, outcome) triples with **labels derivable from user behavior** (accepted / corrected / ignored). No public dataset ships with it — the data lives in the deploying product, which for us would be GSE's own member surface.
- **Skeleton value:** Reference architecture for the skeleton's **user-input learning loop** and its **honest-minute discipline**: CLiF's outputs split naturally into fast-changing artifacts (skills, eval cases — minutes) vs. slow ones (fine-tune sets — batched), which is the same split the program already mandates.
