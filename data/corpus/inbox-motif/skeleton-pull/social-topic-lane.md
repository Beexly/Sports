### 3. RRSI — Google Research's Regularized Recursive Self-Improvement
- **Post:** https://www.instagram.com/reel/Dd83Jx1jUd-/ ("Google open-sourced RRSI", text-on-black explainer)
- **What it is:** RRSI = Regularized Recursive Self-Improvement of Agent Harnesses (Google Cloud AI Research with UNC-Chapel Hill, Stanford, WashU; released Sep 21, 2026). A frozen model's harness — prompts, tools, memory, control flow, sub-agents — is rewritten by an improvement loop, while five rules regularize the *search* rather than the harness: annealed edit budget, evidence ledger, **leakage critic** (screens every candidate edit for task names, benchmark entities, answers, suite-specific logic BEFORE evaluation), noise-adjusted acceptance floor (gain must clear the bootstrapped eval-noise band), and a cost rule (added tokens must be paid for by measured gain) plus pruning of non-contributing components.
- **Provenance:** Poster is a recreator; its headline numbers check out. Primary sources: arXiv:2609.24972 (Xia et al.) and https://github.com/google-research/rrsi (Apache-2.0). Verified results [verified]: Terminal-Bench 2.1 evolve split 74.2% → 80.2% (Claude Opus 4.8 policy); SWE-bench Verified 82.0% → 83.8% having never been used for selection; all six held-out benchmarks improved; with Gemini 3.5 Flash policy, Terminal-Bench 64.6 → 78.7. Poster's "74 → 80" framing matches the paper.
- **Verdict:** TEST — highest-priority import in this lane. The leakage critic + noise-adjusted floor + cost rule are exactly the promotion gate the skeleton's near-minute improvement loop needs, and the repo ships them as working code (critic.py, calibrate.py).
- **Engine-training value:** The evidence ledger is a labeled dataset of (edit → measured delta) pairs — a training signal for predicting which harness changes generalize. Noise-band calibration data per benchmark suite.
- **Skeleton value:** promotion loop (primary), benchmark program integrity.

### 5. SEAL — Self-Adapting Language Models (MIT)
- **Post:** https://www.instagram.com/p/DXXjUTWiDDd/ (3-slide carousel of the paper's pages)
- **What it is:** SEAL (Zweiger, Pari, Guo, Akyürek, Kim, Agrawal — MIT, NeurIPS 2025) lets an LLM generate its own finetuning data and update directives ("self-edits") for new tasks/knowledge, then learns *how to write good self-edits* via an outer RL loop whose reward is downstream performance after the update is applied (ReST-EM).
- **Provenance:** The post is a faithful paper screenshot share (poster = distributor, not author). Primary source: arXiv:2506.10943; project page jyopari.github.io/posts/seal; code via github.com/Continual-Intelligence. Verified results [verified]: knowledge incorporation (SQuAD no-context) 32.7% → 47.0% after two RL rounds, beating GPT-4.1-generated synthetic data; few-shot ARC 72.5% vs 0% in-context baseline on the paper's filtered subset. The paper's own Section 5 limitation — sequential self-edits cause catastrophic forgetting — is shown in the post's slide 2 and is the key caveat.
- **Verdict:** TEST — self-edit generation is a candidate mechanism for the skeleton's data pipeline (the model drafts its own training data from user-input distributions), but only behind a forgetting regression gate (see items 3, 23).
- **Engine-training value:** Self-edit pairs (input passage → generated finetuning set → measured delta) are a labeled dataset for training an edit-policy; reward = post-update task score.
- **Skeleton value:** data pipeline + brain (continual weight updates).

### 6. TTPO — Test-Time Policy Optimization (Zhejiang University / Alibaba)
- **Posts:** https://www.facebook.com/MontrealAI/posts/pfbid03SVnp22Xg1DnhkvRWXAojwA3QozQsjFBZEmfJNTrw814gpz5WgMDNPyDPbMQP7xtl and mirror https://www.facebook.com/groups/Montreal.AI.Academy/permalink/1948738702458248/ (same paper, two group shares — counted once)
- **What it is:** Test-time training for math reasoning **without ground-truth labels**. Majority-vote pseudo-labels are fragile because a wrong vote corrupts the teacher; TTPO's asymmetry observation: rollouts that *disagree* with the pseudo-label are usually wrong whether or not the vote is right. So agreeing rollouts get OPSD distillation, disagreeing rollouts get GRPO penalties, with token-level selection in both branches.
- **Provenance:** Group-share posts are recreators; the paper image they carry is genuine. Primary source: arXiv:2608.27448 (Wang et al., submitted Aug 27, 2026); code https://github.com/ZJU-REAL/TTPO. Verified results [verified]: label-free TTPO matches or exceeds label-supervised OPSD across Qwen3-1.7B/4B/8B on AIME 2025/2026, HMMT 2025/2026, BRUMO 2025; pure-TTT setting raises 1.7B base 38.0% → 45.2%; +25.2% to +36.4% in no-thinking mode. Fine-tuning in the paper is LoRA r=64.
- **Verdict:** TEST — this is the cleanest published recipe for learning from *unlabeled* live traffic: user inputs arrive without labels, and TTPO shows how to extract a training signal anyway. Directly on-brief for the consent/input-learning line.
- **Engine-training value:** Pseudo-label agreement rate per prompt is itself a difficulty/uncertainty feature; agree/disagree rollout split produces preference-style pairs without human labels.
- **Skeleton value:** consent/input-learning (primary), brain.

## SYNTHESIS — what the topic layer says that the feeds didn't

1. **The improvement loop has converged, publicly, into one architecture.** Every serious item in this lane is the same machine wearing different clothes: complete **traces** (Chase, AgentLoop, HALO) → **evaluation** against a defined good (evals, judges, verifiers) → **proposals** at three layers (context, harness, weights — Chase's decomposition) → **gated promotion** (RRSI's leakage critic + noise floor + cost rule; SIA's feedback agent choosing the lever; Dreaming's non-destructive review-before-apply). The skeleton's promotion loop should be built to this convergent spec rather than invented.
2. **Label-free learning from live input is now a published, working recipe, not a hope.** TTPO (item 6) extracts GRPO/DPO-class signal from unlabeled traffic via majority-vote asymmetry; SEAL (item 5) has the model author its own training data with an RL-trained edit policy. Combined with execution/outcome verification once resolutions land (our ForecastBench-style data resolves by construction), the consent/input-learning line has a concrete method stack.
3. **Calibration is a post-training casualty unless defended.** The Apple semantic-calibration result (item 15) plus AIA's Platt-scaling recipe (item 13) plus the sycophancy findings (inventoried) form one warning: RLHF-family post-training and CoT degrade native calibration and inflate agreement. Our benchmark program needs calibration metrics (Brier, smECE/B-calibration, agreement-bias) as promotion gates, not diagnostics.
4. **ForecastBench is enterable now and its data is downloadable now.** Biweekly rounds, a documented submission protocol, CC-BY-SA datasets with reasoning traces and resolutions (item 14). The next FRI-called round is November 9, 2026. Of the seven program suites, this is the one where the skeleton can post a public, primary-source score first.
5. **The public claim layer on forecasting is systematically inflated by exactly one move: dropping a qualifier.** CereFin (preliminary + one category → "#1 overall"), GreenTree (dataset-#1 → "topped the benchmark"), FutureSearch (operator's "parity, not outperformance" → "matches or exceeds"). 6. **Adapter composition is the promotion mechanic, with an audit gate in front.** TIES/DARE/MergeKit (item 19) + hot-swap serving economics + the ICML 2026 audit finding (92.5% of sampled public LoRAs fail provenance basics) = the skeleton should only ever merge adapters it trained or audited itself.
