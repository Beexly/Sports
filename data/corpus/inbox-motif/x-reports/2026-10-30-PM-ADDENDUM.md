### A1 — @N01ennn — harness2: Google Research's self-improving agent harness (TOOL — full dossier)
- Post: https://x.com/N01ennn/status/2116233378215411919 (feed item F35)
- **WHAT IT IS:** An open-source framework that improves an AI agent by rewriting everything *around* the frozen model — its harness. The loop as posted and as verified: the agent runs a task with its current harness; a Harness Editor proposes edits (one general, one domain-specific) across 8 editable components (system prompt, guardrails, memory, skills, plugins, tool guidance, scripts, subagents); each edit is probed on the same task; a Harness Composer merges what the behavioral contrast supports; an Experience Reflector writes lessons into a persistent Improvement Harness that guides future tasks. No ground-truth labels are used — improvement is contrastive (before vs after behavior), which the authors call Propose-Probe-Compose.
- **WHERE TO FIND IT:** Verified by Motif this run via web sources: code at **github.com/google-research/harness2** (Apache-2.0; repo screenshot in the post matches — docs/, harness2/, scripts/, LICENSE, README.md, pyproject.toml); paper at **arXiv:2610.14224**; project page harness2.github.io. Released by Google Cloud AI Research + Northwestern (lead: Tomas Pfister's team; first author Ruiyao Xu). README states it is not an officially supported Google product.
- **HOW TO USE IT:** Local demo runs on Linux with Python 3.12 + uv and needs no AI account or API key (deterministic editors). Real benchmark runs need model API access (the paper's executors were Gemini 3.5 Flash and GLM-5 under OpenCode/Codex harnesses, with Claude Opus 4.8 as editor). Reported gains from one refinement step: up to +11.5 points on WorkBuddy-Bench (GLM-5/OpenCode 64.2 → 75.7), +4.5 JobBench, +11.8 on Harvey's LAB — vendor/paper-reported, labeled as such.
- **WHICH SYSTEM IT PLUGS INTO:** **Agent fleet infrastructure** — this is the first credible, open, verifier-free recipe for the exact thing Garrett's fleet does by hand: improving agent scaffolding (prompts, skills, memory, subagent configs) from experience. It maps one-to-one onto the fleet's skill/AGENTS.md layer and the claude-ds/OpenCode harness setups. It would not replace the fleet bus; it would sit above individual agent harnesses as an offline improvement loop.
- **CREATIVE ANGLES:** Run harness2's loop against a *single* bounded fleet job first (e.g., a sweep's own dossier-writing harness — this very task's prompt scaffold), with Garrett's hard gates untouched: the loop edits scaffolding, never permissions. The lessons-file mechanism ("Improvement Harness") is also a design pattern worth stealing even without the code: a persistent, structured lessons artifact that future runs must read — AGENTS.md already plays this role manually.
- **RISKS AND LIMITS:** Research code, ~3 weeks old, not a supported product; self-editing scaffolding can drift guardrails if the editor proposes guardrail edits — the 8 components include guardrails themselves, so any fleet trial must pin guardrail files read-only. Benchmark gains are the authors' own runs. Star counts in secondary coverage conflict (4,740 vs 12,000+) — irrelevant to the code, noted as noise.
- **FIRST TEST AND VERDICT:** Clone the repo and run the no-credential local demo; then scope a bounded trial on one non-production harness. **TEST** — the strongest fleet-infrastructure find in this run, arguably in the sweep's history.
