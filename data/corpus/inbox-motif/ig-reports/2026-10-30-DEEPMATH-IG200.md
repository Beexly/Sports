All 10 tokens go through the model in one parallel forward pass with causal masking. At every layer, each position produces a query, key, and value vector. This pass is compute-heavy and is why the first token takes noticeably longer. TTFT is mostly prefill.

QKᵀ for a 10-token prompt gives a 10×10 matrix. Row 10 is Q₁₀·K₁, Q₁₀·K₂, all the way to Q₁₀·K₁₀.

A basic nearest-neighbor search compares the query with every stored vector.

Every vector index cuts this work differently: clustering, graph traversal, compression, or a mix of these.

Here are five common approaches:

1️⃣ Flat: exact search that scans every vector, great when the dataset is small enough to scan
2️⃣ IVF: clusters the space and searches only the nearest clusters; more probes = better recall, more latency
3️⃣ HNSW: a multilayer graph that jumps far on top and refines below; low latency, high recall, extra memory
4️⃣ IVF-PQ: IVF + product quantization; compact codes cut memory and compute, with some recall loss
5️⃣ ScaNN: partitions, scores quantized vectors, then rescores the top candidates exactly; built for throughput

The choice depends on what your system can afford to trade: recall, latency, or memory.
