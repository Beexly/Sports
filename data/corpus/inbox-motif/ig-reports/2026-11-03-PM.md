### PM-02 — @dailydoseofds_ — image — feed pos 2 — https://www.instagram.com/p/DfRPdmNCaSA/
**Payload:** Agent Lightning — Microsoft's open-source framework for training any running agent with reinforcement learning, no agent rewrite.
1. **WHAT IT IS** — An RL training layer that decouples the agent from the trainer. The agent keeps running in its own harness (any framework, any control flow); Lightning sits between agent and model, captures the interaction traces, converts them to training samples, and a trainer (verl + vLLM in v1.0) updates the policy, which is then served back to the agent. The post's screenshot shows the older v0.x design (LightningStore, emit-style API, PyPI 0.2.0 badge); the caption itself correctly notes the v1.0 refactor (Aug 2026) into Trainer / API Gateway / Rollout Controller. Verified at the repo: ~3,500-line lightweight framework per its own tagline, MIT, Python.
2. **WHERE TO FIND IT** — https://github.com/microsoft/agent-lightning (18,889★, 1,706 forks, 184 open issues, created 2025-06-18, pushed 2026-11-03; **v1.0.3 released 2026-11-03**). Docs: https://microsoft.github.io/agent-lightning/stable/ — installation, architecture, and examples including a one-GPU Calc-X proof-of-concept (AutoGen + MCP calculator tools). Technical report linked from the README (arXiv).
3. **HOW TO USE IT** — Per the repo's own docs: install the base environment, run the verl GPU stack setup script for the trainer side, point an existing agent's model calls through the gateway so rollouts are captured, define the reward, and train. Agents can run locally or as Kubernetes Jobs. Requirements: a GPU for the trainer (the Calc-X example needs one GPU); the agent side needs no rewrite.
4. **WHICH SYSTEM IT PLUGS INTO** — **Agent fleet infrastructure + GSE prediction engine.** Garrett's fleet runs on hand-tuned prompts (the exact grind this replaces). Concrete seats: (a) train a small open model (Qwen-class) on GSE pick-reasoning traces with outcome-based rewards instead of endlessly editing the reasoning prompt; (b) train fleet utility agents (sweep dissectors, reply drafters) on scored outputs. It sits beside the fleet MCP bus as the improvement loop the bus currently lacks, and it runs on the Kaggle GPU lane for the trainer side.
5. **CREATIVE ANGLES** — (a) Reward = calibration: score reasoning traces by whether the stated confidence matched outcomes, and RL directly optimizes the thing GSE sells. (b) The GROK LOOP pattern from the 2026-10-29 sweep (workers → grader → coach with rollback) is a hand-rolled version of this; Agent Lightning is that loop with real gradient updates instead of prompt edits. (c) Selective optimization: the framework can train one agent in a multi-agent crew while freezing the rest — matching the fleet's lane structure, where only the failing lane should move.
6. **RISKS AND LIMITS** — RL on a bad reward function makes a confidently wrong agent faster; the reward design is the whole job. GPU cost is real (verl + vLLM stack). 184 open issues signals an active but still-settling v1.x. The headline result in the caption (a Qwen model's SWE-bench Verified jump on 6K samples) is the team's own reported number — labeled team-reported, not independently reproduced here.
7. **FIRST TEST AND VERDICT** — Smallest real test: run the Calc-X example on one Kaggle GPU against a toy MCP-tool agent, confirm traces → training → measurable score movement end-to-end. If the loop closes there, scope a GSE reasoning-trace pilot. **TEST** — the strongest tool find of this run.
