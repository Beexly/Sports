### AM-06 — gpu-unlock: Linux kernel module that removes GeForce tensor-core half-rate cap — @githubsignals (recreator)
Post: https://www.instagram.com/p/DfUXNxBHCBO/ · Feed position 12
1. **WHAT IT IS** — A Linux kernel module by **Zagitta** that runs from the initramfs *before* the stock NVIDIA driver binds the card, writes two internal speed selectors (SS0 `0x88888888`, SS1 `0x8`), performs a function-level reset, and lets the *unmodified* driver load — removing NVIDIA's product-segmentation cap that runs GeForce tensor cores at half rate for FP16/BF16/TF32 math with FP32 accumulation (the same silicon in RTX A-series pro cards runs full rate). Not a patched driver, not a VBIOS flash, so driver updates do not undo it. It does nothing unless `gpu_unlock.targets=` is on the kernel command line.
2. **WHERE TO FIND IT** — Repo: https://github.com/Zagitta/gpu-unlock · Coverage with repo-verbatim detail: Notebookcheck, Wccftech (via LetsDataScience), Indie Kings' Nov 2 write-up.
3. **HOW TO USE IT** — `git clone https://github.com/Zagitta/gpu-unlock` → `make install` (detects Arch/Debian/Ubuntu/Fedora families, builds the matching package, places the module in initramfs) → append `gpu_unlock.targets=all` (or specific PCI addresses) to the kernel command line → reboot. Support: Ampere (RTX 30) marked stable with 100+ user reports; Ada (RTX 40) and Turing (RTX 20) experimental; Blackwell (RTX 50) not supported and, per the FAQ, unlikely. Linux only; a community Windows port exists and the author warns about unofficial Windows installers.
4. **WHICH SYSTEM IT PLUGS INTO** — Garrett's model-routing / local-inference stack and the urgent new-computer decision: if the next machine (or any existing Windows-side box) carries an RTX 30/40 card, this is a free ~2x on exactly the math local LLM work uses. Independent coverage confirms the shape of the gain: dense BF16 matmul on an RTX 3090 Ti 87.5 → 157.4 TFLOPS (+80%), TF32 +94%, LLM *prefill* +25–55% — while token *decoding* barely moves (memory-bandwidth-bound), per the repo's own framing and Wccftech's reporting.
5. **CREATIVE ANGLES** — (a) Prefill is the bottleneck for long-context reasoning workloads (big prompt, short answer — exactly the GSE reasoning-trace shape), so the gain lands where Garrett's workload actually is. (b) Pair with AM-08: a dense 65B at NVFP4 (~57 GB) still does not fit a consumer card, but smaller local models' time-to-first-token is what this unlock buys. (c) It reprices the used-GPU market for the computer purchase: a used 3090 + this module is a different value proposition than its stock specs suggest.
6. **RISKS AND LIMITS** — License trap, stated plainly: the README labels the module/packaging GPL-2.0-only, but GitHub's license detector reports *no recognized license file* — fine for personal use, not for redistribution until that is cleaned up. Maturity: repo created Oct 18, 2026 — three weeks old — with ~14,307 stars and 111 open issues (per the Nov 2 write-up reading the repo): explosive adoption, zero long-term failure data, no warranty position from NVIDIA, and kernel-module risk on a primary machine is real. All performance numbers are the author's/community's, **not independent lab measurements** (Notebookcheck says exactly this).
7. **FIRST TEST AND VERDICT** — Smallest real test: on a non-primary Linux boot (or the new machine before it becomes primary), install, boot with `targets=` set for one card, run a PyTorch BF16 matmul + a vLLM prefill benchmark before/after. Kill criterion: any boot instability or <20% prefill gain. **Verdict: TEST** — highest-leverage hardware find in this run, gated on a spare-boot test, never on a production box first.
8. **ENGINE-TRAINING VALUE** — Indirect but real: prefill throughput is the cost driver for running the reasoning engine's L1–L5 traces locally; a verified 25–55% prefill gain changes which local models are viable as trace generators/judges. No dataset or labels ship with the tool itself.
