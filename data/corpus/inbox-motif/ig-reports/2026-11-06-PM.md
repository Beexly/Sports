### PM-03 — PageIndex: vectorless, reasoning-based RAG over a document tree — @simplifyinai (recreator; origin: VectifyAI)
Post: https://www.instagram.com/p/DfaFOOYGQoL/ · Feed position 3 · Comment gate: comment "AI" for the link + free-resources list (one line; repo identified on-slide).
1. **WHAT IT IS** — An open-source RAG framework that deletes the vector stack: no embeddings, no chunking, no vector DB. For each long document (PDF/Markdown) an LLM builds a **hierarchical tree index** — a smart table of contents where each node carries a title, a summary, and a pointer to the raw text — and at query time an LLM *reasons its way down the tree* to the relevant sections, then answers with page-level citations and an explicit retrieval trace. The headline number: **98.7% on FinanceBench** — with the correction every secondary source repeats: that score belongs to **Mafin 2.5**, VectifyAI's finance system *built on* PageIndex, on a benchmark of structured SEC filings, run by the team itself, with no independent replication and no published latency/cost figures.
2. **WHERE TO FIND IT** — Repo: https://github.com/VectifyAI/PageIndex (**40,152★, MIT, pushed 2026-11-06** — GitHub API this run) · `pip install pageindex` · Hosted Cloud API at pageindex.ai (free tier 1,000 pages on signup, per secondary write-ups) · MCP server available.
3. **HOW TO USE IT** — `python run_pageindex.py --pdf_path your_document.pdf` builds the tree (GPT-4o by default — indexing sends every page through the LLM API, which is the cost center); queries then run the reasoning loop over the tree. A cookbook agentic-RAG demo ships in-repo.
4. **WHICH SYSTEM IT PLUGS INTO** — The research program's document layer (NGS/arXiv corpus, the mind corpus) and the knowledge/RAG seat in the fleet — the same seat WeKnora (register S12) was cataloged for. PageIndex's shape fits Garrett's corpus unusually well: his research material is long, structured PDFs (papers, books, filings-style reports) where chunking destroys exactly the structure that matters, and the **retrieval trace** (why this section) matches his provenance rule — an answer that shows its path beats a similarity score.
5. **CREATIVE ANGLES** — (a) Point it at the sweep corpus itself: three years of dossiers as one tree-indexed library an agent can reason over instead of grepping. (b) The tree index is itself an artifact Garrett can *read* — a generated map of a 300-page research PDF before he commits to it. (c) Pair with PM-01: Gitingest digests repos, PageIndex trees documents — together they cover the two shapes everything Garrett ingests arrives in. (d) For GSE: game books, rulebooks, and long scouting reports are structured documents; a tree index over them is a reasoning-layer input, not a vector afterthought.
6. **RISKS AND LIMITS** — Cost/latency are the honest unknowns: reasoning-based retrieval spends LLM calls *during* retrieval, and indexing a large corpus is a per-page API bill (GPT-4o default; other providers supported in community implementations). The 98.7% is vendor-run on the friendliest possible document class. Young-but-active project (40,152★ and pushed the same day as this run). MIT — no license trap.
7. **FIRST TEST AND VERDICT** — Smallest test: index one real research PDF already in the corpus (~100 pages), ask 10 questions whose answers are known, score accuracy + API cost per query against the current grep/WeKnora-style baseline. Kill criterion: cost per correct answer worse than baseline, or tree quality collapses on a scanned/OCR-heavy PDF. **Verdict: TEST** — top test priority this run.
8. **ENGINE-TRAINING VALUE** — Direct for the reasoning layer: (question → tree path taken → section → answer) traces are labeled retrieval data — they teach *where in a document an answer lives*, which is trainable supervision for GSE's own document reasoning. The FinanceBench result is itself a labeled benchmark row (system × benchmark × score) for the fleet's model/tool routing records.
