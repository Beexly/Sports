# gse-ml-service — fully pinned dependency lock.
#
#   INSTALL WITH:   python -m pip install --no-deps -r requirements.txt
#                                         ^^^^^^^^^
# The --no-deps is REQUIRED, not a micro-optimisation. See "Why --no-deps" below.
# The Dockerfile and .github/workflows/python-tests.yml both use exactly this command.
#
# Every version here is the version actually installed while the 328-test suite passed,
# read back from `pip freeze` in a clean virtualenv, not copied from a changelog. The
# whole file was then re-verified from scratch: fresh venv -> `pip install --no-deps -r
# requirements.txt` -> `python -m pytest app/tests -q` -> 328 passed, plus a live
# `uvicorn app.main:app` boot and a GET /health.
#
# ---------------------------------------------------------------------------
# Why --no-deps
# ---------------------------------------------------------------------------
# `ripser==0.6.15` DECLARES `persim` (and `Cython`) as runtime dependencies, and
# `persim` depends on `hopcroftkarp`, which is sdist-only — no wheel exists for any
# platform, so pip must compile it at install time. That build has failed on Python 3.11
# (setuptools' removed `install_layout` API); it happens to succeed with current
# pip/setuptools, but it is a compile step in every CI run and every image build for a
# package this service never imports. persim also drags in matplotlib, pillow, fonttools,
# contourpy, kiwisolver and friends — tens of MB of plotting stack for a headless API.
#
# We do not need any of it: `app/models/tda.py` calls `ripser.ripser()` only, and writes
# its own persistence-image vectorisation (persim's `PersistenceImager` is exactly what
# it replaces). A clean venv with ripser installed `--no-deps` and no persim present runs
# the full TDA test file green — that is how this lock was produced.
#
# `--no-deps` means pip installs EXACTLY the lines below and resolves nothing, so every
# transitive package is pinned here explicitly. Adding a direct dependency means adding
# its transitive closure too: install it normally in a scratch venv, run `pip freeze`,
# and update both sections.
#
# Plain `pip install -r requirements.txt` (without --no-deps) is not fatal — it just
# re-adds persim/hopcroftkarp/matplotlib and the source build. Don't.
# ---------------------------------------------------------------------------

# torch's `+cpu` local version exists only on PyTorch's own index. Pinning it (rather
# than plain `torch==2.13.0` from PyPI) keeps the install to a single ~192 MB wheel
# instead of the multi-GB CUDA build: there is no GPU in the deployment target and
# nothing in this service trains.
--extra-index-url https://download.pytorch.org/whl/cpu
